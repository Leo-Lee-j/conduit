# Conduit 设置菜单设计重评

日期：2026-11-26。范围：设计评审与三个可操作的 HTML 方向初稿，尚未选定生产实现方向。

## 用户目标

原话：「现在的设置菜单UI设计我不满意，用 huashu-design 重新评估下设计方案」。用户在补充中明确「我希望是三个方向都有」：整体层级与布局、视觉质感、操作效率必须共同改善，而非三选一。

## 共同输入

- Windows 原生 AI 编程工作台；已有 Rust / GPUI 实现。当前 Cargo 版本 0.3.22，不据此推断已经发布。
- 三版统一 1440×900 比较；另验 1100×800、800×800 和 375×812，窄宽优先收起辅助预览与文字导航。
- 真实分类共 11 项：通用、外观与字体、快捷键、AI 引擎、模型与服务、会话设置、Git 工作流、Skills、MCP 服务、插件、数据与更新。
- 核心样本都是「外观与字体」：主题模式（跟随系统/浅色/深色）、浅色主题/深色主题、界面字体/字号、聊天字体/字号/行高、代码字体/字号/行号/语法高亮、背景。另有「会话设置」和「模型与服务」的可浏览示例来验证架构。
- 系统字体使用 Segoe UI、Microsoft YaHei UI 等本机字体。正文至少 14px，辅助标签至少 12px；按钮与选择区有足够点击面积，键盘焦点明确。
- 产品图标用 assets/app-icons/source.png，并内嵌为 data URL；不使用外部 CDN、图片、字体或生成插画。主要视觉资产应是可操作的 Conduit 聊天/代码预览。
- 示例模型用「服务默认模型」与「本地 CLI」，不编造型号、凭据、连接状态或真实性能数据。
- 所有交互仅改变本次浏览器内存；不连接账号、不读取应用配置、不写生产设置。底部简短标注「设计预览 · 不写入应用」。
- 搜索能跳到具体设置项；主题、字号、字体分组切换、重置和本地模拟保存反馈可操作。分类导航允许部分页为明确标注的结构示例，不能假装已实现完整后端。
- 沿用真实范围：界面/聊天/代码独立；默认模型影响新会话；共享服务编辑可能影响引用同一 ID 的既有会话后续使用。不要引入尚不存在的工作区覆盖配置或配置同步承诺。

## form 五问

1. 叙事角色：让设置成为可定位、可理解、可观察结果的工作空间。
2. 观众距离：近距离桌面操作，非宣传海报；信息密度与行高优先于大字装饰。
3. 视觉温度：专业、明确、舒适，品牌青绿只用于选中和操作反馈。
4. 容量：十一类可发现，单屏优先呈现当前任务的常用项，高级项渐进展开。
5. 视觉母题：Conduit 的对话和代码是调整结果，因此预览必须显示这两种真实阅读场景。

## 三个入选方向

- A 清晰双栏：独立设置空间、固定文字导航、明确页标题；按主题/文字/背景切换短页，文字选中聊天；简短行式表单配紧凑的同屏预览。安静浅色，以稳定秩序改善全部三项。
- B 预览工作台：保留窄项目上下文；分类＋编辑区＋大面积即时预览，字体控制分成界面/聊天/代码三个标签。深石墨色、品牌青绿强调，预览直接体现读写效果。宽屏优先，窄屏预览收在设置下。
- C 搜索与任务：顶部搜索和四个域导航；域内的横向分类，再以左侧任务清单与右侧详情组织「主题」「界面文字」「聊天文字」「代码」「背景」。亮中性色、线性列表，首屏就展示修改值及位置。固定设置入口可发现，不新增需要维护的收藏/最近使用系统。

不覆盖旧原型，不修改 src/。初稿完成后附截图与评审说明，等待用户选方向或混合方案。
