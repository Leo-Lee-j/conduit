# 设置菜单评审

## 判断

本轮最需要的是重排层级、缩短任务路径、让调整结果可见。现有代码已具备全局搜索、分域分类、自动保存、窄窗分类下拉；问题集中在它们怎样呈现，而不是缺少功能。以下为设计判断，不是可用性实验分数。

## 证据边界

阅读了当前设置路由、容器与外观实现；目视对照 2026-11-23 历史原生截图与上一轮 HTML 截图。桌面截图助手不可用，未捕获当前运行版本。不能据历史画面断言今天窗口的精确像素表现。新三版均为 HTML 设计初稿，尚未改造 Rust / GPUI。

## 优先修正

| 问题 | 具体证据 | 用户影响 | 修正方向 |
| --- | --- | --- | --- |
| 页面主标题缺席 | settings_page 隐藏 header；分类信息主要在导航 | 搜索落点、窄面板及跨类切换缺少稳定的位置提示 | 正文固定页标题；分组标题不承担页面标题职责 |
| 外观页组织过长 | 同页含主题、工作区排序折叠、三类字体和背景 | 首屏被主题与行为项占据，聊天/代码排版需要向下寻找 | 将工作区行为归通用；主题、文字、背景任务清晰分隔 |
| 边框层级近似 | 分组容器都有 rounded_lg + border；历史图中主题选项又位于容器内部 | 每一层都强调，真实分组与普通项目不容易扫读 | 以空间与字号分主次，只为可操作选择和预览保留必要边界 |
| 说明占据主阅读路径 | 大量 12px description 长行；历史截图中多行说明连排 | 中文长文、英文换行与缩放时更难快速比较控件 | 14px 主要说明，12px 短辅助；必需范围提示保留，低频细节渐进展开 |
| 编辑与效果距离远 | 预览位于外观页内部，随整页滚动 | 调字号/行距时需要来回判断结果 | A/C 紧凑同屏预览，B 独立预览栏 |
| 工作台上下文与设置竞争宽度 | 历史原生图同时保留项目栏、设置栏、内容与工具栏 | 同样窗口下内容区更窄，长标签更早换行 | A/C 独立设置目的地；B 压缩上下文并按可用宽度退化 |

## 应保留

- 搜索覆盖所有分类并精确落到设置项；保持旧分类词与自动命名兼容入口。
- 浏览引擎与更改默认模型分开；默认值与共享服务编辑范围分开。
- 界面、聊天和代码排版独立，重置按组进行。
- 真实保存状态包含保存中、失败与只读；正式实现沿用现有状态，不使用无根据的「已保存」。
- 窄窗保留文字分类选择，不退化为只有图标的栏。

## 三方向取舍

| 方向 | 层级与布局 | 视觉质感 | 操作效率 | 成本与代价 |
| --- | --- | --- | --- | --- |
| A 清晰双栏 | 独立设置空间、明确页标题、分类一直可见 | 浅中性底、统一行高、弱边界 | 短页与分组减少寻找，同屏预览 | 最稳妥；离开设置才回到工作上下文 |
| B 预览工作台 | 保留上下文，配置与效果并排 | 石墨底、克制青绿、大面积真实对话 | 改字体/字号/行距立即看到完整效果 | 宽窗表现最佳；响应式与 GPUI 预览联动成本较高 |
| C 搜索与任务 | 域、分类、任务三级导航 | 亮中性色、清晰摘要、线性列表 | 搜索直达字段，常用任务无需长滚动 | 跨域多一步；需要用户理解新的横向分类 |

建议以 A 为基底评估，吸收 B 的即时预览关系；若最在意大量设置的定位，再考虑 C 的导航结构。最终方向由用户看过三版后确定，可混合选择。

## 生产实现约束

设计选定后再落地 Rust / GPUI：保留现有 route 身份和 search target 兼容映射，布局变化不迁移配置；默认模型、权限、共享服务语义不变；按真实设置面板宽度响应；键盘焦点、只读状态、保存失败、大字号和中英文长标签分别验证。

三版首屏中演示值由原型固定，未读取用户的真实配置。外观可操作程度高于其它页面；非外观页标注结构示例。所有截图需同时注明 HTML 初稿身份。
