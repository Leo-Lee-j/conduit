# 方向确认

日期：2026-11-26。

用户选择原话：

> 方案A 看起来可以，另外要求：
> 1.不要为了还占空间而特意放大UI
> 2.保持信息密度和可读性,可操作性

确认方向：A / IDE控制中心。此前三方案与11类菜单已在index.html展示；对应原型design-demos/dir-1.html，截图previews/dir-1-*-1440.png。

实施约束：

- 字体、行高、按钮和导航宽度不随窗口空余空间等比放大。用户主动调整UI字号时，控件才按字体需要适配。
- 大窗口增加可见内容或保留自然留白；短字段、选择器与表单有合理宽度上限，长路径和资源表利用可用空间。
- 标准正文14px、辅助12px；桌面常用操作目标32–36px，简单属性行36–44px，长说明自然换行，不强行压扁。
- 统一11类菜单的导航、页头、范围、属性行、对象信息与状态；保留真实功能、编辑器、默认规则和保存边界。
- 只使用主会话加最多两个子代理；不提交或发布。

huashu-design用于已选方向的视觉规范与验证；原生实现按现有Rust/GPUI架构完成，不重新套三方向问卷。
