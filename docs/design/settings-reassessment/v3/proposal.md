# Conduit 设置菜单重构方案

建议选 **A：IDE控制中心**。把设置改成同一窗口中的独立工作视图，统一迁移全部11类菜单。技术感来自明确的分类、对齐的属性、可核对的状态和操作边界。

## 现状诊断

本次看过实际原生截图 appearance-polished-wide.png，并以CodeGraph核对设置路由、页面拼装、通用/会话/插件/快捷键实现，以docs/settings.md核对服务与扩展的行为。

1. **空间结构挤压内容。** 当前1600px截图中，聊天工作区侧栏约384px、设置导航184px、外观预览280px，主内容受多重边栏挤压。密度虽高，但视线不断跨越空栏。
2. **新规则只覆盖部分页面。** 外观采用属性行；通用/会话/Git仍是分组表单；服务、扩展、插件的工具条和列表各自组织。统一颜色无法解决结构差异。
3. **搜索与导航多层叠放。** 全局搜索、外观过滤、分组选择同时常驻；页标题与导航也有重复。需要固定信息层级，降低找入口的成本。
4. **关键关系需要可见。** 引擎、服务、模型、来源、默认与会话引用是不同概念；已发现、已启用、已连接、当前会话加载也不同。应在共同模板中处理。

## 从研究得到的设计规则

官方文档及截图证据见 product-facts.md 和 refs/reference-board.jpg。采用JetBrains稳定分类、VS Code单一搜索与过滤、Raycast对象归属；不复制任何一家完整皮肤。

- **设置独占内容空间。** 进入时暂时收起工作台两侧面板，退出恢复宽度/展开状态/焦点。无需打开额外系统窗口，保留当前应用上下文。
- **11个稳定入口，最多三级。** 四组分类 → 页面 → 章节/对象；不会把每一个扩展都提升成全局分类。
- **一个全局搜索。** 搜索结果给出页面/章节/字段与作用范围；局部列表过滤是搜索范围条件，不再重复一排输入框。外部“发现”搜索明确切换搜索域，不混在本机偏好结果中。
- **统一四类页面模板。** 偏好表单、对象列表/详情、快捷键表、配置编辑；共用页头、作用范围、状态、空态、错误态、操作栏。
- **信息密度靠布局。** 桌面行高36–44px；正文14–16px，辅助12–13px；4/8/12/16/24间距；小圆角3–5px；1px必要分隔；标题20px左右；无大卡片、发光和装饰数字。
- **保存方式忠于行为。** 偏好自动保存，服务和配置显式保存；没有“保存全部”。写入失败明确留在原处并可重试。

## 全菜单覆盖及归属

| 分组/页面 | 统一模板 | 页内结构与特别处理 |
|---|---|---|
| 工作台 / 通用 | 偏好表单 | 语言、布局、目录/标签、数量限制、通知；工作空间排序与折叠建议从外观迁入此处，旧搜索深链做别名 |
| 工作台 / 外观与字体 | 偏好表单+按需预览 | 主题、UI/聊天/代码字体、背景；三种字体独立；Wallhaven和下载历史保留完整入口 |
| 工作台 / 快捷键 | 命令表 | 命令/绑定/范围；录入、冲突、单项恢复；不变成普通设置卡片 |
| AI与工作流 / AI引擎 | 对象列表/详情 | 四引擎、启停、启动路径、版本、更新渠道；检测状态与启用独立 |
| AI与工作流 / 模型与服务 | 对象列表/详情+局部编辑 | 服务来源/模型/关联会话；显式默认；CCS只读来源；本地编辑待保存保护 |
| AI与工作流 / 会话设置 | 偏好表单 | 新会话默认、权限、聊天显示、自动命名、空会话清理、自动归档；范围标签按分组展示 |
| AI与工作流 / Git工作流 | 偏好表单+配置编辑 | 远端检查、提交说明引擎/服务/模型、长提示词；提示词展开编辑 |
| 扩展能力 / Skills | 对象列表/详情+发现 | 已安装/发现；引擎/目标范围/来源；本地与在线安装、停用/恢复；托管与Qoder能力限制 |
| 扩展能力 / MCP服务 | 对象列表/详情+配置编辑 | 已安装/发现；配置启用/检测分列；工具列表；配置变更预览；连接与会话加载区分 |
| 扩展能力 / 插件 | 对象列表/详情+发现 | 已安装/发现、本地导入、在线安装、启停、卸载、图标主题预览和选择 |
| 应用维护 / 数据与更新 | 偏好表单+状态任务 | 路径信息、版本/更新详情、自动检查/下载/安装、性能监测；不发明危险数据清理入口 |

原内部route 5自动命名兼容到会话页。路由ID、搜索别名、存储键、默认配置继续保持兼容。remote feature构建的通用附加区套用表单模板，原型以默认桌面构建为范围。

## 共同交互规范

| 情境 | 显示/动作 |
|---|---|
| 查看服务或切引擎 | 只切查看上下文；默认信息不随之改变 |
| 设为新会话默认 | 独立明确按钮；提示仅影响新会话；指向同一份默认配置 |
| 编辑共享服务 | 显示受引用会话/用途；保存影响其后续请求；不伪造版本隔离 |
| 编辑中离开 | 保留草稿或确认放弃；写入中不能丢弃；不要因切分类悄悄提交 |
| 扩展安装 | 先选引擎和范围；详情固定目标；结果按同一目标反馈 |
| MCP检测 | 显示待检测/检测中/已连接/失败；检测成功不能宣称当前会话已加载 |
| 只读 | 正常浏览、搜索、选择查看上下文；写动作禁用并给原因 |
| 保存中/失败 | 状态紧邻编辑对象；自动保存状态只描述偏好，不能覆盖局部表单状态 |
| 空态/无结果 | 解释当前范围，给清空过滤/导入/发现入口；与网络失败区分 |
| 窄窗口 | 分类折叠为完整名称入口；列表进入详情可返回；预览与检查器改为单栏；按可用宽度及UI缩放判断 |
| 键盘/可访问性 | Tab可达、焦点可见、控件有名称、状态不只靠颜色；Ctrl+K搜索；Esc先处理弹层/搜索/待保存 |

## 三方案选择

| | A IDE控制中心 | B 资源浏览器 | C 设置索引 |
|---|---|---|---|
| 主结构 | 左分类+右编辑 | 顶部领域/页面+左对象+右文档 | 顶部搜索/分类+全宽表+按需检查器 |
| 适用 | 完整设置长期统一 | 服务/扩展管理很频繁 | 熟悉字段、键盘检索频繁 |
| 优势 | 定位稳定、所有菜单易发现 | 对象切换快、编辑范围清楚 | 内容宽、扫描和搜索效率高 |
| 代价 | 资源页面仍有两层选择 | 领域切换增加一步 | 对新用户解释性较弱 |
| 推荐 | **首选** | 作为第二选项 | 保留为专家模式思路 |

推荐理由：用户既要求技术密度，也指出“所有菜单没有统一”。A能给偏好、资源和配置一个稳定外壳。服务详情采用B的对象归属，搜索采用C的精确过滤即可；不需要三套全局导航同时存在。

## 原生实施顺序与完成标准

1. **先搭外壳和共同组件。** 调整settings/workspace、navigation以及宿主打开/返回逻辑；建立页头/作用范围/属性行/资源列表详情/状态区的共同接口；保留路由适配器。
2. **一次覆盖所有页面类型。** general、appearance、sessions、Git、maintenance统一表单；engines、services、extensions、plugins统一对象页；shortcuts统一表格；配置编辑器统一待保存和错误行为。
3. **接通搜索和上下文。** 设置搜索覆盖页面/字段/对象，保持深链；筛选与查看状态不写入默认；每个页面只提供真实支持的范围。
4. **验证整套体验后再称完成。** 11页逐页截图评审；明暗主题、窄窗口、UI20px、中文/英文、长路径、空列表/错误/只读、未保存离开、字体独立性、默认边界和MCP检测状态全部验证。

现有入口/编辑器优先复用，输入实体保留以避免重排丢焦点。模型目录与运行时行为不在本次重构中重写。只改UI外壳和呈现层仍需要针对关键行为进行回归，不以HTML原型测试替代原生测试。

当前交付为三套HTML交互方案与覆盖规范；真实服务、安装、更新、保存均未由原型执行。原型样本不代表用户本机配置。选定后再将整套方案迁入GPUI，完成标准是11类全部采用统一规则。
