# 六个候选与三个完整方向

共同spec见 spec.md。用户已明确技术风格、紧凑、高密度，因此不再重复偏好问卷。当前交付是方案比较，不代表原生实现完成。

## 候选1 · 功能秩序（设计师思维）

用Dieter Rams式功能秩序作为方法标签：优先减少交互层级、统一控制件，不冒称由该设计师创作或评审。骨架是一个按任务排布的紧凑设置文档，局部工具只在需要时出现。主角为可读的设置行，技术对象名使用等宽字；强调整个应用的功能关系。没有单独选做：对于11类、多个实体目录，一份长文档的定向成本过高，其克制原则吸收到共同规范。

## 候选2 · 对象与任务索引（设计师思维，选为C）

用Alan Cooper的目标/任务视角作本次方法演绎：专家通常先知道要改什么，再寻找位置。骨架是横向分类 + 全宽索引表 + 按需检查器；大胆之处是撤去永久侧栏，让结果和数据占据主要面积。实际可核对的搜索机制来自VS Code官方资料，而非归因给某位设计师的实际作品。正文14px、索引行40px左右、路径/ID辅助12px。Conduit特有的服务来源、会话用途和扩展范围构成表格列，不能用通用营销卡片替代。完整方向卡 direction-c.md。

## 候选3 · 稳定分类与内容（现实参照，选为A）

官方参照JetBrains分类树，辅以VS Code搜索结果定位。参考板 refs/reference-board.jpg，原图 refs/jetbrains-settings.png。测量：官方截图中性色约94%、彩色约2%；本方案用窄选中条和文字建立焦点，左导航固定216px，而不是复制原截图尺寸。骨架是左分类、右统一内容，资源页再分列表和详情；偏好页不强加第三列。主角为“团队网关”的服务/模型/关联会话，形式来自Conduit的实际共享服务关系。原作浅色和全局Apply不借，使用Conduit石墨色与局部保存。完整方向卡 direction-a.md。

## 候选4 · 资源浏览器（现实参照，选为B）

官方参照Raycast对象所属关系，原图 refs/raycast-settings.png、refs/raycast-agents.png。其截图中性深灰主导，说明层级并不依赖高彩色；本方案故意用浅灰软件界面，避免复制材料。骨架是顶部领域/页面tab、左侧当前资源或章节、右侧详情，左列表270px、正文14px、两行资源约48px。主角是可被多会话引用的服务与可指定范围的扩展。大胆之处是把整棵全局分类从左边移到上方，侧边空间全部给当前任务。完整方向卡 direction-b.md。

## 候选5 · 聚焦对象（风格轮盘）

抽取秒数S=37，网页20项中为18号“深色画廊”，已看 skill 样张 web/18-gallery-dark.jpg。只借“当前对象占主要空间、元数据退到侧后”的结构，主角会是外观预览/服务详情而非摄影图；不能用缺席内容制造留白。由于该结构偏预览且低密度，与完整设置任务冲突，不选做。若用户后续只设计主题浏览器，可保留为备选。

## 候选6 · 界栏索引（风格轮盘）

同一S=37，东亚12项中为2号“宋刻本版式”，已看 east/02-song-block-print.jpg。只借对齐的界栏和固定注释位置；不用竖排、纸纹、鱼尾、朱印。主角是高密度中文参数与技术值，横向阅读。由于迁移后只剩表格秩序，独立成完整设置方向容易流于格线装饰，不选做；统一对齐思想吸收到C。风格还原低于70%，故不以“宋刻本风格”宣传交付。

## 三方向真正的区别

| | A IDE控制中心 | B 资源浏览器 | C 设置索引 |
|---|---|---|---|
| 先定位什么 | 页面类别 | 当前对象/章节 | 参数或资源记录 |
| 全局导航 | 固定左侧11项 | 顶部领域+页面tab | 横向分类/全局搜索 |
| 次级导航 | 页内小节或资源列表 | 左侧对象或章节目录 | 索引分组与过滤 |
| 详情 | 当前页面中 | 常驻编辑文档 | 按需检查器 |
| 普通偏好 | 紧凑属性行 | 分章节文档 | 参数表 |
| 最适合 | 全部功能的长期统一 | 大量服务与扩展 | 高频检索的熟练用户 |
| 主要代价 | 资源页有两层导航 | 总览需切顶部领域 | 发现性和解释空间较弱 |

优先建议A；B的对象详情组织、C的搜索过滤可以作为A的内部机制，但不要把三个不同导航同时叠加。
