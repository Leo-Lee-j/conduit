# 第二轮六张方向卡

此轮沿用第一轮已核实并看过的参照与风格探索（../directions.md），依据新的密度偏好重新选择结构，不额外声称新的外部调研。

## A IDE 属性面板（入选）

来源：功能分层的设计师推演，延续第一轮 A 的一致控件原则。借的机制是稳定的类别位置与参数对齐。约 184px 固定目录，主区 2/3 放密集的分组属性行，右侧约 280px 放聊天/代码与当前作用域提示；标题 20px、正文 14px、标签 12px。主角是同屏的主题、界面、聊天、代码参数与对照预览。深中性底与细分隔线来自原生开发工具语境，品牌青绿用于选中状态。胆量在于一次展示多组参数而不增加卡片层。form 来自用户需要跨文字场景微调的任务。

## B 预览检查器（入选）

来源：直接操作与即时反馈的设计师推演，延续第一轮 B。借的机制是控制和结果始终相邻。左 56px 领域导轨＋约 150px 设置分类，中间是完整的聊天/代码工作样本，右约 356px 紧凑检查器，一屏展开主题、界面、聊天、代码组。主角是较宽的真实阅读结果。低饱和墨蓝中性底和青绿来自同一品牌，强调右侧属性检查器而非复制终端外形。胆量是把常规左表单右预览翻转，让用户从效果出发。form 来自 Conduit 的对话与代码阅读场景。

## C 设置参数表（入选）

来源：第一轮已核实的 VS Code 官方 Settings editor 参考，仅沿用搜索定位机制，参考信息和量测在 ../directions.md。顶层四域导航＋域内横排分类；主区是名称/当前值/作用说明三列紧凑表格，下方固定短预览。将第一轮“任务索引＋详情”改为无需逐项进入的直接编辑。主角是可筛选、可操作的真实参数表；浅石板灰便于密集横向扫描，等宽仅用于数值。胆量是取消纵向类别侧栏，把宽度给表格。form 来自开发者快速查找、比较和修改参数的操作。

## D 单页折叠组（备选）

来源：同仓库原型的双栏长页，已在第一轮查看。保留页面骨架，缩短说明、默认展开常用组。迁移成本低，但仍依赖纵向滚动，跨组比较弱于 A。

## E 区块工作台（备选）

来源：沿用第一轮秒数轮盘 S=42 的网格分区机制，不借复古拼贴表达。将界面、聊天、代码各放紧凑二维格区，直接编辑。空间利用高，但阅读顺序分散、后续复杂设置难以统一。

## F 主题色谱抽屉（备选）

来源：沿用第一轮 S=42 色谱选择机制。主题缩略预览横排、参数紧凑抽屉。适合比较主题，难覆盖模型与服务等设置，暂不作为整体设置结构。

三个入选方向都同时改善层级、质感、效率；用户指定技术感未指定深色，因此 C 保留浅色以检验结构密度，而非默认技术风格必须深色。
