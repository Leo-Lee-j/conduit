# 紧凑技术风格重评

用户新增偏好明确了本轮目标：技术风格、紧凑布局、高信息密度。第一轮的短页和分层标签能降低单页复杂度，但一次仅显示少量参数，留白过多，不符合这一偏好。

这轮将信息密度落实为“同屏可直接修改的有效参数”，而非缩小所有文字：主题、界面、聊天、代码和背景同时展开；名称与值对齐；辅助说明简短；正文保持 14px。桌面输入主要 28–32px，高频操作可以连续用键盘完成。

## 设计判断

| 方向 | 结构 | 适合的使用方式 | 代价 |
| --- | --- | --- | --- |
| A 属性面板 | 184px 固定目录、中间密集属性、280px 右预览 | 设置位置清楚，跨组调参数时保持稳定的空间记忆 | 窄窗口需收起预览；内容多时属性区内部滚动 |
| B 预览检查器 | 领域轨和分类、中间完整阅读场景、右紧凑检查器 | 从实际聊天和代码效果出发，边读边调 | 复杂设置和长说明在窄检查器中更难排；1100px 以下需要更多滚动 |
| C 参数表 | 顶部域/分类、名称/值/范围三列、底部短预览 | 快速查找、横向扫描、连续修改多个参数 | 表格感更强；阅读预览较短；跨域需要先切上方分类 |

**建议优先以 A 继续。** 它最接近用户提出的成熟桌面工具和紧凑技术感，并保留十一分类的可发现性。C 的“仅已修改”与直接过滤可以作为后续组合候选；B 的大预览适合外观页，但不一定适合全部设置。

此推荐是设计判断，未做用户可用性实验。三个方向均可单独选择；当前未记录用户批准任何方向。

## 来源与内容

A 延续功能分层与参数对齐的设计思路；B 延续直接观察结果的反馈机制；C 只延续第一轮已核实的 VS Code 搜索定位机制，整体改成横向分类与参数表。所有字体、青绿强调和标志来自 Conduit 既有语境。六候选具体来源与未选原因见 directions.md；真实资产见 brand-spec.md。

技术感来自功能结构：小圆角、细分隔、稳定的列对齐、等宽数值、清楚的作用范围。中文标签保持系统 UI 字体，代码和数值才用等宽，避免整页变成终端道具。C 使用浅石板灰，证明高密度不依赖深色。

## 生产语义

- 保留自动应用，不增加保存按钮；原型状态为“预览已更新”。
- 界面、聊天、代码参数分别生效，重置只影响当前组。
- 浏览引擎不改变默认；新会话默认不改写已有会话；共享服务的修改可能影响已有引用的后续使用。
- 次级分类为明确标注的结构示例，当前完整验证重点在外观与字体。
- 原型内所有值均为示例，未读取用户实际配置。主题配色样本不等于已安装主题清单。

## 边界

本次只新增 v2 HTML 设计草稿与评审文档。第一轮原型和历史原生截图保留；没有改造 Rust / GPUI。原生现状证据沿用 ../product-facts.md：未取得今天运行窗口的即时截图，不以 HTML 初稿冒充当前原生界面。

选定方向后的落地应复用现有设置路由、搜索映射和配置结构；另外验证中英文长标签、大字号、保存失败/只读、键盘焦点与真实面板宽度。布局变化不应迁移用户配置。
