# 内容分栏与实时文件预览：设计与实现

更新：2026-11-23。状态：两列预览、分栏比例持久化、Windows 事件驱动文件刷新、修改提示、工具结果核对、可选结果回放、Claude 文件参数流的拟议修改预览，以及左右两个独立聊天会话已实现。支持范围和人工验收边界见下文。保留用户目标：全区/半区预览、默认最多两列、可靠来源的 AI 虚拟光标与生成过程展示。

## 复审结论

上一版把布局重构、通用多视图、文件同步、会话跟随和编辑过程演示纳入同一条实现路径，首版范围过大。建议按三个可独立验收的版本交付：

1. **两列文件预览**：全区或并排、可调宽度、自动刷新、正确的焦点与会话归属。
2. **修改位置提示**：在最新文件上标记确认的修改行；可靠定位时显示 AI 光标。
3. **编辑过程演示**：可选的短回放；真实参数流先做单独的适配器验证。
4. **双聊天分栏**：Main 与 Reference 可分别打开不同会话，各自显示流式消息、Markdown、运行状态、审批和独立草稿/输入框；切换、搬移、关闭不改变另一侧会话。

第二、三版不作为第一版上线的前置条件。以下分别记录各版的约束与实际实现；任意分栏、同文件双开仍属于后置需求；真实参数增量已按下文的来源能力接入。双聊天采用现有 Main / Reference 固定两组，不引入任意停靠。

交付关系见 [Mermaid 源图](../diagrams/content-panes-live-preview.mmd)。实线表示已实现的磁盘快照、回放和 Claude 拟议修改路径；虚线表示其他来源按证据能力降级。

## 第一版：两列文件预览

### 产品边界

主内容区只有 Main 与 Reference 两个固定组位置。Main 沿用聊天及现有全页文档入口，Reference 首版承载只读文件；聊天 + 文件是优先验收组合。两文件并排可复用相同路由，但同一文件只能在一个位置，两个聊天同时可见后置。Diff 继续可用原有入口，嵌入右组是独立增量，不阻塞首版。

仍使用既有 Resizable 组件和文件预览实体。两个组有各自的活动标签和临时预览槽，但暂不交付跨组拖拽、合并组、任意分割树或文件标签及组布局跨重启恢复。提供菜单操作“全区显示 / 在旁边显示”，移动同一个文件实例；文件查找与滚动随实例保留。

### 行为约定

| 操作 | 结果 |
| --- | --- |
| 设置“独立标签，占满内容区” | 后续普通文件打开在 Main 显示，Reference 暂时隐藏；聊天及参考标签保留 |
| 设置“并排预览，默认各半” | 后续普通文件打开到 Reference，Main 保留当前内容；无主内容可参考时全区打开 |
| 修改默认设置 | 只影响下一次普通打开；不自动搬移已有标签 |
| 显式“在旁边显示 / 全区显示” | 覆盖本次默认方式；已有文件搬移或聚焦，不复制第二份视图 |
| 点击已打开标签 | 显示该标签所在位置，不重新执行默认打开策略 |
| 文件树单击 / 双击 | 替换目标组临时预览 / 固定标签；不影响另一组 |
| 同一会话中阅读右列文件 | 不改变 Main 会话、草稿、工作目录、模型及权限，不自动聚焦 composer |
| 关闭 Reference 最后一个标签 | 恢复 Main 全区；仅释放关闭文件的资源 |
| 设置、用量、PR 页面 | 按现有方式全区显示，关闭后恢复内容布局；跨工作区 PR / 用量导航返回目标工作区 |
| 窗口变窄 | 临时只显示聚焦组，提供切换与恢复入口；不丢标签、不修改用户正常比例 |
| 切换聊天或工作区 | 主会话正常切换；右列固定文件可保留并明确显示完整路径和来源。未来的 AI 跟随先暂停，不能静默切换绑定会话 |

“默认最多两列”不增加第三列入口，也不另设列数开关。没有已保存比例时首次并排为 1:1；正常双栏拖动结束后将 Main 所占比例随设置持久化，下一次运行首次打开并排时恢复。窗口缩放、最小列宽约束、全区切换及覆盖页面不覆盖用户比例；恢复只涉及比例，不自动重开文件或恢复组布局。

跨工作区文件只作为只读参考展示。右列工具栏的文件操作使用文件自身身份；发送、终端、工作区级 Git 操作继续使用 Main 上下文。任何“切到该文件工作区”都必须是明确导航操作。

左右导航和右侧详情 Dock 位于两个文档组之外。底部终端及分支面板沿用主区公共下方区域，不在每列复制。按扣除 Dock 后的实际内容宽度判断双栏是否可用；不能仅看窗口宽度。窄窗临时单组显示不改变正常布局。具体最小宽度待原生窗口、字体缩放及 DPI 验证。

### 必须拆开的少量状态

```text
默认打开偏好：Full / Beside
用户展示选择：MainOnly / SideBySide
实际布局：MainOnly / SideBySide / ReferenceOnly，由展示选择 + 可用宽度 + 最近活动内容组推导
组状态：各自的标签、活动项、临时预览项
聚焦区域：Main / Reference / 终端或其他区域
文件状态：保留现有 Document + 单个 FilePreview
```

应用会话上下文继续由 Main 管理。只读参考文件渲染改为显式传入 DocumentId，不读取全局 active_file。文件标签恰好属于一个组；关闭或搬移后修复活动项，当前可见/正在使用的文件不能被 20 文档容量限制淘汰。全局列表与分组列表不能各自独立成为顺序的权威来源。

新增“可见文档集合”“聊天是否可见”查询，所有轮询、完成提示和快捷键通过它们判断，逐步替换原有 active_file implies chat-hidden 的假设。不能为了绘制右列临时改 selected_session、active_file 或 global composer。

### 首版状态与操作契约

- `open_tabs` 继续作为唯一标签顺序来源，组归属只标识文件属于 Main 或 Reference；组内标签序列由此派生。每组独立保存活动项、临时预览槽、标签滚动和布局状态。菜单请求携带组身份，“关闭全部 / 左侧 / 右侧”仅作用于该组。
- Main 会话仍由 `selected_workspace/selected_session` 管理；`active_file/active_diff` 只表达 Main 文档。Reference 激活、刷新和关闭不调用 `switch_context`，不修改主草稿、权限或模型选择。显式把跨工作区文件移到 Main 属于主区导航，沿用原有主区上下文切换。
- 文件内容与查找/阅读状态仍由 Document 及其单个 FilePreview 持有；Main、Reference 各自使用绑定组内活动 DocumentId 的 FileDocumentView，缓存快照也绑定该 ID。不可在绘制或缓存计算期间临时修改全局活动文件。
- `session_is_visible` 统一根据实际布局及全区页面判断聊天可见性，供通知和完成标记使用；文件轮询读取可见文件集合。插件工作区/会话和终端继续属于 Main，插件 document 明确表示 Main 文档，参考文件按钮直接携带自己的文件 ID。会话详情 Dock 的可用性跟随 Main 文档身份，不随窄窗临时切组反复显隐，避免 Dock 宽度与折叠阈值形成循环。
- 最近活动内容组独立于实际键盘焦点；鼠标或键盘进入内容组时更新。进入终端、侧栏、菜单不清除它。自动刷新不改变该记录或输入焦点。

### 展示状态转移

| 起点与操作 | 目标与恢复规则 |
| --- | --- |
| 聊天或 Main 文件，普通打开新文件 | 默认 Full（兼容旧配置）；Full 激活 Main 并暂藏 Reference，Beside 放入 Reference；首次无主内容时使用 Main |
| 已打开文件，再次普通打开 | 聚焦其所属组，不搬移；若组暂时隐藏则恢复显示，强制检查文件；显式全区/旁边命令才搬移 |
| 聊天 A + 参考文件 F → F 全区 | F 移到 Main，记住原 Main 活动项 A；Reference 其他标签保留，暂时隐藏 |
| Main 文件 F → 在旁边显示 | F 移到 Reference；优先恢复刚才记住且仍存在的 Main 活动项，否则恢复 Main 现有标签或所选聊天；无主内容时保持 Main |
| 并排 → 窗口变窄 | 仅展示最近活动内容组，提供 Main / Reference 切换入口；终端拥有焦点时也使用该记录 |
| 窄窗 → 足够宽 | 自动恢复并排及用户拖动比例；不因窄窗覆盖比例，不搬移文件 |
| 在 MainOnly 时选择 Reference 标签或“显示参考区” | 恢复并排；空间不足时只显示 Reference |
| Reference 最后一个文件关闭或移走 | Main 全区；修复活动项和临时槽，不触发主会话切换 |
| 全区设置、用量或 PR 页面 | 临时覆盖内容布局；返回仍存在的原文档时恢复此前展示模式与最近活动组。显式跨工作区切换 PR / 用量标签时，Main 返回目标同步到新工作区；设置覆盖这些页面时先返回该页面 |

首版采用每组最小 320 个逻辑像素作为双栏起点，按扣除导航、右侧详情 Dock 和分割条后的宽度计算；这是实现初值，仍需真实窗口与 DPI 验收。比例只在正常双栏拖动时更新，单组退化不写回比例。

### 首版验收补充

1. 主会话流式输出时打开另一工作区的 Reference 文件，编辑并发送主草稿；核对实际发送目标、附件、权限、终端及右侧会话详情。
2. 两个不同文件同时显示、交替更新和查找；相互不覆盖正文、搜索、滚动。流式聊天与文件刷新不得引入跨组内容缓存。
3. Reference 菜单批量关闭、预览替换、搬移、超过文件容量及跨工作区切换；Main 标签保留，可见文件不得被容量淘汰。
4. 全区→并排往返、关闭恢复目标、终端聚焦时缩窗、窄窗切组再恢复；状态转移遵循上表。
5. 读取期间再次修改、短暂不可读、删除后重建、关闭后旧结果返回；有成功快照时保留正文并显示过期提示，首次失败才显示完整错误页。图片必须在新快照成功后替换旧资源。
6. 设置默认打开方式后重新读取配置，验证旧配置默认 Full；设置修改不立即搬移现有标签。

### 刷新最小实现（首版基线，事件监听增量见文末）

先复用约 2 秒后台轮询，覆盖两个组的可见文件，隐藏文件再次展示时检查。对当前已知工具的成功终态，可合并触发可见文件重读；不解析每个文本 token，也不将工具输入当成已落盘结果。每个工具终态只触发一次；失败也可触发状态核对，但不标为成功修改。

文件加载只需明确：上次成功快照、load generation、dirty、error/retry、订阅是否可见。加载期间有新事件则置 dirty，完成后再检查；关闭或身份变化后旧任务不得提交。暂时不可读保留旧内容并提示过期，低频有限退避重试；删除后重建可恢复。后台执行磁盘读取和高亮计算。

第一版不承诺 500 ms。先测量实际延迟，再判断是否引入 watcher；watcher 是降低发现延迟的优化，不提供逐字符编辑顺序，也不自动解决 AI 归属。mtime+长度轮询存在同大小、同时间戳写入漏检的边界，工具终态、手动刷新和重新展示时允许强制读取；有严格外部编辑刷新要求再加低频内容校验或 watcher。

## 第二版：修改位置提示

**实现状态：已交付。** 右列始终以最近一次成功读取为准。首次读取只显示文件内容；后续比较同一文件的上次成功快照与新快照，呈现最近变化的增删行计数、可见源码/Markdown 变化区域和定位入口。纯删除在删除边界保留计数与回放入口；没有前快照或超出计算预算时降级为文件级提示。

只有修改工具提供的路径、操作与已验证版本对应时，才增加 AI 标记。否则显示普通“文件已更新”。虚拟光标仅是确认范围的指示器，不声称是实际鼠标或逐键输入位置；完整结果到达后使用“刚刚修改”，只有可靠的执行中范围才使用“准备修改/修改中”。

变化定位与“跟随当前会话”入口均已实现。跟随仅绑定明确会话和已打开文件，不自动切换文件；离开会话、隐藏预览、手动选择、查找或滚动后暂停，提供继续/停止操作。自动定位不抢键盘焦点。

精确定位仍需验证原始 patch 的基线与上下文，或者验证 old/new 片段。合成的 hunk、被截断的 EditFileDiff、重复匹配和版本冲突只能降级为文件或范围列表提示。相同文本匹配不是归属的充分证明；无法排除并发编辑时不显示确定性的 AI 行归属。

## 第三版：可选编辑演示

**结果回放：已交付。** 正常模式保持最新文件；用户主动进入后，演示栏标明“修改回放 · 非实时输入”，以 Unicode 字素短暂展示旧内容到新内容并显示虚拟定位光标。回放使用同一预览位置，不创建第三列；“返回当前文件”恢复 Markdown/源码阅读模式和滚动位置。Claude 参数流现已接入，来源能力与边界见文末“真实参数流的拟议修改”。

两类来源必须区分：

- **回放**：取得可验证的前后片段后，短暂选中旧内容、展示新增内容、移动虚拟光标；状态为“修改回放”，不代表实际键入时序。
- **生成过程**：只有实际 CLI 提供可用且已校验的参数增量时，才逐步展示；状态为“拟议修改/生成中”，工具完成与落盘另行确认。

基线只能来自已缓存且确认对应的版本、明确的执行前快照或完整可信工具记录。事后读磁盘无法保证得到执行前版本；首版不为此拦截所有文件写入，也不建立整个仓库的自动快照。

大修改按块展示，单次动画有总时长与内存上限；新版本到达取消旧动画并追上最新，不建立无限播放队列。减少动态效果时改为静态标记。仅重绘可见片段；字符推进覆盖中文、组合字符和 emoji，位置换算覆盖换行、Tab、DPI 与水平滚动。

复制、查找和行号在演示模式中统一对应可见演示内容。Markdown 源码模式可定位行，渲染模式只标对应块；图片和超限文件保持文件级提示。回放和拟议修改均使用主动进入的入口，阅读与复制语义由相应 GPUI 回归覆盖。

## 预览队列拥塞收敛（2026-11-21）

复审并补充回归发现：逐工具插入结束标记仍会消耗控制事件的 32 个保留槽，多次调用可让可选预览间接终止请求；排队中的预览也可能挤掉聊天正文。现改为以下规则：

- 同一工具的相邻快照先扣除旧快照成本再计算替换成本；事件数或字节数恰好达到上限时，仍允许预算内的原位替换。
- 预览无法入队，或必须投递的普通事件需要回收预览空间时，移除队列中全部预览事件，并设置一个不占队列预算的请求级撤销信号。授权、失败、清理及请求完成的保留容量不被预览撤销消耗。
- 消费方先收到撤销信号，恢复当前磁盘视图并清除该请求的全部候选；已排队的旧快照已经移除，因此不会随后重新显示。
- 本次请求剩余的预览起始、快照和结束帧一律忽略，包括新的工具 ID；下一次请求使用独立队列重新启用。抑制状态仅两个布尔量，不按工具 ID 累积。

## 事件驱动的文件预览刷新（2026-11-22）

在原有读取链路上加入 Windows 原生目录变化监听，不新增第三方依赖。每个当前可见文件订阅其所在目录的名称、大小、最后写入及属性变化，并订阅上一层目录的目录名称变化，以发现文件所在目录被删除或替换。相同目录合并，两个可见文件最多四个非递归订阅；不递归扫描整个工作区。API 提供粗粒度的“目录已变化”信号，目录内其他文件变化也可能让关联预览重新核对，不把它解释为确定的文件修改或 AI 归属。

单后台线程独占原生句柄，每 50 ms 非阻塞核对通知；没有订阅时休眠，切换目标或释放预览状态时唤醒。UI 每次既有的约 33 ms 调度先同步可见目标并处理通知，再判断原有两秒轮询间隔。每个文件最多保留一个 dirty 槽，静默 75 ms 后出队，连续变化最长 250 ms 出队，通知数量不随写入次数增长。读取中的变化沿用 dirty 标志，在当前成功读取结束后再核对一次。父目录信号使其下的已订阅目录重新布防，避免替换目录后继续依赖旧目录句柄。

订阅失败每两秒重试，首次注册、重注册及注册失败均请求快照核对，覆盖订阅空档；原有约两秒 metadata 轮询继续运行。每个可见文档独立记录上次成功读取时间，约十秒强制核对内容，覆盖相同大小与时间戳、丢失通知或不可用监听等情况；后台读取耗时、界面调度及错误退避可能延长实际间隔，不提供严格截止时间。错误文件保留最后成功快照，原有有限退避继续生效，收到新通知则立即解除退避以处理删除后重建。

可见目标集合携带代际，关闭、替换、隐藏或切换目标时清空旧待处理通知；旧代际和未知文件 ID 不得进入 dirty 集合。全区覆盖页面不订阅文件，重新显示会核对内容。跨工作区保留且仍然可见的 Reference 继续监听，已隐藏的 Main 文件不再接受旧通知。窗口关闭时取消订阅，UI 不等待文件系统线程退出；原生句柄由后台线程释放。异步读取继续验证文件 ID 和请求序号，不复用已关闭文件的身份。
