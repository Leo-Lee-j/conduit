# 内容分栏与实时文件预览：设计复审

日期：2026-11-20。状态：复审后的收敛建议，尚未实施；取代上一版作为建议交付顺序。保留用户目标：全区/半区预览、默认最多两列、后续 AI 虚拟光标与打字效果。

## 复审结论

上一版把布局重构、通用多视图、文件同步、会话跟随和编辑过程演示纳入同一条实现路径，首版范围过大。建议按三个可独立验收的版本交付：

1. **两列文件预览**：全区或并排、可调宽度、自动刷新、正确的焦点与会话归属。
2. **修改位置提示**：在最新文件上标记确认的修改行；可靠定位时显示 AI 光标。
3. **编辑过程演示**：可选的短回放；真实参数流先做单独的适配器验证。

第二、三版不能成为第一版上线的前置条件。以下是设计建议的范围收敛，不代表已实现，也不将以后支持通用分栏或打字效果的需求取消。

交付关系见 [Mermaid 源图](../diagrams/content-panes-live-preview.mmd)。虚线表示后续可选增量，不是首版前置依赖。

## 主要发现

| 优先级 | 发现与触发场景 | 修正 |
| --- | --- | --- |
| P1 | 右列文件仍沿用 `select_document`，跨工作区时会调用 `switch_context`，更换 selected_session、草稿、权限选择及 Git 上下文；只修改渲染布局不能保障发送目标 | 右列激活走独立入口，绑定文件身份。显式聊天导航才切换会话；验证发送实际绑定的会话 |
| P1 | 原设计没有完整区分“可见”“聚焦”“选中聊天”。现有事件处理中用 active_file/active_diff 判断聊天被遮挡，并影响完成/审批提示；右列文件若继续占用这些全局字段，会把可见聊天误判为隐藏 | 增加独立的可见文档、聚焦区域语义；审计事件提示、快捷键及缓存，禁止渲染时临时切换全局 active 状态 |
| P1 | 虚拟光标无法通用地获得真实位置与顺序。现有 Diff 被截断，部分行号是合成的；工具参数和文件写入也不是同一时刻 | 把光标降为可选标记；只有版本及范围可验证时精确定位。完整 Diff 解析与真实增量接入另做验证 |
| P1 | 回放旧→新内容会让右列暂时落后于磁盘，复制/查找/选区/行号都引入第二套语义；新修改和取消还会打断动画 | 最新文件视图先只显示当前快照并叠加标记。打字效果放到用户可选的“修改演示”模式，不自动倒退正在阅读的正文 |
| P2 | 默认两列，却首版安排同文件双实例、跨组移动/合并、通用 DocumentStore/ViewId、跨工作区布局恢复，收益尚不足以支撑迁移量 | 首版每个文件仅一个视图实例，以搬移或聚焦复用；保留两个固定组位置，不做任意停靠、同文件双开或通用视图注册层 |
| P2 | 单文件轮询会遗漏未聚焦但可见的预览；错误文件被过滤后不能自动恢复，loading 期间的新通知可能丢失 | 轮询由可见性驱动；增加 dirty 和请求代际、错误重试。复用已有后台读取，watcher 后置 |
| P2 | “全区默认”“最大化”“缩窗自动折叠”“持久化比例”混在一起；已有右侧 Dock 和底部终端的归属不明确 | 明确偏好、用户选择的展示模式、实际宽度退化三者；固定主区下方的终端及外侧 Dock 归属 |

P1 为开始实现相应版本前需要解决的设计缺口，P2 为需要明确的范围或行为。这里审查的是方案，不表示这些新功能已经造成线上缺陷。

## 第一版：两列文件预览

### 产品边界

主内容区只有 Main 与 Reference 两个固定组位置。Main 沿用聊天及现有全页文档入口，Reference 首版承载只读文件；聊天 + 文件是优先验收组合。两文件并排可复用相同路由，但同一文件只能在一个位置，两个聊天同时可见后置。Diff 继续可用原有入口，嵌入右组是独立增量，不阻塞首版。

仍使用既有 Resizable 组件和文件预览实体。两个组有各自的活动标签和临时预览槽，但暂不交付跨组拖拽、合并组、任意分割树或布局跨重启恢复。提供菜单操作“全区显示 / 在旁边显示”，移动同一个文件实例；文件查找与滚动随实例保留。

### 行为约定

| 操作 | 结果 |
| --- | --- |
| 设置“独立标签，占满内容区” | 后续普通文件打开在 Main 显示，Reference 暂时隐藏；聊天及参考标签保留 |
| 设置“并排预览，默认各半” | 后续普通文件打开到 Reference，Main 保留当前内容；无主内容可参考时全区打开 |
| 修改默认设置 | 只影响下一次普通打开；不自动搬移已有标签 |
| 显式“在旁边显示 / 全区显示” | 覆盖本次默认方式；已有文件搬移或聚焦，不复制第二份视图 |
| 点击已打开标签 | 显示该标签所在位置，不重新执行默认打开策略 |
| 文件树单击 / 双击 | 替换目标组临时预览 / 固定标签；不影响另一组 |
| 同一会话中阅读右列文件 | 不改变 Main 会话、草稿、工作目录、模型及权限，不自动聚焦 composer |
| 关闭 Reference 最后一个标签 | 恢复 Main 全区；仅释放关闭文件的资源 |
| 设置、用量、PR 页面 | 按现有方式全区显示，关闭后恢复前一文档布局 |
| 窗口变窄 | 临时只显示聚焦组，提供切换与恢复入口；不丢标签、不修改用户正常比例 |
| 切换聊天或工作区 | 主会话正常切换；右列固定文件可保留并明确显示完整路径和来源。未来的 AI 跟随先暂停，不能静默切换绑定会话 |

“默认最多两列”不增加第三列入口，也不另设列数开关。首次并排 1:1，之后保留本次运行中的用户比例；只持久化默认打开方式，比例持久化可单独增加。

跨工作区文件只作为只读参考展示。右列工具栏的文件操作使用文件自身身份；发送、终端、工作区级 Git 操作继续使用 Main 上下文。任何“切到该文件工作区”都必须是明确导航操作。

左右导航和右侧详情 Dock 位于两个文档组之外。底部终端及分支面板沿用主区公共下方区域，不在每列复制。按扣除 Dock 后的实际内容宽度判断双栏是否可用；不能仅看窗口宽度。窄窗临时单组显示不改变正常布局。具体最小宽度待原生窗口、字体缩放及 DPI 验证。

### 必须拆开的少量状态

```text
默认打开偏好：Full / Beside
用户展示选择：MainOnly / SideBySide / ReferenceOnly
实际布局：由展示选择 + 当前可用宽度推导
组状态：各自的标签、活动项、临时预览项
聚焦区域：Main / Reference / 终端或其他区域
文件状态：保留现有 Document + 单个 FilePreview
```

应用会话上下文继续由 Main 管理。只读参考文件渲染改为显式传入 DocumentId，不读取全局 active_file。文件标签恰好属于一个组；关闭或搬移后修复活动项，当前可见/正在使用的文件不能被 20 文档容量限制淘汰。全局列表与分组列表不能各自独立成为顺序的权威来源。

新增“可见文档集合”“聊天是否可见”查询，所有轮询、完成提示和快捷键通过它们判断，逐步替换原有 active_file implies chat-hidden 的假设。不能为了绘制右列临时改 selected_session、active_file 或 global composer。

### 刷新最小实现

先复用约 2 秒后台轮询，覆盖两个组的可见文件，隐藏文件再次展示时检查。对当前已知工具的成功终态，可合并触发可见文件重读；不解析每个文本 token，也不将工具输入当成已落盘结果。每个工具终态只触发一次；失败也可触发状态核对，但不标为成功修改。

文件加载只需明确：上次成功快照、load generation、dirty、error/retry、订阅是否可见。加载期间有新事件则置 dirty，完成后再检查；关闭或身份变化后旧任务不得提交。暂时不可读保留旧内容并提示过期，低频有限退避重试；删除后重建可恢复。后台执行磁盘读取和高亮计算。

第一版不承诺 500 ms。先测量实际延迟，再判断是否引入 watcher；watcher 是降低发现延迟的优化，不提供逐字符编辑顺序，也不自动解决 AI 归属。mtime+长度轮询存在同大小、同时间戳写入漏检的边界，工具终态、手动刷新和重新展示时允许强制读取；有严格外部编辑刷新要求再加低频内容校验或 watcher。

## 第二版：修改位置提示

右列继续显示最新文件。第一次载入仅显示内容；之后比较同一文件的上次成功快照和新快照，可以生成“最近文件变化”行标记。缺少前快照就不补造旧版本。替换标记新区间；纯删除在删除边界显示计数，必要时进入独立 Diff 查看。

只有修改工具提供的路径、操作与已验证版本对应时，才增加 AI 标记。否则显示普通“文件已更新”。虚拟光标仅是确认范围的指示器，不声称是实际鼠标或逐键输入位置；完整结果到达后使用“刚刚修改”，只有可靠的执行中范围才使用“准备修改/修改中”。

首个增量建议只做行标记，不自动切文件、滚动或播放键入动画。随后单独增加“跟随当前会话”入口：绑定明确会话，离开该会话或关闭预览时暂停；手动选文件/查找/滚动时统一暂停跟随，并保留一个“继续跟随”操作。自动更新始终不抢焦点。确有使用需求时再拆细分的“锁定文件、仅跟随行”等选项。

精确定位仍需验证原始 patch 的基线与上下文，或者验证 old/new 片段。合成的 hunk、被截断的 EditFileDiff、重复匹配和版本冲突只能降级为文件或范围列表提示。相同文本匹配不是归属的充分证明；无法排除并发编辑时不显示确定性的 AI 行归属。

## 第三版：可选编辑演示

保留虚拟光标和打字效果目标，但作为独立“修改演示”模式交付。正常文件预览始终显示当前内容；演示模式有明确标签和“返回当前文件”。同一位置切模式，不创建第三列，也不自动把用户阅读的正文倒退到旧版本。

两类来源必须区分：

- **回放**：取得可验证的前后片段后，短暂选中旧内容、展示新增内容、移动虚拟光标；状态为“修改回放”，不代表实际键入时序。
- **生成过程**：只有实际 CLI 提供可用且已校验的参数增量时，才逐步展示；状态为“拟议修改/生成中”，工具完成与落盘另行确认。

基线只能来自已缓存且确认对应的版本、明确的执行前快照或完整可信工具记录。事后读磁盘无法保证得到执行前版本；首版不为此拦截所有文件写入，也不建立整个仓库的自动快照。

大修改按块展示，单次动画有总时长与内存上限；新版本到达取消旧动画并追上最新，不建立无限播放队列。减少动态效果时改为静态标记。仅重绘可见片段；字符推进覆盖中文、组合字符和 emoji，位置换算覆盖换行、Tab、DPI 与水平滚动。

复制、查找和行号在演示模式中统一对应可见演示内容。Markdown 源码模式可定位行，渲染模式只标对应块；图片和超限文件保持文件级提示。方案需先做一个小范围原型验证阅读与复制语义，再决定是否默认提供回放入口。

## 实现前验证门槛

| 版本 | 最小验证 | 通过条件 |
| --- | --- | --- |
| 两列预览 | 一边流式聊天，一边打开/刷新另一个文件，再发送消息 | 消息发给原会话；草稿、权限、终端上下文正确；提示不误判聊天隐藏 |
| 两列预览 | 打开、固定、搬移、关闭、窄窗恢复，穿插错误与异步加载 | 标签唯一归属，恢复比例与阅读位置，关闭后无旧结果回写 |
| 修改提示 | 替换、删除、新文件、重复片段、外部编辑和两会话竞争 | 未确认的行位置或归属不显示为确定的 AI 操作 |
| 编辑演示 | 小文本回放与连续覆盖、暂停查找、复制、取消、Unicode | 不阻塞文件同步，不累计过时动画，显示内容与复制内容一致 |
| 真实增量 | 针对所用 CLI 版本录制脱敏的实际事件并建立 fixture | 明确文件/工具身份、增量或快照语义、顺序与缺失补偿；不满足则保留结果回放 |

第一版的必要修改集中在 `files.rs`、`shell.rs`、会话/事件可见性判断、设置及快捷键；不需要同时引入通用 DocumentStore、动画播放器或新的 provider 协议。不能承诺“只加一个开关”，但范围已能独立验收。
