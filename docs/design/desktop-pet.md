# 桌面像素宠物：Conduit 集成设计

版本 1.0 · 2026-11-23 · Windows · 项目锁定的 GPUI Kit

这是现有桌面宠物的重构设计，替代原字符小猫方案。目标是代码绘制的像素角色、可测试的离散动画、真实任务状态与低频唤醒。实施和验收记录见 [pet-notes.md](../pet-notes.md)；未通过真实窗口验收的行为不得写为已验证。

## 1. 产品范围与兼容性

- 沿用 **设置 → 插件 → 桌面宠物** 的总开关、悬浮窗开关、模型服务、语气、回复长度和上下文隐私选项。
- 角色由矩形绘制，不依赖图片或字体。已有气泡、菜单继续使用应用字体和主题。
- 单击先播放 600ms 的 Poked，保留一次手动鼓励语请求；请求尚未结束则显示 Working，结束后显示成功/失败及气泡。忙碌时重复点击不提交请求。缺配置也先播放点击反馈再显示错误。
- 拖动不触发请求；右键菜单可再次互动、收起、隐藏宠物。关闭插件取消请求并隐藏窗口。隐藏悬浮窗保留模型配置。
- 保留气泡复制、再次互动、手动收起和约 25 秒自动收起；悬停阅读或菜单打开期间暂停气泡计时。气泡期限与角色动画独立。
- 接入 Conduit 已有任务和审批状态，不因角色动画、休眠、恢复或展示状态变化调用模型 API。
- 不做自主行走、多角色、换肤、语音、自动聊天。逐像素点击穿透、独立进程、TCP/stdin 输入属于后续扩展，本次不开放监听端口。

## 2. 架构与工程约束

根 Cargo package 保留，增加 workspace member `crates/pet-core`，由 Conduit 通过路径依赖使用。

| 模块 | 职责 |
| --- | --- |
| `crates/pet-core/src/sprite.rs` | 身体、调色板、脸型和 Pose |
| `crates/pet-core/src/raster.rs` | 特效、白边、最终格子合成、水平矩形合并、ASCII 快照 |
| `crates/pet-core/src/state.rs` | 输入事件、宿主活动快照、优先级与期限 |
| `crates/pet-core/src/anim.rs` | 确定性动画及下一次变化时刻 |
| `src/app/encourager/pet.rs` | GPUI 视图、宿主状态订阅、气泡、计时与输入 |
| `src/app/encourager/pet/` | 宿主适配、窗口几何与回归测试，按职责拆分 |
| `src/app/encourager/native_window.rs` | 限定于宠物的 Win32 窗口适配 |

`pet-core` 只依赖标准库，能单独跨平台测试，不读取时钟、不访问系统或 UI。时间由调用方传入；GPUI 适配使用 `background_executor().now()`，使 UI 测试可使用假时钟。复用已有 Windows 依赖，不添加 rand、图片或字体库。修改后按阶段运行相应检查；提交仅在用户要求时进行。

数据依次经过宿主快照/用户输入、StateMachine、Animator、rasterize、GPUI canvas。核心不持有 Conduit 会话或凭据。首帧沿用开窗前生成快照的方式，禁止在主实体更新期间重新读取该实体。

## 3. 精灵规格

### 3.1 画布与坐标

所有坐标单位是「格」，原点在画布左上角，x 向右，y 向下。

| 常量 | 值 | 含义 |
|---|---|---|
| `CANVAS_W` | 25 | 画布宽（格） |
| `CANVAS_H` | 19 | 画布高（格） |
| `SPRITE_W` / `SPRITE_H` | 16 / 12 | 身体大小 |
| `SPRITE_ORIGIN` | (1, 6) | 静止时身体左上角 |
| `SHADOW_ROW` | 18 | 阴影所在行，紧贴身体下方 |
| `FX_REGION` | 列 18..=24，行 0..=11 | 特效区，含 1 格白边，身体不会进入 |

身体实际左上角：`x = 1 + pose.shake`（shake ∈ {-1,0,1}），`y = 6 - pose.bob - pose.hop`。身体最右列最大为 17，所以特效区从 18 列开始，不会互相覆盖。

本轮每格固定为 6 个逻辑像素，角色区域约 150×114 逻辑像素；整数物理像素对齐后尺寸可能略增。原生透明画布固定预留 320×312 逻辑像素供气泡使用，实际窗口区域仅包含角色和当前可见的气泡。4 到 10 的用户尺寸设置留作后续扩展。

### 3.6 特效（fx）

特效是小位图，不超过 5×5，画在特效区。每个特效先画一圈 1 格的白边（对位图做 4 邻域膨胀，颜色用 `halo`），再画本体。这样不管桌面壁纸是深色还是浅色都看得清。

| Fx | 位图与位置 | 颜色 |
|---|---|---|
| `Dots(n)`，n ∈ 0..=3 | 单格点，位置 (19,5) (21,5) (23,5)，只画前 n 个 | outline |
| `Exclaim` | 3×5，左上角 (20,3)：`.#.` `.#.` `.#.` `...` `.#.` | 需要处理用 amber，失败用 red |
| `Heart{rise}`，rise ∈ 0..=3 | 5×5，左上角 (19, 6−rise)：`.#.#.` `#####` `#####` `.###.` `..#..` | heart |
| `Zzz{step}`，step ∈ 0..=3 | 3×5 的 Z，左上角 (20, 6−step)：`###` `..#` `.#.` `#..` `###` | outline |

测试必须断言：所有特效格子（含白边）都在 `FX_REGION` 内。


合法脸型约束：`X` 眼睛占用 `(3,7)` 与 `(12,7)`，禁止与腮红同时显示；栅格化器对外部传入的该组合自动关闭腮红。`Happy/X` 忽略 look。仅对合法组合断言各部件不重叠。

## 4. 状态与宿主映射

展示状态：Idle、Working、Attention、Success、Error、Sleep、Poked、Dragged。

优先级：`Dragged > DebugState > Poked > Attention > Error/Success overlay > Working > Idle/Sleep`。Attention 不应被另一个任务的成功动画遮蔽；Idle 与 Sleep 是互斥条件，不是两个始终成立的层级。

状态机分别保存 working、attention、可选 working_until、结果 overlay、debug overlay、poked_until、dragging、last_activity。所有截止时刻使用单调时钟。DebugState 独立保持 3 秒；Poked 独立保持 600ms；成功 2.5 秒；失败 8 秒。恢复底层状态时不延长已经流逝的期限。

| 输入 | 行为 |
| --- | --- |
| TaskStarted / ToolRunning | 清旧结果，置 working，刷新 10 分钟工作期限和活动时间 |
| NeedsApproval / ApprovalResolved | 设置/清除 attention，刷新活动时间 |
| TaskSucceeded / TaskFailed | 单任务事件接口：结束工作和审批，设置结果 overlay |
| Reset | 清空业务和临时状态，从新的 Idle 开始 |
| 用户点击/拖动/菜单操作 | 刷新活动时间；点击和拖动不清业务状态 |
| 宿主活动快照 | 汇总仍存在的运行与待审批；相同快照不算新活动，不重复启动动画 |
| 宿主完成反馈 | 仅设置结果 overlay，不清除其他仍在运行或等待审批的任务 |

5 分钟没有有效活动且无业务/临时状态时进入 Sleep。任何有效事件和用户交互会唤醒。Attention 没有超时。10 分钟工作超时仅用于离散事件入口；宿主仍拥有的运行属于权威状态，不因宠物自行超时而被标为完成。

集成目标：所有活跃会话中任意待审批/问题待答映射 Attention，其他活跃任务或鼓励语请求映射 Working；后台会话同样可见。真实任务的成功/失败只采用明确的终态结果，不通过最后一条聊天文字猜测，不把取消、删除或窗口关闭当成成功。仅状态变化及真实任务事件算活动；宿主无关重绘不会阻止休眠。

## 5. 动画时间表

Pose 是离散值：bob 0..1，hop 0..2，shake -1..1，look.dx -1..1，look.dy -1..0。xorshift64 的 0 种子替换为固定非零值，测试固定种子。

| 状态 | 时间规则 |
| --- | --- |
| Idle | 每 600ms 呼吸翻转；眨眼开始间隔 2–5s，持续 120ms；环顾开始间隔 6–12s，保持 1.2s |
| Working | 每 400ms 呼吸和 Dots 同步变化，点数 0→1→2→3；look=(1,-1)，Flat；眨眼开始间隔 3–6s |
| Attention | 每 900ms 小跳，周期中 80–160ms 为 hop=1，其余 0；感叹号每 500ms 显隐 |
| Success | 每步 80ms，0,1,2,2,1,0 连续两轮后静止；爱心每 250ms 上升一格，到 3 停止 |
| Error | 每步 60ms，shake=-1,1,-1,1,0；240ms 起静止；红色感叹号常亮 |
| Sleep | 呼吸与 Z 共用 **1400ms** 节拍；Z 的 step=0→1→2→3→0；约 0.714 次唤醒/秒 |
| Poked | 每步 80ms，hop=0,1,2,1,0，Happy + Open；600ms 后状态机恢复底层状态 |
| Dragged | hop=1，Open + O，无特效，静止 |

相同 set_state 不重启动画；真正切换状态才重置所有动画期限。tick 必须可在迟到或跳过多个时刻后返回正确姿态，next_wake 严格大于 now，静止动画返回 None。相邻重复姿态可跳过唤醒。

视图只保留一个可取消的下一次唤醒任务，期限取状态机、动画、气泡和位置写入的最小值。窗口关闭后任务和订阅随实体释放。禁止 detach 的永久循环和常驻 request_animation_frame。Idle 动画平均约 2–3 次/秒；Sleep 少于 1 次/秒。宿主通知不得反复替换同一时刻的任务。

## 6. 绘制与 DPI

先在 25×19 格内合成阴影、身体、腮红、眼睛、嘴、特效白边和本体，再按每行最终颜色合并矩形。最终矩形互不重叠；测试保留语义字母以区分同色的眼睛与嘴。阴影在第 18 行，站立列 4..13，跳起列 5..12，alpha 46/255（约 18%）。每帧矩形少于 120。

GPUI 使用 `canvas` 与 `window.paint_quad(fill(...))`。角色外没有底板，不包裹会绘制背景的组件 Root。

每格默认 6 逻辑像素。物理格子 = round(6×scale)，实际逻辑格子 = 物理格子/scale。画布原点也对齐物理像素；角色区域按实际格子大小计算。125% 缩放时一格为 8 个物理像素，区域随之增大，不能按 150×114 裁切。

回复、右键菜单和收起均不改变原生窗口尺寸或位置，避免 DXGI ResizeBuffers 和延迟布局造成闪烁。固定透明画布通过 SetWindowRgn 仅暴露当前角色/气泡的矩形并集；布局后只在区域变化时更新，收起后的空白不占用桌面鼠标区域。窗口区域按物理像素对齐，成功设置后由系统接管 HRGN。正文使用有明确可用高度的滚动区域，操作栏禁止收缩，防止文字挤占按钮或被父容器裁切。

窗口尺寸/DPI 变化订阅驱动重新计算。`bounds_changed` 会同步通知尺寸订阅，移动和缩放必须经 `window.defer` 在 PetView 借用释放后执行；不能用仍借用实体的 `cx.defer_in` 代替，避免真实 Windows 窗口重入崩溃。

## 7. 窗口与交互

复用已修复的透明 PopUp 创建流程：隐藏创建、显式 WS_POPUP、去掉边框和系统圆角、保留 DirectComposition、同步客户区、绘制首帧、SW_SHOWNOACTIVATE 显示。GPUI 版本锁定为 gpui-pre 0.3.9，Kit rev 为 11345ec002d9f182a266b5d5dd3a217090700a87，API 以本地锁定源码为准。

不抢焦点需要 WS_EX_NOACTIVATE **并拦截 WM_MOUSEACTIVATE 返回 MA_NOACTIVATE**；锁定后端默认返回 MA_ACTIVATE。仅修改扩展样式不足。适配只作用于宠物，保留右键菜单和鼠标事件。无焦点窗口以鼠标为主要入口，不能承诺按下全局 Esc 就关闭宠物；已有 GPUI 焦点路径中的 Esc/Enter/Space 保留。

拖动阈值为 4 物理像素，屏幕坐标用于计算窗口移动，输入回调后 defer 执行。需处理窗口外松手与捕获丢失，绝不能残留 Dragged。后台窗口的 SetCapture 有限制；未通过原生验收前，不宣称“无激活的窗口外拖动已可靠”。禁止为此引入常驻鼠标轮询；仅按下期间的有界恢复任务可使用。

位置继续使用现有 Store 的紧凑角色锚点和逻辑坐标格式，不在此次重构中静默改成物理坐标或另建 pet.json。关闭窗口强制保存，移动后用单次延迟合并写入；动画不触发磁盘写入。恢复时选包含锚点的工作区，否则回主屏右下角；恢复、DPI 调整和拖动时将预留画布限制在工作区，确保之后展开不会推移角色或把气泡放到屏外。混合 DPI、拔屏后回退属于真实窗口验收项。

逐像素穿透不在本轮实现。HTTRANSPARENT 的文档行为限于同一线程，不能作为穿透到任意桌面程序的保证。未来需要独立验证窗口区域或合成方式，并覆盖跨进程目标。

## 8. 模型、设置与隐私

既有鼓励语 API 路由保持：Claude Messages / Codex Responses 服务，复用用户已有服务配置与受保护凭据。只有用户主动互动发起请求；动画和任务映射不发送消息、不启动 CLI。

默认只发送场景、语气与长度指令；用户开启上下文选项才附上当前会话最近一条用户消息与助手回复并限长。不发送项目文件、终端输出或完整历史，不把回复写入编程 transcript。取消后的迟到结果按已有 generation 防护丢弃，传输可能直到超时才结束。错误提示不得包含凭据或敏感 URL。

回复长度档位为简短 40、正常 80、较长 120 字符。明确将所选上限加入模型指令，要求 1–3 个完整短句、单段纯文本、不换行。返回值统一空白；超限时优先截到完整句末，没有完整句子时在安全的字形/英文词边界加省略号。省略号计入上限，不再直接以字符数硬切后伪装成完整回复。

## 9. 验证与交付

1. 核心：身体及七张脸黄金快照、合法脸型无重叠且在身体内部、全部 FX 白边在保留区、最终矩形边界/互斥/数量。
2. 状态：优先级、审批保持、Poked/Debug/结果独立期限、新任务清旧结果、睡眠/超时、权威快照不误超时、多任务结果不清其他工作。
