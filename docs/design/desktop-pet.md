# 桌面宠物

状态：2026-11-19 根据第二轮桌面测试修复 Windows 原生边框与展开裁切。待机仅显示字符小猫，直接点击触发思考动作与模型 API 反馈。

## 本轮评审结论

旧实现有三个问题：透明窗口内部仍绘制了带背景、边框与标题的完整卡片；通用组件 Root 也绘制主题背景；角色点击只负责展开面板，真正请求需要再点击聊天按钮。前两项让宠物看起来像工具窗口，后一项让点击角色缺少回应。

本轮移除宠物窗口中的卡片、标题栏、常驻按钮和 SVG 形象。宠物窗口直接使用 GPUI 根视图，避开组件 Root 的主题底板。设置和工作台互动页继续承载模型、场景与语气选项。

第二轮实测发现，移除业务卡片与 Root 仍不足以消除 Windows 系统边框。当前锁定的 `gpui-pre-windows 0.3.9` 用样式 `0 / WS_OVERLAPPED` 创建 `WindowKind::PopUp`，实际 HWND 仍出现 `WS_CAPTION`，DWM 非客户区渲染也处于开启状态。此外，原生 `SetWindowPos` 在 GPUI 窗口被借用期间同步派发消息，回调无法重新取得窗口；布局视口因此可能停留在旧尺寸。这分别解释了外框随反馈扩大，以及气泡、字符被裁切的问题。

## Codex 宠物调研与采用范围

参考 [Codex 官方宠物说明](https://learn.chatgpt.com/docs/pets)：桌面角色可拖动、保存位置和隐藏，使用 sprite 动画，减少动态效果时使用静态帧。官方支持透明 PNG / WebP 自定义素材。这里借鉴的是“透明角色 + 状态反馈 + 临时浮层”的交互方式；Conduit 按用户要求继续使用等宽字符绘制，每组字符表情相当于一帧，点击仍触发既有模型 API。

官方没有在该说明中公开原生窗口源码或创建参数，因此不把 Electron 的配置推断为 Codex 实现。作为独立工程参考，[Electron 透明窗口文档](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles) 也明确区分透明内容与无框宿主窗口，并指出透明像素不会自动实现点击穿透。本项目直接使用 GPUI / Win32，不引入 Electron。

Windows 配置依据 [Microsoft DWM 属性文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)，并用本机原生窗口探针验证：

- 创建期间先隐藏窗口，显式改为 `WS_POPUP`，移除 `WS_CAPTION`、`WS_THICKFRAME` 与扩展边缘样式；保留置顶工具窗口属性。
- 关闭 DWM 非客户区渲染；在支持的平台上关闭系统圆角、边框颜色和 backdrop。无需额外叠加模糊背景或整窗不透明色。
- 保留 GPUI 的 DirectComposition 透明渲染。若环境显式禁用了该能力，开启宠物会返回明确错误，避免展示不透明替代窗口。
- 设置真实无框客户区尺寸后显式调用 `bounds_changed`，更新 GPUI 视口。移动、展开和收起同样同步；避免使用仍缓存旧系统边框偏移的尺寸换算。
- 准备首帧场景后以 `SW_SHOWNOACTIVATE` 显示，不主动抢占用户当前焦点。

适配仅作用于宠物窗口；不修改依赖缓存或主应用窗口样式。代码位于 `src/app/encourager/native_window.rs`，由实际宠物和原生探针共同使用。

## 产品定位

桌面宠物是一个可选的内置插件，以悬浮角色作为主要互动入口。用户可以主动和它聊聊，宠物通过 Conduit 宿主调用用户已有的模型 API 返回短消息。功能不启动 CLI，不自动分析会话或定时插话。

设置位于 **设置 → 插件**。插件总开关控制宠物能力和工作台互动入口；独立的悬浮窗开关控制角色是否显示。模型、风格和隐私选项保存在宠物设置卡片中。关闭插件会隐藏宠物、撤销入口并取消当前请求，但保留模型配置和悬浮窗偏好。

这是随应用发布的内置原生插件，不是可安装的用户脚本包。宿主负责 API 路由和受保护凭据；宠物界面不会获得密钥或任意网络访问能力。当前外部插件包仅支持声明式文件图标，Shell 插件运行时也未进入生产准入，因此不把 API 调用交给外部代码。

## 互动流程

1. 在 **设置 → 插件** 开启桌面宠物，并选择是否显示悬浮窗。
2. 选择已有的直连模型服务、模型、宠物语气和回复长度；可选允许参考当前会话最近一轮。
3. 直接单击字符小猫，立即切换到思考姿态，同时提交一次模型 API 请求。思考表情和省略号每 360ms 换帧，至少显示约 540ms；连续点击不会重复提交请求。
4. 完成后变为开心表情并显示回复气泡。服务未配置或请求失败则显示疑问表情与具体提示。气泡可复制、再次聊天或手动收起，不进入编程聊天记录。
5. 按住角色并移动至少 6px 才开始拖动；松开拖动不会调用模型。右键显示操作菜单，可隐藏宠物；Esc 收起气泡和菜单；角色获得焦点后 Enter / Space 也能触发互动。
6. 气泡在约 25 秒后收起，鼠标悬停阅读时暂停计时。回到待机后只保留字符小猫。插件开关与悬浮显示开关仍由设置页管理。

宠物提供四种场景：我卡住了、刚搞定一个问题、给我一点动力、今天先收工。语气可选温柔前辈、热血教练、冷面同事或猫猫。回复长度约为 40、100 或最多 180 个字符；较长回复不会触发续聊或额外请求。

## 悬浮宠物 UI

宠物使用独立置顶的透明无边框 PopUp 窗口。待机承载范围为 148 × 112，反馈或右键菜单出现时为 320 × 312。待机没有窗口底色、外框、阴影、标题、语气标签或聊天按钮，只有字符本身。思考也在角色本身表现，不需要先展开面板。

字符使用固定等宽网格，暂用 Consolas，字号 22px，每行 24px；浅暖色字符配细暗色描边，使浅色和深色桌面都可辨认。顶部保留 4px 安全间距，每个表情保持相同占位，避免换帧时角色跳动或描边被裁切。待机不循环播放装饰动画。反馈气泡只有自身底色，取消描边；固定 12px 内边距与 8px 内容间距，长回复在气泡内部滚动。

```text
待机          思考           反馈
               ...
 /\_/\         /\_/\         /\_/\
( o.o )       ( -.o )       ( ^.^ )
 / > <\        / ? \        / > <\
```

窗口位置保存为字符小猫在紧凑状态下的左上角坐标，避免保存临时气泡的位置。Windows 下气泡向角色左上方展开，空间足够时保持角色在屏幕上的位置；靠屏幕边缘时夹取到显示器可见区域。气泡收起后窗口同步缩小，避免留下大块透明拦截区域。透明空白目前仍属于窗口的命中范围，未实现逐像素点击穿透。创建时不主动请求焦点；用户点击时窗口可能按系统行为获得激活。不播放音效。

鼠标拖动使用 Windows 原生窗口坐标，避开标题栏命中区域与单击交互的冲突。窗口移动在输入处理结束后执行。非 Windows 平台保留 GPUI 的移动与缩放回退路径，视觉和锚点行为需另行实机验证。

设置卡片限宽 760px，分为插件/显示开关、对话偏好、上下文隐私三组，使用既有主题和轻分隔线。宽屏采用左侧标签、右侧 288px 控件，窄屏下拉字段自动折行；下拉控件高 32px，值左对齐并显示下拉箭头。插件、悬浮显示、上下文三个布尔设置使用切换开关，开关与标签保持同行；默认深浅主题明确设置关闭态灰色轨道及白色滑块，避免融入底色。关闭插件仍保留模型偏好。移除插件介绍及字符小猫操作说明两段提示；隐私提示随上下文开关更新。没有兼容服务时，字段显示简短空状态，配置引导单独放在字段下方。

设置标题与右侧入口统一使用猫咪图标。插件关闭期间，宿主会清理失效的渲染器绑定，因此每次重新开启都从同一个定义重新安装原生渲染器，确保图标和点击功能与首次启动一致。回归覆盖首次关闭、启动时启用，以及连续三次停用/启用。

## 模型与隐私

宠物使用独立模型设置，不跟随会话 CLI 路由，也不要求重复录入 API Key。当前支持已配置的 Claude Messages API 和 Codex Responses API 服务，包括本地创建和从 cc-switch 导入的 provider；导入服务使用 Conduit 同步时保存的加密运行配置，地址、凭据及请求头不再随每次请求回读 cc-switch 数据库，也不把密钥复制到宠物设置。修改外部服务后通过“重新读取配置”更新快照。切换服务会更新模型列表，重新选择当前服务会保留已选模型；只支持 OpenAI Chat Completions 的服务暂不可选。模型凭据只由宿主读取。

默认发送固定指令、场景、语气与长度要求，不发送代码、项目文件、终端输出或聊天历史。开启“参考当前会话最近一轮”后，每次手动触发才会附上最近一条用户消息和助手回复，并限制长度。上下文不缓存、不写入宠物设置；回复不会发送给编程助手，也不会写入 transcript。

请求在后台执行，使用非流式响应、超时、响应大小限制和已有服务地址校验。取消或关闭插件后，迟到结果会被丢弃；传输本身可能持续到网络超时。错误提示不展示凭据、认证头或敏感 URL 参数。

## 生命周期与崩溃修复

GPUI 的 open_window 会同步构建并绘制新窗口的首帧。此前在主应用实体更新期间开启宠物时，首帧构造器又读取该实体，造成“while it is already being updated”崩溃。现在主应用在开窗前生成宠物状态快照，并将快照传入首帧；后续状态变化再由实体订阅更新。

GPUI UI 回归测试覆盖设置中开启、启动恢复，以及新窗口待机无背景绘制、点击先思考后反馈、重复点击不重复请求、拖动不触发聊天、复制入口和 Esc 收起气泡。
