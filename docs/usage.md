# 使用指南

Conduit 当前支持 Windows x64，运行 Claude Code、Codex 或 OpenCode 的本机 CLI。

设置和关于图标位于窗口右上角，在最小化、最大化和关闭按钮的左侧。

设置会进入独立的整页工作区。点击“返回工作台”或按 Esc 返回，聊天草稿、文档标签与当前会话保留。可用 Ctrl+, 或 Ctrl+M 打开；再次使用打开快捷键会聚焦设置搜索。左侧按工作台、AI 连接、扩展能力、自动化、应用分组，窄窗口下可滚动导航。

Ctrl+F 聚焦设置搜索；Enter 打开第一项结果。搜索具体选项会打开对应的分组视图，“查看完整页面”或点击左侧分类可恢复该页全部设置。有搜索内容时，Esc 先清除搜索，再按一次才返回工作台。编辑表单打开时，Esc 优先交给表单处理。 原生配置或模型服务表单有修改时，Esc、关闭与取消都会保留表单，选择“继续编辑”或明确“放弃未保存修改”；检测或保存进行中不能关闭。

普通偏好即时应用并自动保存，底部显示保存中、保存失败或只读状态。CLI 路径选择后立即保存；模型服务和原生配置通过各自的编辑表单保存。

## 开始对话

1. 在对应 CLI 中完成安装和登录，确认终端可以正常使用。
2. 添加本地工作区，在输入区选择引擎、Provider、模型和思考强度。
3. 输入任务，按 Enter 发送；Shift+Enter 或 Ctrl+Enter 换行。

输入 `@` 搜索工作区文件，也可拖入文件、使用附件按钮或粘贴图片。工具请求需要审批时，选择允许或拒绝；取消会结束当前任务的进程树。

## 集成终端

点击主内容区底部的终端图标，或按 `Ctrl+反引号`，在当前活动工作区打开终端。图标的数量徽标表示当前工作区保留的终端数，数量为零时隐藏徽标。初次打开创建 shell，已有标签则恢复选中项；面板已打开时，该快捷键先聚焦网格，再次使用会收起。面板支持拖动分隔线调整高度和最大化，窗口过矮时占满中间区。

新终端以创建时选中的工作区（包括 Git worktree）作为启动目录。切换工作区会显示该工作区自己的标签，已有 shell 继续运行，不自动执行 `cd`。shell 内执行 `cd` 不会改变工作区选择。未选择工作区或目录无效时会提示，不自动改到其他目录。正常运行时不显示目录副行，启动、失败、退出和清理状态仍显示必要提示。

点击 `+` 或按 `Ctrl+Shift+反引号` 新建标签。旁边的 Shell 菜单可选择默认 Shell、PowerShell 或 cmd，选择后会新建并记住偏好。默认优先使用 PATH 中的 PowerShell 7，再使用系统 Windows PowerShell，最后使用 cmd。每工作区最多保留 4 个标签，全局最多 8 个，已退出标签也占名额。

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl+反引号` | 打开、聚焦或收起终端 |
| `Ctrl+Shift+反引号` | 在当前工作区新建终端 |
| `Ctrl+Shift+PageUp/PageDown` | 切换当前工作区的终端标签 |
| `Ctrl+Shift+F6` | 将焦点返回之前的内容 |
| `Ctrl+C` | 将中断控制字节发送给 shell |
| `Ctrl+Shift+C` | 复制选区 |
| `Ctrl+Shift+V` / `Shift+Insert` | 粘贴；多行先预览并确认 |

拖动选择文本，双击选择词、三击选择行，滚轮回看输出。TUI 开启鼠标模式后，可按住 Shift 进行本地选择或滚动。复制使用 `Ctrl+Shift+C`，只复制选区；原始终端输出不保存到聊天记录。

**收起保留进程；运行中的终端需要两次点击标签右侧关闭图标：第一次变为红色确认图标，第二次才终止该终端及其子进程并关闭标签。** 点击标签主体、切换工作区或收起面板可取消待确认状态；面板下方不再显示确认条。关闭未选中的终端不会切换当前标签。已退出标签保留输出，可直接点 × 关闭或重新启动。关闭应用会确认并等待终端清理；移除工作区前也需要先结束其终端。更新页会等待活动终端退出，或通过“终止全部终端后安装”继续。终端进程不会在应用重启后恢复，停止聊天只作用于聊天任务。

## 文件名搜索

在主界面连续轻按两次 Shift（间隔不超过 500ms），搜索当前工作区的文件名或相对路径，支持模糊匹配。使用 ↑ / ↓ 选择，Enter 打开只读文件标签，Esc 关闭；也可点击搜索结果。Shift+字母、Shift+Enter 等组合键不会打开搜索。

搜索遵循工作区忽略规则，不搜索文件内容。尚未选择工作区时会提示先选择工作区。

## 文件内容查找

在文件预览标签内按 Ctrl+F 打开或关闭查找条，输入关键词后自动高亮并定位。输入框右侧的筛选图标切换模糊匹配，选中时表示开启，悬停可查看状态。默认忽略大小写并开启模糊匹配，例如 `opfile` 可找到 `open_workspace_file`；关闭后只匹配连续文本。关键词首尾的空格参与匹配，仅含空白时不搜索。匹配限制在同一逻辑行内，结果按文件顺序排列。

Enter / F3 跳到下一个结果，Shift+Enter / Shift+F3 跳到上一个，到达首尾时循环跳转。再次按 Ctrl+F 或按 Esc 关闭查找并保留当前位置；文件和关键词未变时，重新打开会恢复当前命中，并聚焦、全选关键词。打开查找条时，单行选中文本会填入查找框，多行选区不替换关键词；切换文件标签分别保留查询词和当前命中。

支持源码、普通文本和 Markdown 正文，Markdown 按实际显示的文字查找，带行号代码块支持命中高亮；Mermaid 中的命中定位到图块。查询词最多 256 个字符，最多显示 2,000 个结果，超过时计数带 `+`。

## CLI 与模型配置

设置左侧将 **AI 引擎**、**模型与服务**、**新会话默认**、**Skills**、**MCP 服务** 分开。搜索支持具体设置、中文关键词、英文别名、服务名称和模型 ID，结果显示分类路径，点击后进入对应分组或页面与引擎。

**AI 引擎**：选择本机 CLI，修改路径后自动检测版本。路径查找顺序为环境变量、应用配置、PATH、常见安装目录；环境变量覆盖应用路径时会直接提示。支持本机 `.exe` 和 npm `.cmd` 启动器。版本检测仅检查启动与版本，认证仍由官方 CLI 完成，可从页面打开安装与登录说明。

每个引擎可单独启用或停用。停用会阻止后续聊天、排队消息、自动命名及提交说明任务启动；正在运行的任务继续，历史保留。停用后仍可调整路径和检测版本，重新启用即可恢复使用。

**模型与服务**：填写端点和 API Key 后，可以主动读取模型目录，也可手动填写模型 ID。直接输入的 API Key 使用当前 Windows 账户加密保存；也支持只保存环境变量名。读取目录不执行模型生成，也不代表生成权限已验证。环境变量修改后需重启应用，直接输入凭据则无需重启。

展开“管理模型目录”，可搜索模型名称、ID 和备注，添加或编辑应用侧模型定义（显示名称、备注、上下文窗口），隐藏/恢复候选项，或设为该引擎的新会话默认模型。目录按 50 项分批显示。“移除本地定义”会移除应用侧覆盖，CLI 原本提供的定义仍保留。隐藏不会修改历史会话；已选模型及新会话默认值仍可识别。模型偏好保存在应用数据中，刷新原生目录不会清除它们。OpenCode 模型 ID 使用 `provider/model` 格式。

服务列表提供“用于新会话”和引用位置查看。**新会话默认**按引擎保存服务与模型；现有会话保留自己的配置，输入区临时选择优先于默认值。自动命名与 Git 提交说明的模型在各自页面设置。

Claude / Codex 支持自定义 Provider 与 CCS 配置同步。OpenCode 使用自己的 Provider、模型目录和原生思考档位，配置方式见 [OpenCode 文档](opencode-cli.md)。切换模型会清除不再适用的档位。“重新读取配置”读取 CLI 和 cc-switch 的配置；从 cc-switch 导入的服务仍在 cc-switch 中编辑。被会话、辅助任务或新会话默认设置引用的服务不能直接删除，引用列表包含历史会话。

| 环境变量 | 用途 |
| --- | --- |
| `CONDUIT_CLAUDE_PATH` | Claude Code 路径 |
| `CONDUIT_CODEX_PATH` | Codex 路径 |
| `CONDUIT_OPENCODE_PATH` | OpenCode 路径 |
| `CONDUIT_DATA_DIR` | 独立的应用数据目录 |

## Skills 与 MCP

两个页面分别展示技能和服务器定义，并明确当前引擎和作用范围。选择工作区时会同时扫描项目与继承的全局定义；来源文件、禁用状态和连接测试结果分别展示，不将“已发现”当作“会话已加载”。这里的引擎选择独立于模型服务页和聊天输入区。

Skills 支持创建、从本地文件夹导入、编辑来源文件和定位文件夹。导入保留技能的脚本及其他资源，不覆盖同名目录；插件包中的文件由安装包管理，不提供直接修改。

筛选菜单支持“全部 / 未禁用 / 已停用 / 插件托管 / 同名定义”；搜索也覆盖来源路径。同名条目分别保留，不自动推断配置优先级。本地 Skill 可停用和恢复：将 `SKILL.md` 改名为 `SKILL.md.conduit-disabled`，恢复时改回，脚本和资源文件保留。共享目录中的操作影响所有使用该目录的 CLI，确认框会说明来源和影响；目标冲突时不会覆盖。

MCP 支持按名称、命令及逐行参数，或远程 HTTP 地址创建服务。先预览合并后的原生配置，再保存；预览保留原配置的其他内容和注释。环境变量、认证头与启停选项可在来源编辑器中修改。保存会校验格式、检查外部修改冲突并保留上一版 `.conduit-backup` 备份，配置由 CLI 在后续会话启动时加载。

Codex / OpenCode 的 MCP 条目提供“停用 / 恢复”，点击后预览原生 `enabled` 字段变更，保存配置后生效。Claude 的启停仍通过来源配置管理；插件托管条目通过对应 CLI 管理。

展开 MCP 条目后可主动“测试连接”：启动配置命令或连接远程服务，初始化并读取工具列表，不调用工具。本地命令测试最多 15 秒，HTTP 请求每步最多 5 秒；可以取消。支持 stdio 与 Streamable HTTP；OAuth 登录、旧式 SSE 和需要 CLI 展开的动态配置应在原生 CLI 中处理。测试结果仅针对所选来源定义，不代表配置优先级解析后的会话状态。

## 会话与文件

聊天输入区权限按钮左侧的 **+** 可直接在当前工作区新建会话，原会话的未发送草稿会保留。

工作区中的会话可以搜索、重命名、置顶、归档和删除。右键会话可选择“置顶会话”或“取消置顶”；置顶状态重启后保留，置顶会话始终排列在普通会话之前，不占用设置中的侧栏会话数量。各组内正在运行的会话优先，其余按最近活动排序。Claude / Codex 的终端历史会按工作区自动导入，继续发送时恢复原生 CLI 上下文，历史会话继续对话后会在所在分组内前移。

标签超过可用宽度时可横向滚动，右侧下拉菜单可选择任意标签；切换会话、关闭标签和窗口变窄时会自动显示当前标签。

输入框右上方的文件修改统计可展开明细，点击文件行会弹出本轮 Diff，支持并排和统一视图。同一文件的多次编辑按顺序切换；内容来自本轮对话记录，截断记录会显示提示。向上浏览历史时，输入区上方中央显示“转到最新消息”箭头。

回复过程中按 Enter 会自动排队一条消息，输入框上方显示迷你气泡，当前回复完成后自动发送；可取回编辑或移除，停止或失败后会暂停，暂停消息可手动发送。点击停止图标，或在输入区按 Ctrl+Shift+X，只停止当前会话；清理完成前按钮禁用并显示加载指示，悬停提示“正在停止”。快捷键说明显示在输入框 placeholder 中，Shift+Enter 和 Ctrl+Enter 继续用于换行。

切换会话会恢复上次阅读的消息位置；原来位于末尾的会话继续跟随最新消息。侧栏获得焦点后，可用上下方向键移动、Enter 打开、左右键折叠／展开工作区、Home / End 跳到首尾；Shift+F10 或菜单键打开当前会话的菜单。侧栏工具栏也提供可点击的文件搜索入口。

不同会话可并行运行，切换会话不会停止任务。同一会话及同一引擎的相同原生会话不能重复运行；同目录任务共享文件，需要隔离时使用不同 Git worktree。

文件侧栏中，单击预览、双击固定标签。源文件和 Diff 目前只读，支持语法高亮、选择复制与差异导航。

## Git

左侧“变更”面板提供文件选择、暂存、Diff、提交与推送；左侧分支图标可查看和管理分支，并显示待推送提交数 badge，悬浮可查看完整数量和上游提示。勾选文件后可批量暂存或移出暂存区；提交与 AI 提交说明只使用勾选文件的已暂存内容，未勾选的暂存内容及未暂存修改会保留。未勾选已暂存文件时提交按钮不可用，需提交全部时先全选。Git 写操作与同一仓库的聊天任务协调，避免并发修改。

新建本地分支后可直接使用 Commit and Push：首次推送自动创建同名远程分支并设置上游，无需在终端执行命令。远程依次按分支的 `pushRemote`、`remote.pushDefault`、分支的 `remote`、`origin` 或唯一远程选择；已有上游的分支继续推送到原目标。只有未配置远程或多个远程无法确定目标时才需要配置或在分支菜单 Push 中选择目标。推送失败仍保留已完成的本地提交。

Diff 顶部可切换“已暂存（待提交）”“未暂存”“全部修改”，分别比较 HEAD→暂存区、暂存区→工作区、HEAD→工作区。提交区的“核对待提交文件”只列出勾选的暂存文件，默认查看其暂存版本。提交不可用时会显示原因和相应处理入口。

分支、冲突恢复和 Diff 细节见 [Git 界面文档](git-ui-design.md)。

## 通知

右侧主内容区底部工具栏最右端的铃铛打开通知历史，数字表示未读数量。通知面板在聊天、文件、Diff、Git 分支管理和空工作区中都可使用；窄窗口会以右侧浮层展示。

右侧栏顶部使用铃铛（通知）和扳手（工具详情）图标标签，与会话标签栏同为 36px 高。会话标签栏右端的侧栏按钮用于展开或收起侧栏，并保留上次选择；点击底部铃铛或工具的详情入口会切到对应标签。没有会话时，侧栏仍可打开通知。

通知中心记录后台会话完成、执行失败、待审批、Git 操作结果、更新和保存故障。CLI / MCP 检测及 Skill 导入的显式结果也会保留。输入校验、Git 进度和聊天流式内容继续在原位置显示，避免历史被高频状态填满。

发送消息时的保存进度仅显示在运行状态或待发送队列中，不弹出红色提示，也不新增通知。启动失败、发送保存失败和排队保存失败统一通过通知浮层及通知中心反馈；保存失败时保留草稿和附件。

- 浮层消失或关闭不会删除历史，也不会自动标为已读。点击“查看”会标读并跳转到对应会话、工作区或设置。
- 可切换“全部 / 未读”，使用“全部标为已读”和“清除已读”。已读且不再待处理的卡片，在悬浮时显示右上角 X，可移除单条记录；键盘聚焦 X 时也会显示。
- “查看”固定在卡片右下角；时间在左下角以较小的辅助文字显示，仅在悬浮卡片时出现，悬浮时间可查看完整时间。
- 当前仍有效的会话审批在“查看”左侧提供“允许本次 / 拒绝”，并显示命令或文件摘要；点击后按钮进入提交中，收到运行时确认才显示“已允许 / 已拒绝”并标读。允许仅使用本次授权；请求不支持时该按钮禁用，仍可拒绝。审批结果表示运行时已处理该决定，不代表工具已执行完成。
- 快捷审批可处理后台会话及其具体请求，保留当前会话、草稿与输入焦点；需要填写答案的问题仍通过“查看”处理。取消、会话结束、目标删除或换轮后，旧审批操作会失效；恢复的历史不提供审批按钮，也不会重放请求。
- 打开历史本身不会清空未读；删除会话或工作区后，旧通知不会重新创建它们。
- 历史单独保存于数据目录的 `notifications.json`，最多保留 200 条、30 天。重新打开应用会恢复历史和未读，不重弹旧提示；关闭前的待处理请求会标记为已结束。
- 通知目前仅在应用内展示。历史文件损坏或无法写入时会显示提示，本次仍可使用内存历史；通知历史不是长期审计日志。

## 更新与数据

在“关于”检查更新并查看 changelog；设置 → 数据与更新可调整自动检查、后台下载和空闲安装。默认不会自动重启，安装前等待后台任务结束并保存草稿。旧安装版首次迁移需手动安装带更新助手的新包。

默认数据位于 `%LOCALAPPDATA%\Conduit`。会话、工具输出与配置在本地保存；模型生成由选用的 CLI 处理；主动读取模型目录和 MCP 连接测试由应用发起。加密凭据需要原 Windows 账户才能解密。聊天记录可能包含代码和命令输出，请按需要保护或备份该目录。卸载保留用户数据。

正常退出会在会话数据保存完成后保存聊天草稿、工作区新会话草稿、提交说明、标签与附件引用；重新打开后恢复编辑，草稿不会自动发送，队列仍保持暂停。草稿写入失败会取消退出并保留输入。更新重启的草稿恢复继续兼容。外部附件若已移动或删除，会提示重新添加；突然断电或强制结束进程不属于正常退出保障。
