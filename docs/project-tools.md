# 项目工具

会话工具栏的“项目工具”集中提供以下入口。本批次不提供项目运行配置、命令管理器、构建测试执行器或运行日志系统。

| 入口 | 当前交付 | 边界 |
| --- | --- | --- |
| 任务 | 目标、分支标签、关联会话、验收清单、计划/进行中/待审查/完成、归档恢复 | 修改目标或验收项使验收失效；未确认全部验收项不能完成 |
| 任务 worktree | 复用 Git 表单，创建独立目录及任务副本；归档后显式确认清理 | 原任务保留；Git 拒绝脏、锁定或未注册目录，分支保留；没有环境初始化脚本 |
| 模板 | 引擎、服务标识、模型、力度、显式 ACP variant、权限、提示词 | 不复制密钥、原生会话 ID 或动态能力目录；尚不组合 Skills/MCP |
| 上下文交接 | 按消息边界生成可编辑 Markdown，复制或创建另一引擎的新会话草稿 | 只转移可见用户/助手正文；不复制隐藏状态；128 KiB 上限及省略提示 |
| Codex 原生分支 | 从已记录的完成轮次建立独立原生会话，保留截至该轮的上下文和本地历史 | 创建不发送模型提示词、不恢复文件；旧导入历史没有可靠轮次映射时使用上下文交接 |
| 代码和终端上下文 | 按行号捕获代码及来源指纹；把终端选中内容附到草稿 | 不自动发送，终端片段不代表完整日志或验证结果 |
| 审查反馈 | 行级意见、版本指纹、处理状态、已查看、历史收件箱、只读 AI 审查草稿及结构化发现导入 | AI 发现默认待复核；PR 讨论保留独立的远端位置；详见 [Git 工作流](git.md) |
| GitHub PR/CI | 当前分支 PR、检查、会话评论、行级讨论及本地同步、失败检查转修复任务、打开链接、附到草稿 | 使用已有 gh 认证；远端状态与本地处理状态独立；不写回 GitHub，无 job 日志 |
| 用量和预算 | 按本地月份、日期、引擎、服务汇总已知 token 与速度，月度 token 提醒 | 未知、部分、历史覆盖单独标记；不估算金额、不硬停止 |
| 自动任务 | 模板驱动的小时间隔或人工会话成功结束事件；暂停恢复、编辑删除、运行记录 | 应用须运行；强制只读；不补跑、不重叠、不连锁触发 |
| 文件检查点 | 手动保存一个文本文件，预览后恢复，自动保留恢复前副本 | UTF-8、1 MiB、最多 200 条；不恢复整个项目或 Git 索引 |
| 产物收藏 | 保存报告、图片、文档路径或 HTTP(S) 服务地址，用默认应用打开 | 不启动服务；无内嵌浏览器；移除收藏不删除文件 |
| WSL/SSH | 保存目标与目录，使用系统客户端连接、重连交互终端 | 文件树、Git 和聊天仍是本地工作区；完整远程路径与进程管理尚未实现 |

## 任务和上下文

“创建任务 worktree”需要先刷新 Git 分支面板。用户确认目标目录和分支，成功后在新工作区复制任务目标与验收项，清空会话关联和验收结果，记录来源工作区。创建不自动合并、提交或推送。清理要求所有相关任务已归档且会话、终端已结束，使用不带 force 的 `git worktree remove`；任务记录和分支仍保留。

模板、交接、代码片段和审查操作只准备或追加草稿，保留原会话草稿。助手消息的“从此处分支”打开交接预览。代码片段输入 `1-20` 或单个行号，留空时取全文；记录路径、行范围及捕获时的全文指纹。代码和终端片段各最多 64 KiB，交接最多 128 KiB。

打开“项目工具 → 项目工作流 → 交接与分支”，选择已完成轮次，再点击“创建原生分支”，可建立独立 Codex 会话。应用只记录实际收到且与当前线程、轮次匹配的成功完成事件，最多保留最近 256 个分支点；不会从消息数量推测原生轮次。复制本地历史前核对内容指纹，单次历史内容上限 16 MiB。源会话和草稿保留，新会话沿用引擎、服务、模型、力度与权限。

创建先保存本地记录，再调用 `thread/fork`，要求返回独立线程 ID 且最后一轮正好是所选轮次。创建期间不能向待绑定会话发送或排队消息；保存失败、配置变化或 CLI 不支持时保留可重试的本地分支。CLI 返回不匹配时不绑定、不回退为新提示词；此时 CLI 侧可能已经生成一个线程，界面会提示检查版本后重试。创建过程不启动继承目标的自动续跑，也不触发完成自动任务、排队发送、自动命名或新增用量记录。分支的首个后续轮次若缺少可靠累计用量基线，统计标为不完整，不重复计入源会话消耗。

原生分支不会回退工作区文件或 Git 状态。Claude、OpenCode、Qoder 以及缺少已记录完成轮次的旧会话仍可使用可编辑上下文交接。

## 用量和自动任务

用量仅记录功能启用后实际观测到的轮次，不把导入历史的最后计数当成本月账单。Codex 采用累计计数的有效差值；其他引擎采用报告的轮次值。最多 10,000 条，淘汰历史后显示覆盖不完整。预算按项目和本地月份提醒，每月一次。

自动任务由用户从模板显式启用，界面说明模型调用会产生用量。先保存触发记录，再创建后台会话并通过既有发送保存门控启动，不切换前台会话或覆盖草稿。间隔为 1 小时至 366 天，错过超过 60 秒记录“错过”；重启时未结束的记录标为“中断”，不补跑。每项不重叠，事件触发最多每分钟一次，自动任务不会触发其他自动任务。最多 50 项调度、1000 条运行记录。

编辑或删除规则前须暂停后续触发并等待当前执行结束。编辑可以保留已保存的模板副本，也可以选择当前项目的另一模板；保存后仍处于暂停状态，恢复时从当前时间计算下一次触发。删除须再次确认，仅移除规则，保留执行记录和结果会话；历史记录仍按原项目显示。

## PR 审查同步

失败检查旁的“创建修复任务”保存 PR 链接、PR 提交、当时的本地 HEAD、分支、检查名称、状态、详情链接和快照时间，并打开对应任务。任务初始为计划状态，包含排查原因、处理问题、核对版本和 CI 结果三项未勾选的验收要求。通过任务的“准备会话”选择引擎后，可继续编辑草稿并自行发送；创建任务本身不会调用模型、启动检查或改写其他工作区的草稿。

相同工作区、PR 链接、提交、检查名称和详情链接对应同一任务；再次操作显示“查看修复任务”，保留编辑过的目标、会话、验收和归档状态，重启后仍能识别。不同提交或检查链接会生成独立任务。缺少链接且同名的检查共用一项任务。CI 后续通过不会自动完成任务或勾选验收；快照不含作业日志，也不证明当前未提交文件已经验证。

只有明确返回失败、错误、超时、启动失败或需要操作的检查可创建任务。运行中、取消、跳过、成功和未知状态不推断为失败；已有任务仍可查看。刷新期间、工作区已移除、过期按钮和不可写状态会阻止新建，保存错误沿用任务面板提示。

打开“项目工具 → GitHub PR / CI”，刷新当前分支的 PR。在“行级审查讨论”中查看文件、左右侧、当前和原始行号、GitHub 已解决及位置过期状态、首条评论对应提交与 Diff 片段。文件级评论和缺少当前行号的旧评论保留原样，不推测本地工作区中的位置。尚未发布的待提交评论会标明状态。

点击“同步讨论到审查收件箱”保存当前获取的快照。本地初始处理状态为待复核；之后按工作区、PR 和讨论 ID 更新，重复同步不新增副本。远端回复、编辑、位置、解决状态或 PR HEAD 变化会提示复核，保留用户设置的本地状态。多个面板按请求开始时间判定新旧，晚返回的旧请求不覆盖较新快照。获取结果中缺失的旧讨论不会自动删除；再次刷新并同步才能更新。收件箱支持附到原工作区草稿、改变本地状态及移除本地副本，这些动作不发布评论或修改 GitHub。

每次最多获取 8 页、每页 25 条讨论；每条保留首条评论和最新 20 条评论，省略内容会提示到 GitHub 查看。面板展示首条和最近两条评论及 Diff 的节选，附到草稿包含全部已捕获评论及原始 Diff。单条评论正文和 Diff 各限 64 KiB，分页响应合计限 8 MiB，单次附加内容限 128 KiB；超限拒绝该次操作。请求中的 PR URL 与 HEAD 每页都需匹配，接口错误或中途变化时不提供可同步的部分结果，PR 检查和会话评论仍可单独显示。本地最多保存 500 条讨论、16 MiB；超限整批不保存。异步保存错误在 PR 面板和收件箱展示。

实现依据 GitHub 官方 GraphQL schema 的 `PullRequestReviewThread` 与 `PullRequestReviewComment` 字段，使用 `gh api graphql` 的查询操作。已核对 2026-11-10 下载的官方 schema（`https://docs.github.com/public/fpt/schema.docs.graphql`）；本机缺少 `gh.exe`，尚未完成真实账户联调。

## 检查点和产物

检查点位于应用数据目录的 `file-checkpoints`，只覆盖用户选定的单个 UTF-8 文本文件。恢复必须先预览当前及保存内容，确认后再次核对精确内容；文件发生外部修改时拒绝覆盖。写入已有文件前同步保存恢复副本。拒绝目录穿越、Git 元数据、重解析点及二进制文件；存在多个硬链接时拒绝恢复，避免影响其他路径。不修改 Git 索引、不恢复未选文件或外部副作用；恢复已删除文件不会创建缺失的父目录。

产物支持项目内 HTML、PDF、常见图片、SVG、TXT、Markdown、JSON、CSV 以及 HTTP(S) URL。链接以默认应用打开，读取时重新校验路径和类型。

## 环境及验收边界

WSL/SSH 入口使用系统 `wsl.exe` / `ssh.exe`。凭据和主机身份确认由客户端处理，不进入应用配置。关闭终端结束本地连接，不保证远端脱离终端的进程退出。此入口不改变文件树、Git 或聊天引擎的本地目标，完整远程工作区尚未完成。

原生命令详见 [Chat 命令](chat-commands.md)：增加 Codex `/compact`、`/review` RPC；Claude/Qoder 原生命令尚未适配。GitHub 本机缺少 `gh.exe`，仅完成解析与边界测试，没有真实账户联调。当前 Windows 窗口控制通道不可用；模拟 UI 测试不等同于实机视觉验收。真实 WSL/SSH 连接和付费模型调用不在已通过的验证范围。

已使用隔离 `CODEX_HOME` 与本地模拟 Responses 服务验证本机 Codex CLI 0.167.0：两轮源会话按第一轮分支后只返回第一轮，创建分支的模型请求数为零。保存失败、配置与 CLI 变化、取消、重试及完成事件隔离有离线回归测试。此验证未使用在线模型或用户已有原生会话。

未完成范围还包括：完整远端文件/Git/CLI 路径映射、其他引擎的原生会话分支、多文件事务检查点、向 PR 发布评论与处理状态写回，以及项目级 Skills/MCP 预设组合。
