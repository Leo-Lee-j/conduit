# 项目工具

入口按使用场景分布：

- 右侧竖向图标栏：统一提供项目工作流（含任务、模板、交接与分支）、自动任务、工具详情和插件面板入口，底部铃铛打开通知中心并显示未读角标。所有入口仅显示图标，悬停可查看名称；点击展开对应侧栏，再次点击或使用关闭按钮可收起。侧栏顶部为标题和操作区，通过竖向图标切换内容。宽窗口可拖动侧栏边缘调整宽度，窄窗口使用侧边浮层。表单草稿在本次运行中按工作区保留。
- 提交侧栏顶部：左侧为“提交”和“PR”两个 Tab（GitLab 显示“MR”），下方独立一行为工作区选择和刷新操作，并用横线与内容区分隔。请求列表显示仓库最近 100 条请求，支持搜索标题、编号、作者和分支，并按状态、作者、负责人、审查人和标签筛选；标题与状态在第一行，编号、创建日期、作者、参与人缩写和评论数在第二行。点击请求在主区打开检查与讨论。切换 Tab 保留提交草稿、文件勾选及各工作区的筛选和滚动位置。审查意见保留在“提交”Tab。
- 左侧文件面板右上角：文件检查点与产物图标按钮（悬停可查看名称）。
- 底部工具栏的「WSL / SSH」：管理当前项目的终端连接；已打开的终端标题栏也保留连接入口。终端按钮旁的重复下拉菜单已移除。
- 左侧导航底部的统计图标：用量与预算。

未选择工作区时，相关入口禁用。原“项目工具”混合菜单已移除。本批次不提供项目运行配置、命令管理器、构建测试执行器或运行日志系统。

| --- | --- | --- |

| 上下文交接 | 按消息边界生成可编辑 Markdown，复制或创建另一引擎的新会话草稿 | 只转移可见用户/助手正文；不复制隐藏状态；128 KiB 上限及省略提示 |
| Codex 原生分支 | 从已记录的完成轮次建立独立原生会话，保留截至该轮的上下文和本地历史 | 创建不发送模型提示词、不恢复文件；旧导入历史没有可靠轮次映射时使用上下文交接 |
| 代码和终端上下文 | 按行号捕获代码及来源指纹；把终端选中内容附到草稿 | 不自动发送，终端片段不代表完整日志或验证结果 |
| 审查反馈 | 行级意见、版本指纹、处理状态、已查看、历史收件箱、只读 AI 审查草稿及结构化发现导入 | AI 发现默认待复核；PR 讨论保留独立的远端位置；详见 [Git 工作流](git.md) |
| GitHub PR/CI | 当前分支 PR、检查、会话评论、行级讨论及本地同步、失败检查转修复任务、打开链接、附到草稿；新增 PR 评论、讨论回复和解决操作 | 写回代码待编译与真实账号验收；使用已有 gh 认证；远端状态与本地处理状态独立；无 job 日志 |
| 自建 GitLab MR/CI | 当前分支 MR、流水线和作业状态、评论、审查讨论及本地同步、修复任务；发表评论、回复与解决可解决讨论 | 使用已有 glab 认证；不创建或合并 MR、不运行流水线、不取作业日志；真实账号联调待完成 |
| 用量和预算 | 按本地月份、日期、引擎、服务汇总已知 token 与速度，月度 token 提醒 | 未知、部分、历史覆盖单独标记；不估算金额、不硬停止 |
| 自动任务 | 模板驱动的小时间隔或人工会话成功结束事件；暂停恢复、编辑删除、运行记录 | 应用须运行；强制只读；不补跑、不重叠、不连锁触发 |
| 文件检查点 | 手动保存一个文本文件，预览后恢复，自动保留恢复前副本 | UTF-8、1 MiB、最多 200 条；不恢复整个项目或 Git 索引 |
| 产物收藏 | 保存报告、图片、文档路径或 HTTP(S) 服务地址，用默认应用打开 | 不启动服务；无内嵌浏览器；移除收藏不删除文件 |
| WSL/SSH | 按项目新增、编辑和移除连接，检测 WSL 发行版，配置 SSH 主机/端口与起始目录，连接及重连交互终端 | 文件树、Git 和聊天仍是本地工作区；完整远程路径与进程管理尚未实现 |

## 任务和上下文

“创建任务 worktree”需要先刷新 Git 分支面板。用户确认目标目录和分支，成功后在新工作区复制任务目标与验收项，清空会话关联和验收结果，记录来源工作区。创建不自动合并、提交或推送。清理要求所有相关任务已归档且会话、终端已结束，使用不带 force 的 `git worktree remove`；任务记录和分支仍保留。

模板、交接、代码片段和审查操作只准备或追加草稿，保留原会话草稿。助手消息的“从此处分支”打开交接预览。代码片段输入 `1-20` 或单个行号，留空时取全文；记录路径、行范围及捕获时的全文指纹。代码和终端片段各最多 64 KiB，交接最多 128 KiB。

打开“右侧任务图标 → 交接与分支”，选择已完成轮次，再点击“创建原生分支”，可建立独立 Codex 会话。应用只记录实际收到且与当前线程、轮次匹配的成功完成事件，最多保留最近 256 个分支点；不会从消息数量推测原生轮次。复制本地历史前核对内容指纹，单次历史内容上限 16 MiB。源会话和草稿保留，新会话沿用引擎、服务、模型、力度与权限。

创建先保存本地记录，再调用 `thread/fork`，要求返回独立线程 ID 且最后一轮正好是所选轮次。创建期间不能向待绑定会话发送或排队消息；保存失败、配置变化或 CLI 不支持时保留可重试的本地分支。CLI 返回不匹配时不绑定、不回退为新提示词；此时 CLI 侧可能已经生成一个线程，界面会提示检查版本后重试。创建过程不启动继承目标的自动续跑，也不触发完成自动任务、排队发送、自动命名或新增用量记录。分支的首个后续轮次若缺少可靠累计用量基线，统计标为不完整，不重复计入源会话消耗。

原生分支不会回退工作区文件或 Git 状态。Claude、OpenCode、Qoder 以及缺少已记录完成轮次的旧会话仍可使用可编辑上下文交接。

## 用量和自动任务

用量仅记录功能启用后实际观测到的轮次，不把导入历史的最后计数当成本月账单。Codex 采用累计计数的有效差值；其他引擎采用报告的轮次值。最多 10,000 条，淘汰历史后显示覆盖不完整。预算按项目和本地月份提醒，每月一次。

自动任务由用户从模板显式启用，界面说明模型调用会产生用量。先保存触发记录，再创建后台会话并通过既有发送保存门控启动，不切换前台会话或覆盖草稿。间隔为 1 小时至 366 天，错过超过 60 秒记录“错过”；重启时未结束的记录标为“中断”，不补跑。每项不重叠，事件触发最多每分钟一次，自动任务不会触发其他自动任务。最多 50 项调度、1000 条运行记录。

编辑或删除规则前须暂停后续触发并等待当前执行结束。编辑可以保留已保存的模板副本，也可以选择当前项目的另一模板；保存后仍处于暂停状态，恢复时从当前时间计算下一次触发。删除须再次确认，仅移除规则，保留执行记录和结果会话；历史记录仍按原项目显示。

## PR 审查同步

PR 与 CI 使用工作区标签页，可与会话、代码和 Diff 来回切换。重复打开同一工作区复用页面，保留当前页签、展开的讨论和各列表的滚动位置；关闭页面释放查询资源，关闭后返回所属工作区的会话。切换工作区不会覆盖其他工作区的草稿。页面展示获取时的分支、提交和更新时间，点击“刷新”重新查询当前分支。

页面先展示 PR 与分支信息、CI 检查汇总和已加载讨论中的未解决数量，再进入检查、审查讨论、会话评论。失败检查与未解决讨论优先排列；进行中、跳过、取消和未知状态不会计作通过。检查的主要处理入口是创建或查看修复任务；“附到 AI 草稿”保留原草稿并返回聊天，不自动发送。发表评论位于会话评论页，打开 GitHub 和刷新为页面公共操作。

失败检查旁的“创建修复任务”保存 PR 链接、PR 提交、当时的本地 HEAD、分支、检查名称、状态、详情链接和快照时间，并打开对应任务。任务初始为计划状态，包含排查原因、处理问题、核对版本和 CI 结果三项未勾选的验收要求。通过任务的“准备会话”选择引擎后，可继续编辑草稿并自行发送；创建任务本身不会调用模型、启动检查或改写其他工作区的草稿。

相同工作区、PR 链接、提交、检查名称和详情链接对应同一任务；再次操作显示“查看修复任务”，保留编辑过的目标、会话、验收和归档状态，重启后仍能识别。不同提交或检查链接会生成独立任务。缺少链接且同名的检查共用一项任务。CI 后续通过不会自动完成任务或勾选验收；快照不含作业日志，也不证明当前未提交文件已经验证。

只有明确返回失败、错误、超时、启动失败或需要操作的检查可创建任务。运行中、取消、跳过、成功和未知状态不推断为失败；已有任务仍可查看。刷新期间、工作区已移除、过期按钮和不可写状态会阻止新建，保存错误沿用任务面板提示。

打开提交侧栏的“PR”Tab，选择请求并进入详情。在“审查讨论”中查看文件、左右侧、当前和原始行号、GitHub 已解决及位置过期状态、首条评论对应提交与 Diff 片段。文件级评论和缺少当前行号的旧评论保留原样，不推测本地工作区中的位置。尚未发布的待提交评论会标明状态。

点击“同步讨论到审查收件箱”保存当前获取的快照。本地初始处理状态为待复核；之后按工作区、PR 和讨论 ID 更新，重复同步不新增副本。远端回复、编辑、位置、解决状态或 PR HEAD 变化会提示复核，保留用户设置的本地状态。多个面板按请求开始时间判定新旧，晚返回的旧请求不覆盖较新快照。获取结果中缺失的旧讨论不会自动删除；再次刷新并同步才能更新。收件箱支持附到原工作区草稿、改变本地状态及移除本地副本，这些动作不发布评论或修改 GitHub。

每次最多获取 8 页、每页 25 条讨论；每条保留首条评论和最新 20 条评论，省略内容会提示到 GitHub 查看。面板展示首条和最近两条评论及 Diff 的节选，附到草稿包含全部已捕获评论及原始 Diff。单条评论正文和 Diff 各限 64 KiB，分页响应合计限 8 MiB，单次附加内容限 128 KiB；超限拒绝该次操作。请求中的 PR URL 与 HEAD 每页都需匹配，接口错误或中途变化时不提供可同步的部分结果，PR 检查和会话评论仍可单独显示。本地最多保存 500 条讨论、16 MiB；超限整批不保存。异步保存错误在 PR 面板和收件箱展示。

实现依据 GitHub 官方 GraphQL schema 的 `PullRequestReviewThread` 与 `PullRequestReviewComment` 字段，使用 `gh api graphql` 的查询操作。已核对 2026-11-10 下载的官方 schema（`https://docs.github.com/public/fpt/schema.docs.graphql`）；本机缺少 `gh.exe`，尚未完成真实账户联调。

## 自建 GitLab

在本机安装 GitLab CLI，确保 `glab.exe` 在 PATH 中，然后自行登录实例：

```powershell
glab auth login --hostname gitlab.example.com
```

打开提交侧栏的 PR / MR Tab，在列表底部的平台菜单中选择 **GitLab**；请求详情顶部也保留平台菜单。选择保存到仓库的本地 Git 配置 `conduit.forge`，刷新和重启后仍然有效；可切回 GitHub 或自动识别。域名含独立 `gitlab` 段（例如 `gitlab.company.com`）时自动识别为 GitLab，其他域名保持 GitHub 默认行为，避免误判 GitHub Enterprise。

按当前分支的 `pushRemote`、`remote.pushDefault`、分支 remote、`origin`、唯一 remote 的顺序确定项目。支持 HTTPS/HTTP、SCP 风格 SSH 与 `ssh://` 地址、多级群组、Web 端口。SSH 端口不会当成 API 端口；SSH 主机别名、API 主机或端口不同、HTTP API 等情况，请先在 `glab auth login` 中配置 `--api-host`、`--api-protocol` 等实例选项。项目内保存平台选择，不保存令牌。当前不支持 GitLab 安装在 URL 子路径的实例。

按当前项目 ID 与本地分支查找 MR，优先显示唯一开放 MR，否则显示最近更新的匹配记录；多个开放 MR 不会任意选取。Fork 项目没有匹配记录时查询其上游项目。查询前后复核本地分支、HEAD、remote 与 MR 版本，讨论保留原提交和行号；旧提交的讨论标记过期，不推测本地位置。流水线标题包含其实际提交摘要，兼容合并结果流水线的临时提交。

读取最多 200 项检查、最近 100 条 notes、8 页共 200 条 discussions；讨论保留首条和最新 20 条评论。截断、权限错误和作业加载失败会提示。系统 notes 不显示，普通讨论不支持“解决”；接口未提供 Diff 片段时留空。发送前重新获取并核对 MR、分支与讨论；超时或取消后结果可能未知，不自动重发。初次连接与刷新只读取远端数据，写回必须由用户在表单中发送。

## 检查点和产物

检查点位于应用数据目录的 `file-checkpoints`，只覆盖用户选定的单个 UTF-8 文本文件。恢复必须先预览当前及保存内容，确认后再次核对精确内容；文件发生外部修改时拒绝覆盖。写入已有文件前同步保存恢复副本。拒绝目录穿越、Git 元数据、重解析点及二进制文件；存在多个硬链接时拒绝恢复，避免影响其他路径。不修改 Git 索引、不恢复未选文件或外部副作用；恢复已删除文件不会创建缺失的父目录。

产物支持项目内 HTML、PDF、常见图片、SVG、TXT、Markdown、JSON、CSV 以及 HTTP(S) URL。链接以默认应用打开，读取时重新校验路径和类型。

## 环境及验收边界

WSL/SSH 连接页先列出已保存的连接，展示类型、目标与起始目录。新增时分别选择 WSL 或 SSH；表单有固定的「保存并连接」「仅保存」操作，短窗口内只滚动内容。名称可留空，默认使用发行版或主机名称；目录留空或 `~` 时进入用户主目录，也可填写 Linux 绝对路径。WSL 检测只列举已安装发行版，不启动发行版，失败可手动输入并重试。SSH 支持 `user@host`、配置别名和 IPv6，端口留空沿用系统配置或默认值，也可单独覆盖。

编辑保留连接 ID；只读、更新期间和切换到其他项目后不能保存或连接。未保存表单离开前确认；移除配置需再次确认，不会删除文件或关闭运行中的终端。启动失败保留当前配置页和错误原因；终端退出后可「重新连接」。本地 SSH 进程运行不表示远端已经认证成功，应查看终端输出完成密码或主机身份确认。

WSL/SSH 入口使用系统 `wsl.exe` / `ssh.exe`。凭据和主机身份确认由客户端处理，不进入应用配置。关闭终端结束本地连接，不保证远端脱离终端的进程退出。此入口不改变文件树、Git 或聊天引擎的本地目标，完整远程工作区尚未完成。

原生命令详见 [Chat 命令](chat-commands.md)：增加 Codex `/compact`、`/review` RPC；Claude/Qoder 原生命令尚未适配。GitHub 本机缺少 `gh.exe`，仅完成解析与边界测试，没有真实账户联调。当前 Windows 窗口控制通道不可用；模拟 UI 测试不等同于实机视觉验收。真实 WSL/SSH 连接和付费模型调用不在已通过的验证范围。

已使用隔离 `CODEX_HOME` 与本地模拟 Responses 服务验证本机 Codex CLI 0.167.0：两轮源会话按第一轮分支后只返回第一轮，创建分支的模型请求数为零。保存失败、配置与 CLI 变化、取消、重试及完成事件隔离有离线回归测试。此验证未使用在线模型或用户已有原生会话。

未完成范围还包括：完整远端文件/Git/CLI 路径映射、其他引擎的原生会话分支、多文件事务检查点、PR 创建/合并与 CI 作业日志，以及项目级 Skills/MCP 预设组合。PR 评论、讨论回复及解决操作已有代码，尚未完成下述验证。

## GitHub 写回（真实账号待验收）

PR 标签页中“PR 评论”下的“发布 PR 评论”，以及讨论中的“回复到 GitHub”“在 GitHub 标记解决”，均先打开独立确认表单，显示目标 PR 和讨论证据；点击确认后才发送。评论限制为 8 KiB。同步到收件箱、改变本地处理状态和附到草稿仍只修改本地数据。

发送前重新查询当前分支 PR，核对 URL、编号、远端 HEAD、本地 HEAD、分支和开放状态。讨论回复/解决还需核对保存的讨论内容、位置和状态；变化时拒绝发送并要求刷新。复核结束后再次检查工作区是否仍存在、应用是否可写。GitHub Enterprise 请求采用 PR URL 中的主机。预检与 GitHub 写入不是服务端原子事务，无法保证这两个请求间远端不会发生变化。

请求只发送一次；超时、取消、网络失败或响应不完整时，不声称写入失败且没有副作用。表单保留正文并禁止直接重发，支持复制草稿和打开 PR 核对远端结果。明确成功后刷新 PR 面板，不自动修改收件箱的本地处理状态。发送期间禁止关闭表单；未发送的草稿关闭前需要明确丢弃。应用退出时取消尚在进行的工作，已经到达服务器的写入不能撤回。

界面按 CI 检查、审查讨论、PR 评论分为三个页签，保留 PR 概览与刷新入口；刷新期间保留旧快照并禁用写入。讨论默认显示摘要，可展开原始评论与 Diff，附到草稿、回复、解决操作同组排列。写入表单区分评论、回复与解决，显示目标、上下文、8 KiB 字节计数、明确的发送状态与底部操作区。界面调整仍待原生窗口视觉验收。

离线回归覆盖了预检、响应校验、禁止重复发送、工作区标签页切换、草稿保留和窄窗口布局。真实 GitHub 账号联调及原生窗口视觉验收仍未完成；离线测试不能代替这些验收。
