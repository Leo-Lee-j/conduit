# CLI 与模型服务设置重设计

## 现状评估

原界面将一次配置任务拆成「CLI」「模型与服务」两页。CLI 页同时展开三个引擎，重复展示路径、状态和操作；模型页同时展开所有服务、来源文件和三个引擎的完整目录。用户必须先理解配置存储结构，再在长页面中寻找操作。服务的引擎、模型数量、URL 和来源被塞进一行小字，长 URL 会挤掉其他信息；CCS 服务显示无法使用的编辑、删除按钮，却把原因藏在悬浮提示中。

## 新方案

合并为「CLI & 模型服务」。先选择 Claude Code / Codex / OpenCode，再在「CLI 配置」「模型服务」间切换。保留设置弹窗原有的固定标题、导航、搜索、关闭与保存提示。

- CLI 配置：仅展示所选引擎。启动路径、实际使用的 CLI、检测按钮与结果集中在一张卡片里。「选择文件」「恢复自动查找」说明具体动作。路径查找规则按需展开。
- 模型服务：仅展示所选引擎的服务。同步与添加在列表顶部；每个服务独立显示名称、配置来源、端点、模型数量和使用状态。CCS 服务直接提示在 cc-switch 中编辑；自定义服务提供编辑与删除。添加时预选当前引擎。
- 默认模型：先显示当前默认模型与目录数量，点击「查看模型目录」才展示配置文件和完整列表。错误仍直接显示，避免被折叠隐藏。
- 配置来源：默认收起；有读取错误时直接提示。同步按钮显示进行中状态并阻止重复点击。
- OpenCode：使用原生模型目录和刷新入口，遵循其 CLI 配置方式。

沿用现有浅色 / 深色主题、按钮、页签和品牌图标，不新增颜色体系。引擎选择按钮高度为 44px，选中项使用蓝色边框与文字；信息使用 12–13px 正文分行呈现。服务使用紧凑行与分隔线，避免重复的嵌套卡片；长端点可通过悬浮查看完整值。保留只读模式和检测取消行为。页面选择状态只存在内存，不改变聊天所选引擎或默认服务。

## 取舍与验证

相比三列总览，这种结构在设置弹窗和窄窗口中保留可读宽度；查看另一个引擎需要一次切换。模型目录仍为只读，模型的实际使用在聊天面板中选择。

设置相关的 3 项测试通过，覆盖 850 × 500 和 1280 × 900 的引擎按钮布局、引擎与页签切换、OpenCode 入口、只读模式，以及原有关闭设置交互。`cargo build --locked`、本次修改文件的格式检查和 `git diff --check` 通过。

截图保存在 `target/ui-acceptance/out/settings-redesign-*.png`，使用隔离的应用数据。视觉检查覆盖深色桌面布局与浅色窄窗口；窄窗口中的内容继续在固定导航、标题与保存提示之间滚动。

全量测试执行到已有的 `models::opencode::tests::native_cache_survives_restart_expires_daily_and_manual_refresh_bypasses_it` 时长时间无进展，已终止该轮，因此不宣称全量通过。全仓库 `cargo fmt --check` 在其他模块的现有改动中失败；严格 Clippy 检查在其他模块报告现有问题，本次设置修改未新增 Clippy 报错。
