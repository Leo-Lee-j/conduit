# 通知中心

通知中心统一承接操作结果、错误、待处理请求和后台进度，右侧历史面板提供回看与来源导航。消息是否进入历史、是否弹 Toast、是否需要持续显示，由事件策略决定。

## 投递与界面

- 成功、失败及校验错误可通过 Toast 即时提示，并保留历史。重复业务事件按稳定身份更新，不反复新增相同提醒。
- 高频正常进度只写历史；持续阻塞状态在相关界面保留必要提示，不能仅靠短暂 Toast 表达。
- 铃铛与未读计数打开右侧通知视图，可筛选、查看来源、标读和清理历史。打开历史本身不意味着所有事项已经处理。
- 后台通知不自动抢焦点。用户选择“查看”后才导航到原工作区、会话或设置；目标已删除时明确说明。
- 错误文本可以展开或复制，敏感凭据和未经整理的完整命令输出不能直接进入历史。

Git 提交、分支及说明生成使用统一入口：结果和校验错误即使面板打开也走 Toast，普通进度仅入历史；移除提交区与分支面板底部重复消息，保留必要的标签重试按钮。

## 审批与问答

权限审批通知可以提供“允许本次 / 拒绝”，问题回答通知只提供导航。绑定包含会话、运行实例与具体票据，绘制和点击时都重新检查；恢复历史不能恢复可执行授权。

提交后立即禁用重复操作并显示提交中，收到 `ApprovalResolved` 后更新原通知结果。它表示审批决定被运行时处理，不表示工具已执行完成。聊天内和通知内操作共享同一票据入口，后台审批保留当前会话、草稿及焦点。

请求撤销、取消、运行结束、目标删除、切换运行身份和关闭都会使动作失效。旧回调或断开的控制通道不能伪造成功，待处理请求不能因普通“清除已读”丢失。

## 持久化与恢复

历史独立写入数据目录的 `notifications.json`，继承 `CONDUIT_DATA_DIR`，通过后台原子替换保存，容量有界（最多 200 条）。历史不是永久审计日志；活动故障和待审批状态仍由业务状态维护。

恢复只加载历史和显示结果，不重放 Toast、授权或命令。文件损坏、不支持的版本或写入冲突保留原数据，退到内存历史并提供诊断；只读模式不落盘。通知写入失败不能再发布一条导致写入的错误通知，避免递归。

通知保存不作为聊天发送或更新安装成功的必要条件。退出对通知收尾有期限，崩溃可能丢失尚未确认的少量历史。
