# Git 界面设计

本轮采用 IDEA 的工具窗口思路，让聊天仍是主界面。现有 Git 命令执行、后台探测、超时和文件状态分类可以复用；提交历史需要新增日志查询与按提交读取变更，当前未实现。

## 本轮已实现

- 对话内容区底栏位于输入框下方，不延伸至工作区列表或右侧停靠区。右侧 Git 图标打开独立右侧 Git 变更栏，再次点击或点击关闭按钮收起。
- 会话标题旁的侧栏图标与工具卡片只打开工具详情。工具详情与 Git 变更按入口切换停靠内容，不再使用共用页签或 split。
- Git 侧栏复用可拖宽停靠区，最大为聊天可用宽度的一半；窄窗时覆盖显示。底栏位于对话列内；宽窗侧栏打开后入口随对话列宽度调整，窄窗覆盖层不遮挡底栏。
- 底栏左侧显示工作区当前分支，向上展开本地/远程分支列表，标记当前分支。保持只读，不 checkout，也不 fetch；远程分支是本地已有的远程引用。
- 非 Git 工作区隐藏分支下拉；没有提交时显示实际分支名；分离 HEAD 显示短 hash。启动、工作区切换、任务结束及手动刷新时读取分支，每 10 秒同步外部 Git 操作。
- 切换工作区立即清空旧数据并取消旧探测。分支探测独立于变更状态读取，关闭侧栏后不再读取 Git 状态。
- Git 侧栏上下分区：上方独立滚动查看按新增/修改/删除分组的变更列表（支持折叠，列表不内联 diff；双击文件打开只读 diff 弹窗），下方固定 Commit Message 输入框。右上角 Sparkles 图标使用当前引擎/模型生成说明，输入区右下角提供 Commit 主按钮和 Commit / Commit and Push 下拉。
- 底栏 Git 图标右侧按需显示待推送图标及提交数 badge；点击向当前上游推送，成功后刷新计数。

## 文件 Diff 窗口（2026-10-25）

参考 IDEA 的 Changes 工具窗口与独立 Diff 查看器：文件列表只保留状态，逐行内容在用户明确双击后打开，避免列表被 diff 撑长。

- **打开方式**：双击 Git 侧栏任一文件行，在当前窗口中央打开只读 diff 弹窗；单击仍用于选择/滚动。弹窗沿用 Dialog 的遮罩、Esc 关闭与居中定位，尺寸按视口计算并限制上下限。
- **基线**：固定为 `HEAD → 工作区`，同时覆盖暂存与未暂存修改。未跟踪文件和无 HEAD 的新增文件按“空（新增前）→ 工作区”展示；删除文件展示“HEAD → 已删除”。版本栏明确标注两端，避免把 diff 误解为仅工作区或仅暂存内容。
- **头部与工具栏**：头部显示路径、增删改状态、`+/-` 行数、只读标记和版本栏；二进制文件额外显示“二进制”标签且不显示行数。工具栏提供并排/统一视图、上一处/下一处差异、展开/折叠未变更、重新读取和关闭。并排模式下内容上方显示左右版本列头（如 `HEAD` / `工作区（含暂存）`），新增或删除文件另一侧为空时也能确认双栏已生效；切到统一后列头隐藏。并排两列各占视口一半并对超长行软换行，否则长行会把右列推出可视区（库不支持两列独立横向滚动）；统一视图保持不换行并沿用横向滚动条。
- **视图与快捷键**：默认并排视图，可切换统一视图；F7 / Shift+F7 与工具栏按钮等价，越过末尾后回绕；Esc 关闭。文件行、模式按钮、差异跳转与刷新都带可访问名称。
- **上下文与折叠**：读取补丁时使用 `--unified=1000000` 输出完整文件上下文，让“展开未变更”能显示补丁 hunk 之外的行；展开/折叠复用 gpui-kit Diff 的未变更行能力。
- **状态**：读取中显示加载；失败显示原因和“重新读取”；空差异与二进制文件分别显示专门占位，不把 `index ...`、`Binary files ...` 等原始补丁头当作正文。单文件补丁最多 4 MiB，读取到上限立即终止 Git 进程并提示，不继续消费剩余输出。
- **只读与取消**：异步读取在后台线程执行；关闭、刷新或重新打开会取消旧请求，迟到结果按工作区/文件隔离并丢弃。弹窗不提供编辑、暂存或冲突合并，也不写入仓库。

## History 推荐方案（待实现）

从底栏增加独立“历史”入口，打开位于底栏上方的可拖高面板，初始高度约 280px，限制在内容高度的 35%–55%。聊天保留在上半区；小高度窗口改为较大的独立历史浮层。

横向布局建议如下：

| 提交列表（约 65%） | 选中提交详情（约 35%） |
| --- | --- |
| 图线 · 分支标签 · 提交说明 · 作者 · 相对时间 | 完整提交说明、作者、时间、短 hash |
| 单击切换所选提交，当前提交有明确标记 | 文件列表及新增/删除统计 |

底栏分支下拉继续承担分支定位，历史首版不额外常驻一列分支树。顶行提供当前分支/所有本地引用范围与提交搜索。首次只加载约 100 条提交，向下继续加载；空仓库显示“尚无提交”，查询错误提供重试。

点击历史文件后，Git 专属右侧栏显示该提交相对父提交的 diff，顶部明确标注“提交 a1b2c3d”并提供“返回工作区变更”，避免把历史版本误认为当前未提交修改。History 的右侧摘要保持在底部面板内部，不随工具详情入口变化。

这样可形成“上方对话、下方追溯、右侧核对”的工作流。首版先做提交列表、完整说明、文件列表和单文件 diff；多分支彩色拓扑图放在后续，否则容易把主要成本花在图线布局上。

实现时补充受管只读 `git log`、`show`/`diff-tree` 查询，使用固定字段分隔、输出上限、后台线程与取消机制；按工作区、提交 hash 和文件路径校验异步结果。合并提交需明确显示与第一父提交的比较，根提交使用空树比较。

## 提交和 AI 生成

Commit 只提交 Git 已暂存区，不自动 add，也不包含未跟踪或未暂存内容。提交说明草稿按工作区保留在内存，切换工作区不会覆盖；提交成功后清空对应草稿。执行前重新核对分支、HEAD 和暂存对象；预览已变化时要求刷新重试。CLI 任务运行期间禁用 Git 写操作；Git 操作运行期间阻止启动新聊天任务。

Commit and Push 先提交，再向配置的 upstream 推送；使用明确的远程和目标分支，不 force、不推送其他分支。没有有效 upstream 时提示先配置；若提交成功但推送失败，清空已使用的提交说明，明确显示“提交已成功，推送失败”并保留待推送入口，下一次可直接 push。普通 commit/push 允许 120 秒（含 hooks/签名/网络等待），失败后刷新状态，不自动重试。

badge 有 upstream 时统计 upstream..HEAD 的提交数；没有 upstream 时统计 HEAD 中尚未被本地远程引用覆盖的提交数，并在 tooltip 说明“尚未设置上游”。不 fetch，故计数基于本地记录；外部 Git 操作由定期探测更新。

设置 → Git 提供多行 Commit Message 提示词，自动保存至 `state.json` 的 `git.commit_message_prompt`，全工作区通用；支持恢复默认、留空回退默认，下次生成时生效。旧配置缺少 Git 设置时自动使用默认提示词。

AI 生成传入设置中的提示词、已暂存文件名与预览 diff（最多 200 KiB）。使用当前会话的引擎和模型，未选会话时使用当前默认引擎；结果填入提交说明后仍可编辑。生成使用独立临时 CLI 会话，不续接聊天、不写入聊天历史；Codex 使用 ephemeral/read-only/never，禁用 shell、hooks；Claude 禁用工具、MCP、hooks 和会话持久化。超时、取消、工具请求和空结果显示错误，不替换已有草稿；流式增量由完整快照替换，避免重复。当前草稿和 AI 草稿都只在内存中保留，重启不恢复。

## 侧栏视觉统一（2026-10-25）

Git 侧栏原有 9–11px 字号、整行状态色文件名与独立标签，和左侧工作区列表、聊天输入框的 12/13px 层级差异明显。本轮只调整 `src/app.rs` 的 `git_panel` 与 `commit_editor`，不改变数据流、异步探测、双击 diff 和提交逻辑。

**列表与分组**

- 头部：分支图标 + 12px semibold 分支名 + 右侧 RefreshCw 图标按钮（tooltip/可访问名“刷新 Git 状态”），替换原文字“刷新”。统计行降为 11px muted，`暂存 N · 未暂存 N · 未跟踪 N`，工作区干净时隐藏。
- 分组：高 28px、12px semibold 彩色标题、6px 状态圆点、10px 计数、Chevron 折叠；去掉左侧引导线。文件名统一 13px `text`，不再整行染色；重命名原路径 10px faint，最多 132px 截断。
- 文件行：高 28px、圆角 6、左内边距 8（配合列表 32px 缩进与分组标题文字对齐），仅悬停时 `surface_hover`；双击打开只读 diff 的交互保持不变。
- 辅助提示：不再显示“双击文件行查看只读差异”等操作提示；仅在快照返回 notes 时以 10px/1.4 行高展示说明（例如未跟踪文件按新增文件展示）。

**空态、加载与错误**

- 干净工作区：居中 CircleCheck(20px) + 12px muted“工作区没有未提交变更” + 10px faint“在终端修改文件后点击右上角刷新”。
- 加载：Spinner + 12px muted 文案，下方 ghost“重新读取”；错误：`danger_bg` 卡片、圆角 10、12px semibold 标题、11px/1.5 原因，右下角“重新读取”。

**提交区**

- 标题 12px semibold，暂存数改为 10px 圆角 pill“已暂存 N”。
- 编辑卡片 `rounded(14)`、`surface` 背景、`p_2`，内层 Textarea 13px、高 96、无边框；Commit 主按钮与模式下拉统一 26px 高。
- 卡片外 helper 与操作反馈统一 11px / 1.4 行高；错误反馈使用 `error_text`。

**验证**

- `cargo fmt`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo build --locked` 通过；`cargo test --locked -- --test-threads=1` 86 passed、0 failed、11 ignored。
