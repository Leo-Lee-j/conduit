# Git 界面设计

采用窄竖向导航 + 左侧工作区 / 文件 / 变更面板，聊天、源文件与工作区 Diff 共用主内容标签。Git 命令执行、后台探测、超时和文件状态分类继续复用；提交历史需要新增日志查询与按提交读取变更，当前未实现。

## 本轮已实现

- 对话内容区底栏位于输入框下方，不延伸至工作区列表或右侧停靠区。底栏右侧 Git 图标或左侧「变更」图标打开左侧变更面板；再次点击底栏 Git 图标返回工作区面板，导航收起按钮可收起整个左侧面板。
- 会话标题旁的侧栏图标与工具卡片只打开右侧工具详情，与左侧 Git 变更相互独立，可同时显示。设置按钮仅保留左侧窄导航栏底部的一处。
- 左侧变更面板可拖宽，范围 280–480px；右侧工具详情保留原有停靠与窄窗覆盖模式。Git 面板的列表与提交区独立滚动，避免窄窗时提交按钮被裁切。
- 底栏显示工作区当前分支，向上展开本地/远程分支列表，标记当前分支。分支右键菜单和行尾操作按钮支持分支管理；展开与刷新只读取本地引用，不自动 fetch。见下方“分支操作”。
- 非 Git 工作区隐藏分支下拉；没有提交时显示实际分支名；分离 HEAD 显示短 hash。启动、工作区切换、任务结束及手动刷新时读取分支，每 10 秒同步外部 Git 操作。
- 切换工作区立即清空旧快照并取消旧探测；已打开的 Diff 按所属工作区保留。分支探测独立于变更状态读取；变更面板或当前 Diff 可见时约每 10 秒刷新，查询或写操作进行中不叠加周期查询；手动刷新期间保留当前快照。
- 左侧变更面板上下分区：上方独立滚动查看变更列表（支持折叠、右键单文件暂存、勾选批量与全部暂存，列表不内联 diff；双击文件打开主内容区只读 Diff 标签），下方为提交编辑器，提交操作固定在底部。Sparkles 图标按设置中的引擎 / Provider / 模型生成说明，默认跟随当前会话；提供 Commit 主按钮和 Commit / Commit and Push 下拉，只提交已暂存内容，不自动 add。
- 底栏 Git 图标右侧按需显示待推送图标及提交数 badge；点击向当前上游推送，成功后刷新计数。

## IDEA 风格提交侧栏（2026-11-02）

采用顶部 Commit 标题与工作区选择器、固定工具栏、独立滚动文件列表、底部提交编辑器的结构，使用现有明暗主题。工具栏提供刷新、全选 / 取消全选、暂存选中、移出暂存区选中、全部暂存、折叠 / 展开及显示选项；图标按钮均有工具提示和可访问名称。

默认按 Changes 与 Unversioned Files 分组，未跟踪组初始折叠。显示菜单保留按新增 / 修改 / 删除分组的原有方式。分组复选框可批量选择整组，含折叠中的文件；显示已选数量。勾选仅用于选择，暂存仍由明确的工具栏或右键操作执行。

文件行优先显示文件名，目录使用次级文字截断；完整路径与 Git 状态可在工具提示中查看。保留文件类型图标、状态颜色与文字码、已暂存 / 部分暂存标记及重命名来源。双击继续打开主内容区只读 Diff，右键单文件与批量操作保持可用。

提交区默认约占侧栏高度的 42%，小窗口保留输入与操作空间。提交说明在输入框内部滚动，长说明不会把底部按钮推出视口。保留 AI 生成 / 取消、Commit 模式下拉、工作区草稿、操作反馈、分支与冲突恢复及待推送入口；提交仍仅包含已暂存内容。

## 提交时创建并推送 Tag（第一阶段）

目标是让用户在现有 Commit 工作流中为刚创建的提交添加 Git tag，并在选择 Commit and Push 时将分支和该 tag 一起推送。该能力服务于仓库发布工作流；tag 是 Git ref，不是提交说明的一部分。版本仍由项目自己的版本文件管理，生成 tag 不会修改源码、Cargo.toml 或自动创建提交。

### 仓库约束

当前 `.github/workflows/release.yml` 由推送 `v*` tag 触发，并要求稳定格式 `vX.Y.Z`，tag 版本必须与 `Cargo.toml` 的 conduit 包版本相等。应用内“生成下一个”只计算候选名称，不更新 Cargo.toml。因此，在实际发布前若当前应用版本与候选 tag 不一致，Commit and Push 应在推送前阻止发布型 tag，并说明需先更新版本号；普通本地 tag 可以根据后续版本策略决定是否允许。Actions 工作流仍是最终校验方，UI 检查不能替代远端验证。

本地标签列表显示当前 Git 仓库可见的 tag，按 SemVer 版本排序；不能解析为版本的标签可在“其他标签”分组中按名称排序。列表仅反映本地已知 refs，包括之前 fetch 获取的远程 tag，不因打开面板或生成候选而自动联网。显式刷新远程标签属于第二阶段。

### 第一阶段：基础版本标签工作流

已实现本地标签读取、版本生成策略、可选标签输入和带标签的原子推送。标签列表展示本地已知引用；选择已有名称后仍需修改为新名称才能提交。推送超时或取消时应核对远端状态。

- **提交区**：在 Commit Message 附近增加可选的 Tag 输入和“生成下一个”按钮。输入支持搜索和选择本地已有 tag 供查看/复制；已存在 tag 不可作为新建目标。标签名为空时行为与现有 Commit 完全相同。
- **生成策略**：设置 → Git 增加 Patch、Minor、Major 三种 SemVer 递增策略，默认 Patch。选取最高的有效稳定 `vMAJOR.MINOR.PATCH`，而不是最新创建时间或字典序；忽略 prerelease/build metadata 和格式不符的标签。示例：Patch `v0.1.9 → v0.1.10`，Minor `v0.1.9 → v0.2.0`，Major `v0.1.9 → v1.0.0`。候选若已存在则继续按同一策略递增，直到找到空闲名称。无有效版本 tag 时从 `v0.1.0` 起步，并允许用户编辑候选。
- **提交行为**：Commit 对新提交创建本地轻量 tag。Commit and Push 推送当前分支及本次指定 tag；不使用 `--tags`，不推送其他本地标签，不 force。若远端不支持原子推送，报告失败，不静默退化为两次可能部分成功的推送。
- **校验**：提交前检查 tag ref 格式、空白、是否已存在，以及分支/HEAD/index 是否仍与预览一致。创建时明确将 tag 指向本次新提交的对象 ID。若目标仓库启用签名/钩子等策略，沿用 Git 自身结果并显示对应阶段错误。
- **配置兼容**：生成策略保存在现有 `GitSettings`，serde 缺省为 Patch，旧配置无需迁移即可读取。策略变更自动持久化并遵从现有只读/关闭状态。
- **部分成功**：提交失败时不创建 tag；提交成功但 tag 创建失败时结果标记为“提交已成功，创建标签失败”，清空已消费的提交说明但保留 tag 输入；提交和本地 tag 成功而推送失败时保留二者、清空提交说明，并清楚标出分支/tag 推送状态及失败原因。不得提示整个操作失败而诱发重复提交。
- **安全推送**：目标 remote 和 branch 继续从当前 upstream 配置解析并显式指定。使用 `git push --atomic` 协商远端支持并在一次请求中 推送 `HEAD:refs/heads/<merge>` 和 `<tag-object>:refs/tags/<tag>`。远端拒绝任一 ref 时两者都不更新。标签名作为单独参数传入并使用安全 ref 校验，不拼接 shell 命令。
- **测试**：使用临时普通仓库与 bare remote 覆盖 SemVer 数值排序、三种递增、无有效版本、重复候选跳号、非法/已存在 tag、tag 指向新 commit、只推送指定 tag、atomic 推送拒绝时远端分支/tag 均不变、提交成功后本地 tag 创建失败及旧 GitSettings 反序列化默认值。UI 回归验证 tag 草稿按工作区隔离、可编辑候选和窄窗口布局。

首阶段不做 annotated/signed tag、自定义前缀/递增表达式、预发布版本递增、远程自动 fetch、历史 tag 删除/改写及失败后自动重试。轻量 tag 足以触发现有 `push.tags: ['v*']` 工作流；若发布政策要求签名或说明，再评估 annotated tag。

### 第二阶段：自定义递增与远程 tag 管理

已实现段与 1–100 的步长设置、远程标签显式查询、列表状态与失败重试。查询只读取当前上游远程的 tag 名，不执行 fetch、不写入本地 refs；远程状态是上次成功查询的快照。

- **自定义递增**：设置增加递增粒度和步长配置，限定为 Major、Minor、Patch 三段中的一个目标段及正整数增量，递增该段并将右侧段归零。例如 Patch `+10`：`v0.1.1 → v0.1.11`；Patch `+1`：`v0.1.1 → v0.1.2`；Minor `+1`：`v0.1.1 → v0.2.0`。不接受任意代码、shell 表达式或不受限格式串。说明“十进位”需对应明确的段和步长，避免把十进制表示、十倍步长与末段递增混为一谈。
- **远程标签刷新**：在标签选择器提供显式刷新，后台使用 `git ls-remote --refs --tags` 查询当前分支上游远程；标识仅本地、本地和远程、仅远程，以及尚未查询的状态。再次点击可取消；网络错误保留旧列表并提供原因/重试。查询结果不写入本地引用，也不自动更新远程跟踪分支。
- **失败恢复**：提交成功且本地标签已创建但原子推送失败时，在反馈区提供仅重试该标签的操作；原子推送失败后应先通过已有 Push 入口推送分支。重试前重新核对 HEAD、本地标签、远程推送地址、upstream 和远程标签；首次提交时若尚未设置上游，可在之后配置上游并推送分支，再重试标签；仅当远程分支包含该提交才允许推送标签，远程同名标签指向其他提交时拒绝。远程已存在同一提交的标签视为成功。重试记录按工作区保存在内存，应用重启后不恢复；不支持多个 push URL。
- **状态展示**：候选列表展示版本、tag 名、来源和本地/远程状态；过滤输入可按子串搜索。标签列表按稳定版本排序、显示前 100 条匹配项并可滚动，输入关键字可继续筛选；直接清空输入可恢复无 tag 的普通提交路径。
- **测试扩展**：覆盖 fetch 成功、远端新增/删除不可见状态的刷新语义、网络失败保留快照、重复/并发刷新取消与迟到结果隔离、远端 tag 冲突、仅 tag 重试，以及自定义段/步长边界与溢出。

第二阶段不实现删除/移动远程 tag、force push、自动删除旧版本 tag 或隐式发布；tag 一旦可能触发 CI/release，应视为不可变版本引用。

验证：真实临时仓库的交互回归通过，覆盖折叠整组选中、暂存与移出暂存、全选切换、提交模式、原有状态分组、Diff 标签及草稿隔离；850×500 下验证长提交说明与长错误提示均不会遮挡提交按钮。修改文件的 rustfmt 与 diff 检查通过。桌面控制原生管道不可用，本轮未取得实际窗口截图。

## 工作区文件 Diff 标签（第二阶段，2026-11-02）

参考 IDEA 的 Changes 工具窗口与独立 Diff 查看器：文件列表只保留状态，逐行内容在用户明确双击后打开，避免列表被 diff 撑长。

- **打开方式**：双击左侧变更面板任一文件行，在主内容区打开只读 Diff 标签；单击仍用于选择/滚动。标签按工作区与仓库相对路径去重，单独限制为 20 个，不占用聊天标签配额；支持和聊天、源文件标签切换，Esc / Ctrl+W 关闭当前 Diff，不关闭窗口。跨工作区激活时恢复对应上下文，草稿、运行任务与未读状态不受影响。
- **基线**：固定为 `HEAD → 工作区`，同时覆盖暂存与未暂存修改。未跟踪文件和无 HEAD 的新增文件按“空（新增前）→ 工作区”展示；删除文件展示“HEAD → 已删除”。版本栏明确标注两端，避免把 diff 误解为仅工作区或仅暂存内容。
- **头部与工具栏**：头部显示路径、增删改状态、`+/-` 行数、只读标记和版本栏；二进制文件额外显示“二进制”标签且不显示行数。工具栏提供并排/统一视图、上一处/下一处差异、展开/折叠未变更、重新读取；关闭入口位于主区标签上。并排模式下内容上方显示左右版本列头（如 `HEAD` / `工作区（含暂存）`），新增或删除文件另一侧为空时也能确认双栏已生效；切到统一后列头隐藏。并排两列各占视口一半并对超长行软换行，否则长行会把右列推出可视区（库不支持两列独立横向滚动）；统一视图保持不换行并沿用横向滚动条。
- **视图与快捷键**：默认并排视图，可切换统一视图；F7 / Shift+F7 与工具栏按钮等价，越过末尾后回绕；Esc 关闭。文件行、模式按钮、差异跳转与刷新都带可访问名称。
- **上下文与折叠**：读取补丁时使用 `--unified=1000000` 输出完整文件上下文，让“展开未变更”能显示补丁 hunk 之外的行；展开/折叠复用 gpui-kit Diff 的未变更行能力。
- **状态**：读取中显示加载；失败显示原因和“重新读取”；空差异与二进制文件分别显示专门占位，不把 `index ...`、`Binary files ...` 等原始补丁头当作正文。单文件补丁最多 4 MiB，读取到上限立即终止 Git 进程并提示，不继续消费剩余输出。
- **只读与取消**：异步读取在后台线程执行；关闭、刷新或重新打开会取消旧请求，迟到结果按工作区/文件隔离并丢弃。Diff 标签不提供编辑、暂存或冲突合并，也不写入仓库。嵌入视图刷新期间保留旧内容，补丁未变时保留模式、折叠与滚动，后台完成不抢聊天焦点；提交后文件不再有差异时显示空差异。

## 分支操作（2026-10-27）

分支行支持右键菜单和可见的行尾操作按钮，两者共用同一菜单。当前分支、其他本地分支、远程分支按适用范围显示操作；进行中的 Git 操作、CLI 任务和其他 Worktree 占用会禁用相关写操作。展开和刷新列表不访问网络，Update / Checkout and Update 明确执行 fetch。

- **基础管理**：Checkout；从所选分支新建（可选择创建后切换）；本地 Rename / Delete；Tracked Branch 子菜单设置或取消 upstream；Push 表单指定 remote、目标分支和是否设置 upstream。普通删除拒绝未合并分支，不提供强制删除和远程删除。远程 Checkout 新建本地跟踪分支，同名已存在时明确失败，保留原分支。
- **比较**：Compare 展示两端最终文件差异，以及最多 200 条分支独有提交（`<` 所选、`>` 当前）。Show Diff with Working Tree 比较所选提交与磁盘内容，包含暂存、未暂存和未跟踪文件。比较引用固定为打开时的提交 ID，HEAD 改变后提示重新打开；文件差异按点击懒加载，复用并排/统一 Diff、折叠和 F7 导航。最多 2000 个文件、单文件补丁 4 MiB。重命名按删除和新增展示。工作区中已删除后重新创建为未跟踪的同名文件仍比较实际内容；临时比较文件自动清理，不修改 index。
- **Worktree**：选择父目录并填写目标绝对路径；填写新分支名时从所选提交创建，留空时使用所选本地分支。目标只能是不存在的目录或空目录。成功后自动加入左侧工作区列表，不切换当前会话。
- **整合**：Merge 所选分支到当前分支；Rebase 当前分支到所选分支；Checkout and Rebase 先切到所选分支，再 Rebase 到原分支。执行前展示方向和历史改写说明，已跟踪文件存在未提交修改时拒绝开始。不会自动 stash、强制切换或强制推送。
- **更新**：Update 当前分支支持 Merge / Rebase 选择；非当前分支只更新未被其他 Worktree 占用的分支，使用 fetch + 快进，不暗中切换分支。已领先上游时保持原状；分叉时要求先 Checkout 再更新。Checkout and Update 明确先切换再更新，后半步失败会报告已经切换，避免将部分成功显示成完全失败。
- **恢复**：从 Git 实际元数据探测 Merge / Rebase，重启后仍显示进行中状态与冲突文件。在外部编辑器解决冲突并 `git add` 后点击继续；中止先显示确认。Cherry-pick / Revert 也会被识别并阻止其他分支写操作，需在终端完成。冲突不会自动回滚，超时或失败后刷新实际状态。
- **执行边界**：分支、HEAD、所选引用提交、upstream 和 Worktree 占用在执行前重新核对；Fetch 后再次核对。Git 写操作使用现有后台线程与 120 秒单命令超时，不阻塞 UI，不自动重试。通过共同 Git 目录协调 linked worktree 的 CLI 任务与 Git 写操作，聊天任务之间的并发规则保持不变。

## 提交和 AI 生成

Commit 只提交 Git 已暂存区，不自动 add，也不包含未跟踪或未暂存内容。提交说明草稿按工作区保留在内存，切换工作区不会覆盖；提交成功后清空对应草稿。执行前重新核对分支、HEAD 和暂存对象；预览已变化时要求刷新重试。CLI 任务运行期间禁用 Git 写操作；Git 操作运行期间阻止启动新聊天任务。

Commit and Push 先提交，再向配置的 upstream 推送；使用明确的远程和目标分支，不 force、不推送其他分支。没有有效 upstream 时提示先配置；若提交成功但推送失败，清空已使用的提交说明，明确显示“提交已成功，推送失败”并保留待推送入口，下一次可直接 push。普通 commit/push 允许 120 秒（含 hooks/签名/网络等待），失败后刷新状态，不自动重试。

badge 有 upstream 时统计 upstream..HEAD 的提交数；没有 upstream 时统计 HEAD 中尚未被本地远程引用覆盖的提交数，并在 tooltip 说明“尚未设置上游”。不 fetch，故计数基于本地记录；外部 Git 操作由定期探测更新。

设置 → Git 提供多行 Commit Message 提示词，自动保存至 `state.json` 的 `git.commit_message_prompt`，全工作区通用；支持恢复默认、留空回退默认，下次生成时生效。旧配置缺少 Git 设置时自动使用默认提示词。

AI 生成传入设置中的提示词、已暂存文件名与预览 diff（最多 200 KiB）。使用当前会话的引擎和模型，未选会话时使用当前默认引擎；结果填入提交说明后仍可编辑。生成使用独立临时 CLI 会话，不续接聊天、不写入聊天历史；Codex 使用 ephemeral/read-only/never，禁用 shell、hooks；Claude 禁用工具、MCP、hooks 和会话持久化。超时、取消、工具请求和空结果显示错误，不替换已有草稿；流式增量由完整快照替换，避免重复。当前草稿和 AI 草稿都只在内存中保留，重启不恢复。
