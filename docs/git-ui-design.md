# Git 界面设计

本轮采用 IDEA 的工具窗口思路，让聊天仍是主界面。现有 Git 命令执行、后台探测、超时和 diff 高亮可以复用；提交历史需要新增日志查询与按提交读取变更，当前未实现。

## 本轮已实现

- 对话内容区底栏位于输入框下方，不延伸至工作区列表或右侧停靠区。右侧 Git 图标打开独立右侧 Git 变更栏，再次点击或点击关闭按钮收起。
- 会话标题旁的侧栏图标与工具卡片只打开工具详情。工具详情与 Git 变更按入口切换停靠内容，不再使用共用页签或 split。
- Git 侧栏复用可拖宽停靠区，最大为聊天可用宽度的一半；窄窗时覆盖显示。底栏位于对话列内；宽窗侧栏打开后入口随对话列宽度调整，窄窗覆盖层不遮挡底栏。
- 底栏左侧显示工作区当前分支，向上展开本地/远程分支列表，标记当前分支。保持只读，不 checkout，也不 fetch；远程分支是本地已有的远程引用。
- 非 Git 工作区隐藏分支下拉；没有提交时显示实际分支名；分离 HEAD 显示短 hash。启动、工作区切换、任务结束及手动刷新时读取分支，每 10 秒同步外部 Git 操作。
- 切换工作区立即清空旧数据并取消旧探测。分支探测独立于 status/diff，关闭侧栏不再读取完整 diff。
- Git 侧栏上下分区：上方独立滚动查看变更和 diff，下方固定 Commit Message 输入框。右上角 Sparkles 图标使用当前引擎/模型生成说明，输入区右下角提供 Commit 主按钮和 Commit / Commit and Push 下拉。
- 底栏 Git 图标右侧按需显示待推送图标及提交数 badge；点击向当前上游推送，成功后刷新计数。

## History 推荐方案（待实现）

从底栏增加独立“历史”入口，打开位于底栏上方的可拖高面板，初始高度约 280px，限制在内容高度的 35%–55%。聊天保留在上半区；小高度窗口改为较大的独立历史浮层。

横向布局建议如下：

| 提交列表（约 65%） | 选中提交详情（约 35%） |
| --- | --- |
| 图线 · 分支标签 · 提交说明 · 作者 · 相对时间 | 完整提交说明、作者、时间、短 hash |
| 单击切换所选提交，当前提交有明确标记 | 文件列表及新增/删除统计 |

底栏分支下拉继续承担分支定位，历史首版不额外常驻一列分支树。顶行提供当前分支/所有本地引用范围与提交搜索。首次只加载约 100 条提交，向下继续加载；空仓库显示“尚无提交”，查询错误提供重试。

点击历史文件后，Git 专属右侧栏显示该提交相对父提交的 diff，顶部明确标注“提交 a1b2c3d”并提供“返回工作区变更”，避免把历史版本误认为当前未提交修改。History 的右侧摘要保持在底部面板内部，不随工具详情入口变化。

这样可形成“上方对话、下方追溯、右侧核对”的工作流。首版先做提交列表、完整说明、文件列表和单文件 diff；多分支彩色拓扑图放在后续，否则容易把主要成本花在图线布局上。

实现时补充受管只读 `git log`、`show`/`diff-tree` 查询，使用固定字段分隔、输出上限、后台线程与取消机制；按工作区、提交 hash 和文件路径校验异步结果。合并提交需明确显示与第一父提交的比较，根提交使用空树比较。

## 提交和 AI 生成

Commit 只提交 Git 已暂存区，不自动 add，也不包含未跟踪或未暂存内容。提交说明草稿按工作区保留在内存，切换工作区不会覆盖；提交成功后清空对应草稿。执行前重新核对分支、HEAD 和暂存对象；预览已变化时要求刷新重试。CLI 任务运行期间禁用 Git 写操作；Git 操作运行期间阻止启动新聊天任务。

Commit and Push 先提交，再向配置的 upstream 推送；使用明确的远程和目标分支，不 force、不推送其他分支。没有有效 upstream 时提示先配置；若提交成功但推送失败，清空已使用的提交说明，明确显示“提交已成功，推送失败”并保留待推送入口，下一次可直接 push。普通 commit/push 允许 120 秒（含 hooks/签名/网络等待），失败后刷新状态，不自动重试。

badge 有 upstream 时统计 upstream..HEAD 的提交数；没有 upstream 时统计 HEAD 中尚未被本地远程引用覆盖的提交数，并在 tooltip 说明“尚未设置上游”。不 fetch，故计数基于本地记录；外部 Git 操作由定期探测更新。

设置 → Git 提供多行 Commit Message 提示词，自动保存至 `state.json` 的 `git.commit_message_prompt`，全工作区通用；支持恢复默认、留空回退默认，下次生成时生效。旧配置缺少 Git 设置时自动使用默认提示词。

AI 生成传入设置中的提示词、已暂存文件名与预览 diff（最多 200 KiB）。使用当前会话的引擎和模型，未选会话时使用当前默认引擎；结果填入提交说明后仍可编辑。生成使用独立临时 CLI 会话，不续接聊天、不写入聊天历史；Codex 使用 ephemeral/read-only/never，禁用 shell、hooks；Claude 禁用工具、MCP、hooks 和会话持久化。超时、取消、工具请求和空结果显示错误，不替换已有草稿；流式增量由完整快照替换，避免重复。当前草稿和 AI 草稿都只在内存中保留，重启不恢复。

- 全套常规测试 55 通过；真实临时仓库回归覆盖 staged-only 提交、Unicode/多行说明、未暂存及未跟踪文件保留、陈旧暂存区/分支拒绝、取消、分离 HEAD、本地 bare remote 推送、ahead 递增/清零，以及提交成功但推送失败时保留待推送状态。
