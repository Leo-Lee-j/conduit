# Chat 中的 @ 文件引用

## 评估与实现（2026-10-27）

原有输入区已支持文件拖入、剪贴板文件粘贴和原生文件选择器，共用路径校验、引用卡片、会话草稿与发送前复验；缺少 `@` 查询、工作区候选列表和对应键盘操作。本次参考 Codex 的文件引用入口，在现有引用机制上补齐文件搜索。选中后沿用输入区附件卡片，不改变存储和两款 CLI 的 prompt 协议；尚未实现正文内的原子引用 token。

## 交互

- 在行首、空白或左括号等边界输入 `@` 唤起；输入文件名、相对路径进一步过滤，匹配不区分大小写，支持模糊匹配和 Windows 反斜杠。邮箱、`@@`、转义的 `\@` 不触发。文件名含空格时，可输入不含空格的片段后选择候选。
- 候选显示文件图标、文件名与相对目录，完整路径可通过悬停查看。优先展示文件名精确、前缀、包含匹配，再展示路径与模糊匹配；每次显示前 6 项，继续输入可缩小范围。
- `↑ / ↓` 循环选择，`Enter / Tab` 确认，鼠标可直接点击；选择保留输入焦点，将当前光标前的 `@查询` 转成文件卡片，前后正文保留。文件被删除、不可读、为二进制或超限时显示现有校验提示，保留查询与草稿。
- 候选加载中或无结果时，`Enter` 不发送消息。关闭候选后，恢复原有 Enter 发送和 Ctrl/Shift+Enter 换行。中文输入法有预编辑文本时，确认、导航与关闭操作不添加文件或发送消息。
- `Esc`、点击弹层外部、移开光标或输入空白可关闭；Esc 后重绘不会重新打开相同查询，修改查询或离开后重新输入可再次唤起。切换会话或工作区后，旧查询结果不能被确认到新草稿中。
- 拖入、粘贴、选择器与 `@` 共用校验和按规范化路径去重；发送前再次检查引用文件。只传递路径，文件内容仍由 CLI 读取。

## 搜索范围与性能边界

使用已有依赖树中的 `ignore` 库（新增直接依赖）后台遍历当前工作区，遵循 `.gitignore`、`.ignore` 等规则，包含未被忽略的隐藏文件；跳过 `.git` / `.hg` / `.svn`、`node_modules`、`target`、`.venv`，不跟随符号链接。工作区外文件和忽略项仍可通过附件按钮添加。

单次扫描最多 100,000 个目录项、64 层深度，并在遍历期间检查 4 秒预算；不对单次阻塞的文件系统调用提供硬超时。访问失败、达到预算或目录项读取出错有相应提示，不把不完整结果当作全量结果。搜索只读取路径，选中与发送时才复用现有文本/大小校验。

索引仅保留最近一个工作区，缓存 30 秒；缓存到期后下一次查询重新扫描。搜索采用 60 ms 防抖，排序在后台执行，UI 只绘制最多 6 个候选；请求序号丢弃被后续查询取代的结果。弹层按光标定位，使用组件库的翻转与视口约束，不占用聊天布局高度。

## 验证

新增纯逻辑回归覆盖 Unicode 光标边界、邮箱误触、选区与路径中间位置、文件名/路径/模糊排序，以及忽略规则与隐藏文件扫描。

GPUI 事件回归覆盖键盘与鼠标确认、Esc 抑制重开、无结果 Enter 防误发、保留正文后缀、含空格的中文文件名、重复引用去重、候选文件删除、输入法预编辑保护、跨工作区丢弃旧结果及 850×500 窗口内的弹层范围。

这些测试验证状态、事件路由与布局边界，不检查真实渲染像素，也不替代实际 Windows 中文输入法、高 DPI 与鼠标手感的人工验收。

验证命令与结果：

- `cargo fmt --check`：通过。
- `cargo test --locked --offline --features ui-tests -- --test-threads=1`：163 passed、0 failed、12 ignored（包含新增 3 项纯逻辑测试与 3 项 GPUI 测试）。
- 最终扫描边界修正后，单独重跑 3 项 `file_search::tests`，全部通过。
- `cargo build --locked --offline`：最终构建通过。
- 隔离数据下隐藏启动 5 秒，进程持续运行、stderr 为空。隐藏模式未暴露可检查的主窗口，不能认定原生窗口响应或视觉验收通过。
- 严格 Clippy：由既有的 `sessions.rs` 嵌套 if、`chat_runtime.rs` 参数数量与 `store.rs` needless return 共 3 处警告阻塞。临时通过命令行允许这 3 类既有警告后，all-targets / ui-tests / `-D warnings` 检查通过；没有修改这些原有代码或写入 lint 豁免。
