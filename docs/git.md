# Git 工作流

Git 查询、命令执行和 Diff 读取在后台完成。界面使用左侧变更/分支导航和主区标签；各工作区保留提交草稿、快照与打开的 Diff。操作前再次检查仓库、引用及工作区身份，迟到结果不能覆盖当前工作区。

## 变更与提交范围

变更侧栏由工具栏、独立滚动文件列表和固定提交区组成。默认按 Changes / Unversioned Files 分组，可切换状态分组；支持单文件、整组、全选及批量暂存/移出暂存。文件行保留状态文字、部分暂存和重命名信息，双击打开 Diff。

**勾选控制提交范围，提交只包含勾选文件的已暂存内容。** 已跟踪文件的修改和删除在常规状态刷新后自动暂存；未跟踪文件首次加入需手动暂存。不希望提交某文件时取消勾选；主动移出的已跟踪修改可能在下次常规刷新重新暂存。

只读、关闭中、Git 写操作、AI 说明生成、同仓库 CLI 任务、未结束的 merge/rebase 或冲突会阻止自动暂存。操作后的结果刷新只读状态，避免自动重试循环。

提交区提供 Commit / Commit and Push、可选 Tag 和 AI 说明生成/取消。AI 配置可跟随当前会话或使用独立引擎/服务/模型，生成范围与文件选择一致。执行期间按钮显示加载状态并阻止重复提交；长说明和窄窗不能遮挡底部操作。

## Diff、分支与日志

Diff 是按工作区与路径去重的只读标签，提供已暂存/未暂存内容，支持首次提交、删除、重命名和部分暂存文件。外部变化与刷新必须保留正确的版本来源，不能用工作区完整文本冒充待提交快照。

分支树展示本地、远程和标签，支持搜索、收藏与滚动；默认展开 Local，搜索临时展开匹配分组。日志与提交文件列表使用虚拟化，加载提交详情时显示占位，刷新已有日志时保留内容。

分支菜单提供创建、重命名、删除、切换、跟踪、推送、更新以及 merge/rebase 与冲突恢复。linked worktree 占用、陈旧引用、脏工作区和未结束操作必须在执行前校验。菜单点击需覆盖 mouse-down → 重绘 → mouse-up，不能仅用 Enter 测试替代鼠标路径。

打开分支列表和普通刷新不自动 fetch。仓库状态与分支探测保留各自的可见性/周期调度，已有查询或写操作时不叠加周期请求。

## 版本标签

标签是 Git ref，生成候选不会修改 `Cargo.toml`、源码或自动提交。稳定标签按 SemVer 排序；“生成下一个”以本地最高的有效 `vMAJOR.MINOR.PATCH` 为基准，支持 Major / Minor / Patch 和 1–100 步长，递增后将右侧段归零，跳过已占用名称。没有有效版本时从 `v0.1.0` 起步。

- Commit 将可选轻量标签明确指向本次新提交的对象 ID。
- Commit and Push 仅原子推送当前分支与本次标签，不用 `--tags`、不 force；远端不支持原子推送时报告失败，不隐式拆成两次推送。
- 发布型标签必须符合目标仓库规则。本仓库要求稳定 `vX.Y.Z` 与 Cargo 版本一致，Actions 仍是最终校验方。
- 标签选择器显式刷新时使用 `git ls-remote --refs --tags` 查询当前上游，区分仅本地、仅远程、两端存在和未查询；不 fetch、不写本地 refs。失败保留上次成功快照。
- 提交和标签已创建但推送失败时保留本地成果。先核对远端状态并推送分支，再使用标签重试；重试重新核对 HEAD、标签目标、上游和推送地址，远端分支包含该提交后才推标签。
- 远端同名标签指向相同提交视为成功，指向其他提交则拒绝。重试状态仅保留在当前应用进程，不支持多个 push URL。

远程标签删除/移动、强推和自动清理旧标签不在此工作流内。发布操作见[发布与更新](releasing.md)。

## 并发与通知

Git 写操作按共享仓库与 CLI 任务互斥，覆盖 linked worktree；不同仓库的聊天不应被阻塞。不可操作原因保留在按钮提示，必要的重试入口随对应状态提供。

操作结果和校验错误统一进入[通知中心](notifications.md)，即使 Git 面板已经打开也显示统一 Toast；普通进度只进入历史，避免自动暂存频繁打扰。提交区和分支面板底部不再重复显示消息，标签推送重试按钮仍按需保留。通知绑定原工作区，后台操作完成不能错误跳往当前工作区。
