# Chat 命令入口设计

状态：首版已实现。下方“当前交付”说明已接入的来源和限制，其余章节保留扩展契约；不代表所有 CLI 的终端命令均已可用。实际验证日志写入忽略目录。

## 目标与边界

在聊天输入框提供 `/` 命令选择入口，支持搜索、补全、参数输入、执行反馈，以及按工作区和引擎切换可用命令。命令既可以来自 CLI，也可以来自 Conduit 已有操作；后续允许接入已注册的插件命令。

核心原则是让输入框消费统一的命令描述，让命令来源负责解释语义，让现有宿主与 CLI 运行时负责执行。公共层不根据 `Provider` 或命令名决定行为，不维护一份跨引擎的硬编码 slash 列表。

首版只建立必要的边界：命令目录与调度、输入框交互、来源适配。暂不增加通用脚本语言、任意命令执行器、完整 JSON Schema 表单系统、远程命令市场或常驻 CLI 池；也不重构整套插件系统。具体原生命令以协议夹具和实际安装版本验证结果为准。

## 当前交付

- 公共模块为 [commands.rs](../src/commands.rs)，UI 控制器为 [app/commands.rs](../src/app/commands.rs)。来源通过 `EngineDescriptor.commands` 可选注册，普通消息、命令与发现使用 `RequestIntent` 明确区分。
- 输入 `/` 只筛选内存目录；有候选项时才显示弹窗，`↑/↓` 选择，`Enter/Tab` 补全后再次提交执行；没有匹配命令时关闭弹窗，`Enter` 直接发送普通消息，其他按键沿用普通输入行为。继续编辑恢复匹配时重新显示弹窗；`Esc` 保持关闭直到查询或目标变化。补全保留参数和附件，执行命令时显式拒绝附件；普通消息沿用附件和排队流程。同名冲突或已选命令失效时保留草稿。
- 宿主动作：`/conduit:new`、`/conduit:settings`，复用现有业务入口。导航操作不进入普通消息队列。
- OpenCode：使用 ACP 会话目录和同一受认证本地服务的 `/command` 元数据。无缓存时提供“连接／刷新命令”；该操作经过保存门控，保留输入与附件，绑定新建或恢复的原生会话，且不发送模型提示词。目录通知可在会话响应前后到达，均需核对原生身份后才发布。
- 首版 OpenCode 只执行可核验的本地 prompt 命令。独立 agent/model、subtask、shell 模板、MCP/skill 或不完整元数据均显示不可用原因。依据执行元数据判断，不使用命令名称白名单。参数含 `!`、反引号或 `$` 时拒绝执行，避免原生模板展开绕过宿主权限；草稿会保留。原文传给来源，空格／引号的最终解释遵循原生 CLI。
- 执行前在当前进程重新取得目录与详细元数据，核对原生身份、命令定义指纹；保存确认前再次校验目标、配置及 CLI 文件身份。命令定义改变／删除时不回退模型提示词。成功且无正文也有完成 Notice，失败／取消复用现有记录与进程清理屏障。命令记录采用既有 Notice 类型，不自动重试或重新解释旧队列。
- 目录内存限制：每个上下文最多 512 项、512 KiB，最多 8 个上下文；完整替换、空目录清空、刷新保留旧快照，旧运行代次不能覆盖新目录。原生详细元数据只在适配器内使用并限制为 2 MiB，不写入 UI 缓存或会话记录。

| 来源 | 当前支持 |
| --- | --- |
| Conduit | 新建会话、打开设置 |
| OpenCode ACP（1.19.2 协议对照；本机 1.19.5 已验证） | 动态目录、显式连接、上述可核验命令 |
| Codex | 宿主动作；原生 App Server 命令待适配 |
| Qoder | 宿主动作；原生命令待适配 |
| Claude Code | 宿主动作；原生命令待适配 |

没有匹配命令的输入统一按 `RequestIntent::Message` 进入既有普通消息流程，协议编码仍由适配器负责；这不保证原生 CLI 不再解释前导 slash。菜单不提供独立的普通消息发送按钮，也不增加逐引擎的 UI 分支。

当前发现接口只接入会话来源，静态宿主目录不需要探测。初始化独立发现、更多原生来源、插件投影、复杂参数、命令排队和磁盘缓存保留为扩展项。新增来源继续在注册／适配层实现，不向公共菜单添加引擎或命令名称分支。

自动回归位于公共模块、输入交互、发送确认和 OpenCode 协议测试。`installed_opencode_commands_discover_resume_and_execute_locally` 是单独选择的本机 CLI 集成测试：隔离配置／数据库，仅使用本机模拟模型服务，验证发现零模型请求、会话复用、命令执行和定义删除后的拒绝。它不使用真实模型账户。

## 职责划分

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| 输入框命令控制器 | 触发、筛选、选中、补全、参数提示、提交意图 | CLI 协议、子进程、权限判断和业务实现 |
| 命令目录与调度器 | 聚合来源、稳定身份、快照、上下文绑定、重校验和路由 | 解析各 CLI 的 wire 字段、拼接 shell 命令 |
| 命令来源 | 提供描述、发现策略、参数解释、能力判定和受信任的执行目标 | 自行持有 CLI 进程树、跳过保存确认或宿主校验 |
| 现有宿主／引擎执行端 | 应用动作、协议转换、保存与运行、取消、结果和清理 | 输入框筛选与弹层状态 |

来源可通过静态定义、后台发现或现有运行中的事件发布目录。输入框不需要知道目录来自磁盘、SDK、ACP 或某个 RPC。

内置应用操作由宿主来源提供；引擎来源由引擎描述符注册可选工厂；未来的插件来源只投影已经注册并允许从 chat 暴露的命令。未提供命令来源的引擎仍能正常聊天。

## 公共数据模型

以下是语义约束，不冻结 Rust 的最终字段名称或公开 ABI。

### 命令定义与身份

| 数据 | 语义 |
| --- | --- |
| `CommandRef` | `source_id + local_id`；不依赖显示名称、翻译、排序位置或 CLI 进程地址 |
| `CommandDescriptor` | 稳定身份、输入名称与别名、标题、简述、参数规范、作用域、执行条件、附件策略 |
| `SourceRegistration` | 宿主颁发的注册身份；来源注销再注册后，旧身份失效 |
| `CatalogSnapshot` | 来源、适用上下文、目录修订号、完整命令集合、当前发现状态 |
| `CommandAvailability` | 针对当前上下文计算的可执行／不可执行状态及原因，不作为持久授权 |

显示名称只用于查找与展示，不能作为执行身份。来源内部可将命令绑定到宿主 action、引擎操作或插件调用；该绑定由来源生成，不能从用户输入或目录描述中获得任意 RPC 方法、shell 片段或宿主函数。

首版参数规范只需要 `None` 和 `TailText { required, hint }`。`TailText` 保留命令名之后的原始文本，不在公共层按 shell 规则拆引号、展开变量或解析路径。特定命令需要结构化参数时，由来源准备执行请求；只有出现多个实际使用方后，再增加公共字段类型。原生协议没有给出必填信息时，不从提示字符串猜测，交给来源校验。

执行条件按语义描述，例如需要工作区、需要会话、需要会话空闲、允许运行中执行、需要可写状态。它们是来源声明与宿主规则的交集，不是来源自行授予权限。

### 目录上下文与调用目标

| 数据 | 绑定内容 |
| --- | --- |
| `CatalogContext` | 工作区、引擎稳定 ID、CLI 可执行身份、配置／路由修订、权限模式，以及来源声明需要的会话身份 |
| `CommandInvocation` | 调用 ID、命令身份、来源注册身份、目录修订、捕获的目标、原始命令文本、参数及允许的附件 |
| `PreparedCommand` | 重校验后的受信任执行请求；不对外暴露可任意构造的协议载荷 |
| `CommandProgress` | 调用 ID、目标、运行代次、状态、可选摘要／正文；通过现有有界事件通道传递 |

工作区和引擎应从实际发送目标推导，包括输入框已选择另一个引擎、下一次发送会新建会话的情况，不能仅使用当前可见会话的 provider。

已有会话的调用绑定本地会话 ID 和原生会话 ID；新会话草稿绑定工作区、预期引擎和草稿目标代次，并在保存确认后绑定新会话。执行中切换标签不能改变调用目标。

目录修订更新但命令身份仍存在时，可以在原目标上重新准备请求；命令被删除、来源被替换、目标或关键执行语义变化时，拒绝旧请求并保留输入，要求用户重新选择。不能只凭同名命令悄悄替换执行对象。

## 来源接口与扩展约束

建议按以下三个职责定义接口，允许在同一模块内实现，不要求每个职责创建独立服务或线程。

| 操作 | 契约 |
| --- | --- |
| 读取目录 | 读取缓存和静态元数据，UI 线程不扫描目录、不启动 CLI、不等待网络 |
| 请求刷新 | 接收上下文与请求票据，在后台发现；发布完整快照、失败或“需要会话”状态，可取消 |
| 准备调用 | 复核来源身份、命令存在性、参数、目标和能力，返回宿主动作或引擎请求，由既有执行端受理 |

可选注册项缺失表示来源不支持命令能力，不能退回猜测协议。执行中取得的原生命令目录也可以更新同一缓存，不要求为每次发现单独启动进程。

公共执行请求区分普通消息、明确命令和目录发现。具体枚举名称由实现确定，但不得靠 `prompt.starts_with('/')` 在每个适配器内重新推断意图。重试、恢复、附件拼接和未来的排队都必须保留这个区分。

引擎适配器内部可以使用来源私有的操作类型或句柄；公共模型不增加 `ClaudeCompact`、`CodexReview` 等逐引擎变体。专用协议操作与普通文本命令采用相同的目录和反馈接口，其差异止于执行端。

插件桥接需要保留原注册系统的 owner、registration、scope 和能力校验，执行时由原注册表重新颁发调用票据。slash 描述不能直接构造已有 `plugins::commands::CommandInvocation`。允许扩展来源不等于首版开放任意第三方运行时。

### 扩展是否合格

- 给已有引擎增加一个相同执行方式的命令，只更新该来源的目录或映射及对应夹具。
- 接入新的命令来源，只增加注册、来源实现及契约测试；输入框、公共筛选器和公共发送路由不增加引擎分支。
- 同一命令可从 slash 面板或其他显式 UI 入口触发，目标校验与执行结果语义一致。
- 仅当多个来源确实需要相同能力时才扩展公共契约；来源私有细节保持私有。

## 目录发现、缓存与首次使用

### 发现方式

来源声明以下能力之一，宿主据此调度，不通过引擎名称推测。

| 方式 | 行为 |
| --- | --- |
| 静态／本地元数据 | 直接读取受信任注册或后台解析来源元数据；解析命令描述不执行命令内容 |
| 仅初始化可发现 | 允许受控的短生命周期初始化，不提交用户提示词、不请求模型生成，不开放工具执行 |
| 需要原生会话 | 在已有会话可安全恢复时发现，或随正常会话事件获取；新草稿不因输入 `/` 隐式创建原生会话 |

没有缓存时立即展示当前来源已确认的静态命令。尚未连接的动态来源显示明确状态；不能将其他工作区的缓存标成当前可用。若需要在首轮聊天之前获取会话级目录，提供明确的“连接以加载命令”动作，通过保存确认绑定和保留原生会话身份，不制造取完目录就丢弃的隐藏会话。

目录探测是否支持无模型调用、是否会建立会话以及如何可靠结束，必须先通过协议样本验证。不满足约束的来源降级为“连接后可用”，不使用探测提示词、不自动登录、不模拟终端键盘。探测进程仍使用现有取消、超时和进程树管理设施。

真正执行时，如果目录需要启动后的权威信息，应在同一次初始化／恢复后先校验命令再提交操作；命令消失或能力不足时结束并报告，不能改发原始文字作为模型提示词。

### 快照与失效

1. 对同一来源和上下文合并并发刷新。输入筛选只在本地快照上执行，不按每次按键发起探测。
2. 缓存按来源声明的作用域复用；键必须包含影响目录的工作区、CLI 身份和配置修订，需要会话的来源额外绑定会话。
3. 刷新保留上一份完整快照与基于 `CommandRef` 的选中项。失败展示旧数据及状态，执行前仍须重校验；明确的空快照表示目录已清空，不能继续保留旧命令。
4. 原生全量通知按全量替换处理。将来若接入增量来源，应由来源完成重建后再发布完整快照，公共层不猜测删除语义。
5. 来源注册身份、上下文、请求序号和运行代次共同拒绝迟到结果。切换会话、CLI 路径、配置、权限或注销来源时使相关请求失效。
6. 能力与命令目录事件应在聊天正文的“只接收当前 Prompt 阶段”过滤之前处理，同时保留原生会话身份检查，避免丢掉初始化／恢复阶段的目录通知。
7. 缓存存储目录元数据，不存凭据、原始协议回包或可直接执行的请求。首版使用有界内存缓存，不新增必须迁移的磁盘目录格式。

建议起始预算：每来源／上下文最多 512 项、512 KiB 的规范化目录，最多缓存 8 个上下文，每个上下文最多一个发现任务。预算统一可配置，验证后调整；超限应有明确诊断和不完整状态，执行前仍以来源校验为准。元数据、结果正文和事件队列都需按字节计量，不能仅限制项数。

## 输入框交互

### 触发与键盘

- 首版只在输入正文第一个非空白字符为 `/`、光标位于首个命令 token 内且存在匹配项时打开命令列表。匹配项变为空时关闭弹窗，恢复匹配时重新显示。正文其他位置、多行代码、网址和包含第二个路径分隔符的路径不自动进入命令补全。
- `/tmp` 这类既可能是路径又可能是命令的输入无法仅靠语法判断；没有匹配命令时，按 `Enter` 将原文作为普通消息发送。
- `↑/↓` 移动选择；有候选项时，`Tab` 或菜单打开时的 `Enter` 只接受候选、替换命令 token，保留已有参数和附件。接受后关闭列表，定位到参数位置，后续明确提交才执行。没有候选项时关闭弹窗，不启用命令菜单键绑定，`Enter` 走既有普通消息发送流程。
- 已完整输入的命令可通过发送按钮提交；若名称有歧义，则先显示来源选择。必填参数缺失时显示提示并保留草稿。
- `Esc` 关闭当前补全；输入或目标实质变化后才允许重新打开。同一时刻只有一个补全模式，避免 slash、文件引用和提示词历史竞争按键。
- IME 组合输入优先；组合期间不执行命令、不接受候选。保留既有换行与发送快捷键语义，列表键绑定仅在对应上下文生效。

每项显示命令名称、简述、参数提示、来源与不可用原因；来源信息用于帮助用户区分同名动作。内部票据、RPC 名称、缓存键等不进入产品文案。

筛选首版使用确定的名称／别名前缀和子串匹配，可补充标题匹配；不让描述相似度改变精确名称的优先级。排序稳定，刷新后按身份恢复选中项。列表沿用现有有界高度、滚动、无障碍角色和焦点规则。

### 名称冲突与普通文本

原生命令保留原始名称和来源要求的大小写；大小写不敏感的搜索不能改变实际发送的拼写。公共层不把每一个冒号都解释成命名空间，原生命令本身可以包含冒号。

Conduit 操作首版采用显式别名，例如 `/conduit:new`、`/conduit:settings`，在列表中单独分组。原生来源之间或与应用别名冲突时，列出来源让用户选择；手动输入有歧义的名称不能自动选择某个来源。内部身份始终由注册表给出，字符串前缀不授予宿主身份。

提交时没有精确匹配且没有已接受的命令身份，按普通消息发送；没有匹配项时不显示弹窗、不拦截 `Enter`，发送按钮遵循相同的提交路由。附件、保存确认、队列和失败保留草稿均复用普通消息流程。已接受的命令身份过期、名称有歧义、参数不合法或命令不可用时仍报告错误并保留草稿，不转成普通消息。引擎如何编码普通消息由适配器负责。

## 执行、反馈与持久化

### 提交流程

1. 先检查 IME、补全模式与提交意图，从未拼接附件的输入解析命令名和参数。
2. 捕获目标并生成调用 ID，解析唯一的来源身份，检查描述、参数和附件策略。
3. 在执行入口重新检查应用状态、作用域、权限、会话忙碌状态与来源能力，创建受信任请求。
4. 宿主导航动作复用既有 action；宿主数据修改复用既有持久化流程；引擎命令遵守与普通发送相同的保存确认和进程启动约束。
5. 只有请求已受理且相应保存确认成功后，才按原草稿版本清理输入。失败或取消启动保留原文本及附件，不清掉用户后来输入的内容。
6. 结果绑定调用 ID、目标和运行代次；后台完成更新原会话记录，不切换当前标签或夺取输入焦点。

首版命令不进入普通消息队列。需要独占原生上下文的命令在会话运行中禁用；打开设置等被宿主验证可并发的动作可以执行。运行中控制必须有对应执行端支持，不能通过另起一个同会话 CLI 来伪装。后续若支持命令排队，队列必须存储明确的请求类型及捕获目标，并在出队时重新校验。

附件策略首版分为“不接受”和“由来源处理”。不接受时提示用户处理附件，不能无声忽略，也不能统一用 `compose_prompt` 把附件追加到命令参数。来自来源的解释不允许改变原绑定的工作区或会话。

### 生命周期与结果

命令状态采用通用的“准备／等待保存／运行／取消中／成功／失败／已取消／结果未确认”。不强制每个命令经过所有中间状态，但终态只能生效一次。

普通聊天事件与命令结果可以共用现有通道，命令元数据需计入事件字节预算。终态控制事件沿用运行时保留容量，不因大量输出而丢失。取消后的迟到文本不能把终态改回成功；进程树未确认退出时继续保留运行互斥，遵守已有清理失败处理。

命令可能只有成功确认、结构化数据或 `result` 文本，没有普通 assistant 流。适配器将其归一化为摘要／正文及完成状态；若相同内容已经通过聊天事件显示，不重复追加。成功但无正文时显示简短完成结果，不能留下无反馈的空白回合。

打开模型选择器、设置等导航操作由相应 UI 反馈，不强制插入聊天正文。改变原生上下文的命令和有输出的引擎命令在原会话保留记录。首版优先复用现有 Notice 展示，可增加默认兼容的可选命令元数据；如确需新存储版本，应单独明确迁移，不能假设旧版本能识别新 `ItemKind`。

保存可回看的名称、来源、状态和必要结果，不持久化可重新执行的协议载荷、授权票据或凭据。原始输入按现有草稿／会话数据策略保存，不额外写进诊断日志。退出恢复只恢复草稿与历史；执行结果不确定时标记中断或未确认，不自动重放命令，也不自动创建第二次原生会话。

旧草稿恢复后仍是未提交文本。旧消息、历史导入和普通消息队列中的 `/...` 不得在加载或出队时重新解释成命令；只有新的明确提交动作进入命令解析。

## 引擎适配说明

本节是公共契约的适配示例。这里的协议判断只进入对应来源／适配器，不能进入公共目录与输入框。列举的命令是验证候选，不是首版完整支持清单。

| 来源 | 目录与执行方向 | 必须核对的项目 |
| --- | --- | --- |
| Claude Code | 从真实初始化元数据获得可用命令，在现有 stream-json 流程执行明确命令 | SDK 文档的字段与本机 stdio 返回值是否一致；初始化目录时机；只读／辅助任务限制；仅 `result` 返回时的展示 |
| Codex | 来源内维护已经验证的 App Server 能力映射；技能目录由对应原生接口提供 | 压缩、审查等操作的参数与完成事件；技能使用原生结构化调用；未知 CLI 版本不靠 slash 字符串猜测支持 |
| OpenCode | 将 ACP 命令更新转换成目录快照，按原生命令调用规则执行 | 初始化／恢复阶段通知、空目录替换、会话过滤、参数与自定义命令、安装版本兼容性 |
| Qoder | 通过相同 ACP 目录契约接入已验证命令 | 现有双文本块的普通消息编码与明确命令编码分离；原生能力子集；权限配置变化必须与宿主保持一致 |
| Conduit | 将少量已有应用动作投影为命令 | 使用原业务入口，遵守关闭、只读、会话与工作区约束；不复制业务实现 |
| 插件，后续 | 显式暴露已有注册命令 | 注销、重新注册、参数限制、权限和作用域票据继续由原注册系统校验 |

命令能够改变模型、权限或原生会话身份时，只有可通过现有状态模型同步并验证效果才开放。首版不提供无法保持宿主状态一致的命令。该限制由执行效果和来源能力表达，不在公共层写特定名称黑名单。

协议参考用于建立夹具，不替代本机版本验证：[Claude 命令](https://platform.claude.com/docs/en/agent-sdk/slash-commands)、[Codex App Server](https://developers.openai.com/codex/app-server/)、[ACP 命令契约](https://agentclientprotocol.com/protocol/slash-commands)、[OpenCode ACP](https://opencode.ai/docs/acp/)、[Qoder ACP](https://docs.qoder.com/cli/acp)。

以下为已使用的代码落点与后续扩展位置。公共类型独立于 GPUI，避免 UI 模块反向成为协议依赖。

| 位置 | 改动责任 |

| `src/app/runtime.rs`、发送确认与队列相关模块 | 统一提交入口的意图分流、目标绑定、保存失败恢复、普通队列语义保护 |

不要一次拆出仅转发调用的多层框架。首版以一个公共模块和一个 UI 模块落地，来源私有逻辑放回各自现有模块；文件规模和真实复用出现后再拆分。

## 实施顺序与交付门槛

### 1. 验证来源契约

采集目标 CLI 版本的初始化、命令目录、调用、完成及取消样本，脱敏后建立离线夹具。记录哪些来源可以无模型调用地发现目录、哪些需要原生会话、哪些命令只有终态返回。真实账户或模型调用按[测试约定](testing.md)显式选择。

产出是每个来源的支持矩阵和降级行为，以及公共请求／事件的最小定义。未验证的原生命令不预先标记可执行。

### 2. 实现可贯通的首版

实现目录、控制器、提交分流和结果反馈，并贯通至少一种动态引擎来源和一种宿主动作，证明相同 UI 可以消费不同来源。随后按已验证矩阵接入其他来源；缺少能力的来源明确显示不可用，不阻塞普通聊天。

首版必须包含首次无缓存行为、参数补全、来源冲突、忙碌限制、失败保留草稿、取消和无正文结果。不以“弹出静态列表，但选择后只发送字符串”作为完成标准。

### 3. 按需求扩展

再增加其他原生命令、技能选择、插件投影或更丰富参数。新增能力必须先检查能否通过来源接口实现；若必须修改公共层，补充跨来源需求和兼容说明。命令排队、磁盘目录缓存和常驻连接分别评估，不捆绑进首版。

## 验收清单

自动回归保护跨组件行为，放入所属模块；不为每个菜单项增加重复布局测试。

| 范围 | 必须覆盖 |
| --- | --- |
| 意图与参数 | 普通消息、明确命令、未知命令、路径、原生冒号名称、参数空格／引号／中文、历史与队列不被重新解释 |
| 输入交互 | IME 确认、有候选时显示弹窗及 Enter 补全、无候选时关闭弹窗及 Enter 发送普通消息、恢复匹配时重新显示、Tab、Esc、鼠标、换行、`@` 和历史按键互斥、参数及附件不丢失 |
| 身份与作用域 | 同名来源、新会话草稿、输入框切换引擎、切换工作区／标签、同名重新注册、CLI 路径／配置变化 |
| 目录 | 初始化阶段通知、全量替换与空快照、失败保留已有列表、选中项稳定、预算、取消和迟到结果 |
| 首次发现 | 无缓存可解释；探测不提交模型提示词；不能安全探测时降级；显式连接后的原生身份可继续复用 |
| 发送与恢复 | 保存成功前不执行、保存失败／取消保留输入、旧回执不清新草稿、错误目标拒绝、忙碌命令不混入普通队列 |
| 执行结果 | 流式结果、仅终态结果、无正文成功、重复事件、错误、取消、清理失败、状态同步与中断后不重放 |
| 权限与插件桥接 | 原业务校验、辅助任务限制、来源不能伪造目标、注销撤销、原命令票据校验仍然生效 |
| 扩展性 | 使用离线假来源接入不同命令，不修改公共输入框；同一命令从两个入口执行仍遵守相同契约 |

人工验收沿用现有主题、窗口尺寸、DPI、键盘和 Narrator 范围，重点观察弹层不挤压输入框、刷新不闪动、长描述／错误可读，以及命令完成后继续聊天的原生上下文正确。实施完成后按 [testing.md](testing.md)运行受影响回归与核心检查；本设计文档本身不代表这些检查已执行。
