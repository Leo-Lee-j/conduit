# 设置与 CLI 扩展列表评估

评估日期：2026-11-02。基于当前源代码及已有 `settings-redesign-*` 验收截图；本次未运行桌面程序或调用真实模型。本文是设计建议，不表示功能已实现。

## 建议

添加 Skills / MCP 列表有价值：用户可以确认 Conduit 使用哪个 CLI 的扩展、配置来自哪里，以及为何当前会话无法使用某项能力。建议保留设置弹窗，新增独立的「扩展」分类，第一版只读展示；不要继续把完整列表追加到 CLI 配置页下方。

设置拥挤主要来自页面承担的任务过多，以及列表可用高度不足。调整信息分组和首屏密度，比单纯扩大弹窗或缩小文字更有效。

## 当前依据

- `src/app/settings.rs`：当前包含通用、外观、会话、Git、CLI & 模型服务、快捷键六页；侧栏默认宽 184px，弹窗高度上限 680px，顶部和底部固定区域分别为 56px 和 36px。
- `src/app/settings/connections.rs`：先选择 Claude Code / Codex / OpenCode，再切换 CLI 配置或模型服务。每次只展示一个引擎，路径帮助、模型目录和配置来源已有按需展开。这些设计应继续保留。
- `src/app/settings/general.rs`：通用页同时包含工作台布局、本机数据、应用更新和诊断；会话页有五项命名配置；Git 页默认展示三个模型选择器和 180px 高的提示词编辑器。
- 已有浅色窄窗口截图中，模型服务页首屏只露出一个服务的部分内容。截图用于判断空间分配，不作为当前运行状态的验证。
- 当前没有统一的 Skills / MCP 目录、状态模型或读取接口，不能只增加列表 UI 就完成可靠展示。

## 信息分组

建议沿用左侧导航，并用小标题分组。新增两页后共八个入口，避免把所有入口做成同一层无分组长列表。

| 导航分组 | 页面 | 内容 |
| --- | --- | --- |
| 工作台 | 通用 | 内容宽度、侧栏会话数量、标签页上限 |
| 工作台 | 外观 | 主题、文字和代码阅读设置 |
| 工作台 | 快捷键 | 已实现的快捷键；未实现项移出正式列表 |
| AI | CLI & 模型服务 | 保留现有引擎选择和两个页签；路径、版本、模型服务 |
| AI | 扩展 | 当前引擎与工作区的 Skills / MCP 列表 |
| AI | 会话 | 自动命名与触发方式；独立模型配置按需展开 |
| AI | Git | 提交说明生成偏好；独立模型配置和提示词按需展开 |
| 维护 | 数据与更新 | 本机数据、更新偏好、诊断 |

「扩展」页和「CLI & 模型服务」页共享浏览中的引擎选择；这是设置浏览状态，不改变聊天引擎。CLI 配置页可以提供「查看 Skills / MCP」入口，直接定位到扩展页并带入引擎。

如果后续加入安装、卸载、编辑、多文件配置和日志排障，再考虑把设置作为主区独立标签打开。当前只读列表尚不足以要求新增窗口或完整设置中心。

## 扩展页布局

```text
左侧：设置导航             右侧：扩展
                         引擎 [Codex ▾]  范围 [当前工作区 ▾]
                         [Skills] [MCP]
                         [搜索名称或描述…]        [刷新]

                         名称               来源 / 状态
                         …                  …
                         …                  …

                         选中行在原位展开详情
```

这是一份结构草图，名称和内容不是本机探测结果。

- 引擎选择改为紧凑控件，为列表腾出空间；只有三个引擎，可保留便于切换的分段控件，但不必继续使用宽大按钮。
- 明确范围：全局，或某个具体工作区。当前工作区范围应包含该工作区可见的全局和项目配置，并标出各自来源；没有工作区时默认全局。
- 如果项目配置涉及祖先目录、插件、环境覆盖或自定义配置目录，应遵循各 CLI 的解析规则，不用固定文件夹扫描推断完整有效集合。
- 页面只有一个主要滚动区域；页签、范围和搜索保持可见，行详情内联展开，不再叠加详情弹窗。
- 名称和简短说明占主列，来源与状态占次列；详情显示完整路径和配置来源，避免每行堆叠长路径。
- 切换页签后保留各自搜索和滚动位置；切换引擎、工作区后按新上下文重新查询，旧查询结果不能覆盖新列表。

## 列表应展示什么

| 类型 | 列表信息 | 展开详情 | 状态含义 |
| --- | --- | --- | --- |
| Skills | 名称、一行简介、全局/项目/插件来源 | 完整简介、来源文件、CLI 返回的可用性或读取错误 | 「已发现」表示找到定义；只有原生结果确认后才标为「可用」。是否在某轮调用属于会话信息 |
| MCP | 名称、传输类型、配置启用状态、可确认的连接状态 | 来源文件、脱敏端点或命令、认证状态、错误；有原生结果时显示工具数量 | 配置状态与连接状态分开；已配置不等于已连接，未检测不等于失败 |

第一版操作建议为刷新、查看详情、打开来源文件。源文件操作接入既有文件预览并遵循其访问边界；无法在应用内打开时提供复制路径。不要用只读状态伪装成不可用控件。

安装、卸载、修改、启停、OAuth 登录和主动连接测试留到后续；它们涉及各引擎不同的配置语义与进程生命周期。展示原始配置时需要隐藏凭据、认证头、URL 敏感参数和命令参数中的密钥，而不只是隐藏 API Key 字段。

## 与当前运行时的关系

「本机配置目录」与「某个会话的有效能力」应分别处理，列表明确标注数据依据和刷新时间。

- Claude 当前通过 stream-json 运行，但应用未将初始化中的扩展信息整理成目录。只读聊天和文本辅助任务会设置 `--strict-mcp-config` 与 `--disable-slash-commands`；因此发现本机定义不能直接说明这些任务能使用它们。
- Codex 当前通过 app-server 运行，但应用尚未接入 Skills / MCP 目录查询。实现前应验证所支持 CLI 版本的原生查询方法、工作区参数及返回字段，避免把用户目录扫描结果等同于会话能力。
- OpenCode 当前通过 ACP 运行。会话创建/恢复参数中的 `mcpServers` 为一个空数组，这只说明 Conduit 没有通过该参数注入服务器，不能据此断言原生配置中的 MCP 都被禁用。需要验证原生配置加载和可用状态查询；目前向 UI 暴露的 ACP 配置目录仅包含模型和思考档位。

在扩展页浏览其他引擎时不展示当前聊天的连接状态。仅当引擎、工作区和会话上下文匹配时，提供「查看当前会话能力」入口；权限导致的限制显示在会话附近。命名和 Git 辅助任务的能力限制不混入普通聊天目录。

## 压缩现有页面

1. 通用页移出数据、更新和诊断，优先展示用户经常调整的工作台偏好。
2. 会话页默认显示自动命名、触发方式及「跟随当前会话」摘要；切到独立配置后才展开引擎、服务、模型选择器。已有独立配置不能被默认折叠的摘要隐藏。
3. Git 页默认展示生成配置摘要和提示词摘要；点击编辑提示词再展开输入区。草稿与保存错误需明确展示，折叠和导航切换保留输入。
4. 减少页面标题下重复说明，以及每组底部长段帮助；能指导操作的一句话留在现场，路径规则、配置解释放到展开详情里。错误始终直接可见。
5. 长目录使用紧凑行与分隔线，避免重复卡片嵌套；完整模型目录继续按需展开，保留现有搜索与读取错误。
6. 保留 Esc 关闭、固定导航和清晰的保存状态。列表页明确标注只读，不让「偏好修改后自动保存」暗示正在修改 CLI 的配置。

## 分阶段实现

| 阶段 | 范围 | 评估 |
| --- | --- | --- |
| 页面整理 | 导航分组、移出维护内容、配置摘要与展开、压缩标题和选择控件 | 主要是现有 GPUI 设置组件调整，范围较小 |
| 只读目录 | 三引擎分别探测读取能力、工作区范围、来源、错误、刷新、缓存 | 中等工作量；主要成本在引擎差异、配置优先级和原生接口兼容 |
| 会话能力 | 将原生有效目录和运行状态关联到具体会话，显示权限限制 | 中等至较大；不能通过静态扫描替代 |
| 扩展管理 | 安装、修改、启停、认证、连接测试 | 单独规划，不混入首版列表 |

目录读取采用后台任务，并支持取消、超时和结果体积上限。缓存按引擎、实际 CLI 路径及工作区区分；影响配置解析的环境变化也应触发刷新或失效。只保存必要的脱敏目录元数据，不复制扩展完整正文和凭据到 `state.json`。

原生查询可用时优先查询；不支持时降级为「配置扫描结果」，明确提示完整性和有效性未确认。遇到某个来源读取错误时，保留其他成功来源，不把局部失败表现为零项。打开设置不自动连接所有 MCP 或发送模型请求；原生查询可能启动服务时，需要先验证该方法的行为，并把主动测试设计成明确的用户操作。

## 落地验收重点

- 850 × 500 与 1280 × 900、浅色和深色：标题与操作不重叠，窄窗首屏可阅读多条紧凑行，无横向溢出。支持键盘导航、可见焦点和文字缩放。
- 三引擎、全局与多个工作区切换：来源清楚，结果不串用，旧后台查询不覆盖新上下文。
- 已发现、CLI 确认可用、配置禁用、连接未知、认证缺失、部分失败和不支持查询分别展示；数量不把错误来源计为已成功读取。
- 同名不同来源、覆盖配置、插件提供定义、无效定义、长路径与大量条目：不误去重，详情可访问。
- 刷新、取消、关闭设置和更改 CLI 路径：进程与任务能清理；敏感数据不进入列表、日志或缓存。
