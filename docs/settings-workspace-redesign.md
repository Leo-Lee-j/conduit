# 设置工作区重设计

日期：2026-11-05

## 评估

旧界面具备分类、搜索和自动保存，但信息规模已超过短任务弹窗：11 个页面同时承担外观偏好、CLI 检测、服务管理、默认模型、扩展配置和诊断。限制到 1080 × 680 的模态表面后，小窗口中的页头、页脚和导航进一步挤占内容。外部点击会关闭设置，用户在多个配置页间往返时缺少稳定的返回路径。

搜索原来主要匹配页面关键词，结果显示内部关键词串；“字体”“提示词”等具体目标仍需在长表单中寻找。统一的“已保存”提示同时覆盖自动保存和需要提交的编辑器，用户难以判断保存边界。

## 方案选择

| 方案 | 取舍 |
| --- | --- |
| 扩大原弹窗 | 接入简单，但仍有遮罩、误关和有限高度的问题。 |
| 独立系统窗口 | 可以并排对照，但引入第二套窗口生命周期、焦点和跨窗口状态同步。 |
| 主窗口内的独立设置工作区 | 充分利用窗口，返回路径明确，共享现有状态；采用此方案。 |

参考 Windows 应用设置指南的整页设置布局、逻辑分组和即时应用原则，以及 VS Code 设置编辑器的搜索发现与直接应用行为。结合本项目原生 GPUI 控件实现，不引入 WebView，也不改变现有配置格式。

参考来源（本次已读取官方页面）：

- Microsoft：`https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings`
- VS Code：`https://code.visualstudio.com/docs/configure/settings`

## 信息架构

| 分类 | 页面 |
| --- | --- |
| 工作台 | 通用、外观、快捷键 |
| AI 连接 | AI 引擎、模型与服务、新会话默认 |
| 扩展能力 | Skills、MCP 服务 |
| 自动化 | 自动命名、Git 提交 |
| 应用 | 数据与更新 |

保留引擎安装、服务凭据和新会话默认值的独立边界。导航加入统一线性图标、分组标题和选中反馈；搜索时取消页面选中状态，避免把全局结果误认为当前页的结果。

## 交互与可读性

- 设置占满主窗口；保留系统标题栏，用“返回工作台”替代关闭图标。返回恢复原输入焦点、会话、文档与草稿，记住上次分类。
- 顶部固定宽搜索框；正文保留最大阅读宽度。页面标题 22 px、分组标题 14 px、搜索说明 13 px、导航与底部提示 12–13 px。使用既有明暗主题语义颜色。
- 正文分组增加间距。导航独立滚动；内容沿用原生设置控件的响应式表单和虚拟列表。小于 650 px 高度时，扩展页压缩说明区，为列表留出空间。
- 搜索覆盖 22 个具体任务以及页面、已有服务和模型 ID。支持大小写无关、多词搜索；结果显示分类路径、名称和人类可读说明，空结果提供可点击建议。
- 具体结果进入聚焦的分组视图；复杂模型配置与提示词自动展开。“查看完整页面”恢复全部分组。该做法避免依赖底层组件未公开的滚动状态。
- Ctrl+, 与 Ctrl+M 打开设置；Ctrl+F 搜索，Enter 打开首项；Esc 先清除搜索，再返回工作台。子表单优先处理 Esc，避免丢掉正在编辑的弹窗。
- 自动保存、保存中、错误、只读状态明确显示；服务与原生配置的保存说明随页面变化。已有表单继续使用原来的验证、保存与取消逻辑。
- 从通知跳往会话或工作区时退出设置，确保导航目标实际可见。
