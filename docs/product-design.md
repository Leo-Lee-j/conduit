# Conduit 产品设计文档

版本 0.3 · 2026-10-19 · Windows 个人自用 · Chat M0

本文取代此前“原生终端为主界面”的设计。最终确认的交互是 **Codex 桌面端风格的 Chat UI，底层复用 Claude Code CLI / Codex CLI**。技术与验证状态分别见 [技术设计](technical-design.md) 和 [验证记录](m0-validation.md)。

## 1. 产品结论

**定位：按本地工作区组织多个 AI CLI 对话的桌面 Chat 工作台。**

核心价值是进入正确目录、找到正确上下文、查看执行结果并控制任务，而无需持续操作多个终端。产品负责对话体验和运行管理；模型、工具执行、认证及原生上下文由 CLI 提供。

差异化先落在“同一套 Chat 管理不同执行引擎”，不要以功能数量竞争。首批用户只有创建者本人，日常使用是否更方便是第一判断标准。

已确定：Windows 原生优先；Rust + GPUI + GPUI Kit；Claude / Codex 两个引擎；会话固定引擎与工作区；历史按工作区组织；不做后台守护；单人开发；暂无商业目标。对“一个会话就是一个 CLI”的实现解释是固定执行引擎与原生对话身份，并不要求空闲时常驻 OS 进程。

## 2. 用户与需求分析

用户目前用多个 CLI 执行真实编程任务，主要成本是记住目录、找回对话、区分运行状态及读取工具输出。需要优先验证这些成本在自己每天的工作中是否足够频繁。

| 场景 | 痛点 | 需求等级 |
| --- | --- | --- |
| 打开昨日项目继续追问 | 目录、引擎、历史上下文容易混淆 | P0：历史与可靠续接 |
| 多项目交替处理 | 终端标签不能充分表达任务状态 | P0：工作区与活动状态 |
| 查看一次代码任务 | 回答、命令、诊断混在终端输出 | P0：回复与工具卡片 |
| 遇到授权或异常 | 不知道在等待什么、是否已经停止 | P0：审批、错误、取消 |
| 同仓库开多个任务 | 文件写入互相影响 | P0：首版限制单活动任务 |
| 比较不同模型答案 | 容易产生自动编排与评测的额外复杂度 | P2：先手动新建会话 |

真正刚需是少出错地管理上下文和执行。统一 token 计费、智能路由、多代理自动协商、市场插件、团队共享与复杂项目仪表盘暂不投入。

独立桌面的价值必须通过使用验证：若只增加一层启动入口，终端或 IDE 已经足够；只有历史、状态、阅读和续接都更顺畅，才值得独立存在。

## 3. 竞品与机会分析

本阶段不重做完整竞品排名，也不依据未验证的产品宣传规划功能。

| 替代方案 | 对用户的价值 | Conduit 必须补足的价值 |
| --- | --- | --- |
| 原生 CLI + 终端 | CLI 能力完整，几乎没有适配层 | 更好找回记录、区分任务和阅读输出 |
| IDE 内 AI 助手 | 编辑与代码上下文靠近 | 项目和引擎管理独立于单个 IDE |
| 单一厂商桌面助手 | 该执行引擎的交互一致性高 | 跨 CLI 的共同管理体验 |
| 多 CLI 包装器或代理工作台 | 与本产品方向直接重叠 | 适配可靠、Windows 稳定、足够轻便 |

最大风险是官方桌面工具扩展多引擎或现有工具已经足够。个人自用阶段不需要证明商业壁垒，应优先证明自己愿意连续两周把真实任务放进 Conduit。

## 5. 信息架构与交互设计

主窗口采用工作区侧栏、对话区、按需打开的执行详情。常用操作靠近对话；低频诊断放右侧，减少主区噪声。窗口顶部使用自绘标题栏（品牌区与最小化/最大化/关闭），不再显示系统原生标题栏。左侧工作区栏与右侧执行详情均可拖动边缘调宽，并各有最大/最小宽度限制；窄窗时执行详情改为覆盖层，避免继续压缩对话区。工具详情与 Git 变更有独立入口：标题栏侧边栏图标查看工具输入/输出，对话内容区底栏右侧 Git 图标打开专属变更侧栏，只读查看文件状态与暂存/未暂存 diff，可手动刷新，并在 CLI 一轮任务结束后自动重读；底栏左侧显示当前工作区分支，向上展开本地/远程分支列表（只读、不切换；无 Git 则隐藏），在后台定期重读；状态查询不写入仓库，也不读取未跟踪文件内容。Git 侧栏下方固定 Commit Message（AI 生成按钮）和 Commit / Commit and Push 下拉，只提交已暂存区、不自动 add；底栏 Git 右侧提供带待推送提交数 badge 的推送入口。侧栏顶部是一行图标操作（新建会话、搜索），不再把 Claude / Codex 引擎作为新建会话入口摆在侧栏。聊天左上角提供工作区选择器，可快速切换到已有目录或添加目录；选中工作区后直接在输入框发送任务会按上次使用的引擎新建会话，不再依赖“新建会话”按钮。输入区在会话、无会话和无工作区三种状态下保持同一宽高。新建会话使用哪个引擎由输入区左下角的引擎下拉决定（向上弹出）；切换引擎会同步切换到该工作区该引擎最近的会话，右上角的模型选择器与底部引擎状态同步更新。工作区默认显示最近 N 条会话（默认 5，设置中可调 1–30，超出可展开），工作区行右侧提供“在本工作区新建会话”图标与向右弹出的菜单（移除工作区；只移出应用路径，不删磁盘文件与 CLI 历史），会话行菜单同样向右弹出并与工作区菜单对齐，提供重命名、归档与删除；可点击的图标与菜单项悬浮时显示 pointer 光标。搜索改为弹出窗口：输入标题或消息内容，列出命中会话并在标题与摘要中高亮命中词。输入区按 Enter 发送、Ctrl/Shift+Enter 换行；不再在输入区显示快捷键提示。审批请求的卡片宽度与对话文字列一致，突出图标、请求标题、可滚动的请求详情与明确的允许/拒绝操作。对话区右下角（输入区右上角上方）在消息列表未停留底部时自动显示 向下箭头按钮，点击回到最新内容并自动隐藏，底部保留一条横向工具栏用于后续功能扩展。右侧工具详情和 Git 变更按各自入口切换，共用可调宽的停靠位置，不再使用共用页签或 split；拖动面板左边缘可调宽，最大宽度为剩余内容区的一半，窄窗时以覆盖层显示。设置弹窗垂直居中打开，左侧导航分为通用 / 外观 / Git / CLI / 引擎 / 模型同步：通用页保留本机数据与诊断设置；外观页提供跟随系统 / 浅色 / 深色主题及侧栏会话数（默认 5，范围 1–30），CLI 路径查找顺序等 CLI 信息在 CLI 页，避免与通用设置混排。

```text
┌───────────────────┬─────────────────────────────────┬──────────────┐
│ Conduit           │ 工作区 / 会话标题          详情 │ 执行详情     │
│ + 添加目录        ├─────────────────────────────────┤ 工作目录     │
│                   │                    用户任务     │ 原生会话 ID  │
│ 工作区 A     运行 │ Claude / Codex 回复             │              │
│ + Claude + Codex  │ Markdown / 代码                 │ 工具详情     │
│   会话 1 ● 执行   │ ▸ cargo check          完成     │ 输入或输出   │
│   会话 2          │                                 │              │
│ 工作区 B          │ [等待审批：完整操作内容]        │              │
│   会话 3          │ [允许本次] [拒绝]               │              │
│                   ├─────────────────────────────────┤              │
│                   │ 描述任务 / 继续追问…            │              │
│                   │ 引擎 · 状态        发送 / 取消 │              │
└───────────────────┴─────────────────────────────────┴──────────────┘
```

侧栏底部提供设置入口（弹窗，左侧导航、右侧内容），展示环境变量、应用配置、PATH 或常见位置中的实际路径来源。用户可选择 exe 并运行有超时限制的版本检测；不保存登录凭证，不用版本号推断登录成功。设置左侧提供独立的 **模型同步** 页面，分别列出两个 CLI 当前模型与 cc-switch（CCS）Provider 模型目录；只查询模型名等非敏感字段，不读取或展示凭证，不回写 CLI / cc-switch 配置。

对话输入区提供会话级模型选择器：默认继承 CLI 当前模型，也可为当前会话指定模型；候选合并当前 CLI 模型与 CCS 当前 Provider 的模型，其他 Provider 的模型仅在设置页展示。选择在下一条消息生效，不影响其他会话。

窗口宽度不足 1100px 时，执行详情覆盖在右侧，提供独立关闭按钮，避免继续压缩对话区。审批队列逐项处理并显示待审批数；取消后移除当前待审批入口。

具体流程：

1. 首次启动为空状态，添加可信任目录；创建会话时选 Claude 或 Codex，不立即调用模型。
2. 发送前核对目录、CLI 路径、工作区空闲状态、模型覆盖和持久化结果；成功保存任务后才启动进程。
3. 首条原生会话 ID 绑定到记录；模型增量显示，完整消息替换对应增量，避免重复。
4. 工具卡片随事件更新，点击看详情；不把调试 JSON 混成助手回复。
5. CLI 发起支持的权限请求时，显示完整详情并等用户决定；只授予本次请求。审批使用 UI ticket 对应一次 wire request，CLI 撤销通知会移除过期按钮；没有请求时不伪造审批。
6. 下一轮用同一 Provider、同一工作区与确切原生 ID 续接；模型覆盖随会话保存并只作用于本轮启动。换工具须新建会话，不自动搬运上下文。
7. 切换会话保留其草稿，任务继续；同工作区的其他会话暂不能发送，跨工作区不受影响。
8. 取消和关窗后先清理进程树，确认归零再解除占用；不让“UI 显示已取消”先于本地进程停止。

异常处理：

| 异常 | 产品行为 |
| --- | --- |
| CLI 未找到 | 不发送，保留输入，提示路径配置 |
| 登录失效 | 展示 CLI 错误；用户回官方 CLI 处理认证 |
| 目录不可用 | 不启动，提示检查目录 |
| 会话恢复失败或 ID 不一致 | 停止，不自动换成新上下文 |
| CLI 提前退出 / 非法协议 | 留下已接收内容与错误，不自动重试 |
| 应用或机器重启 | 载入记录并标记上次中断，不重放任务 |
| 本地数据损坏 | 原文件保留，禁止写入与新任务 |
| 不支持的交互请求 | 显式返回错误；提示使用官方 CLI |

Windows 是唯一已实现平台。GPUI 文本输入替代终端键盘模拟，但 IME、DPI、长文本和快捷键仍须实测。macOS / Linux 后续复用业务及协议层，重建进程后端并分别验收。

## 6. 核心业务模型

Workspace 包含多个 Session；Session 固定 Provider，包含 ChatItem、可选 native_id 与可选模型覆盖；ActiveRun 只代表当前任务在内存中的运行。CLI Provider 是两种枚举，不先做插件注册中心。

暂不独立建立 Project、Task、GitRepository、User 等实体。目录就是 Workspace；一次用户发送就是一轮任务；Git 状态未来附属于工作区。进程、会话和消息不能合成一个实体，否则无法表达关闭进程后继续历史对话。

关键规则：一个工作区最多一项活动任务；会话不可切换 CLI；不同轮次可以使用不同 OS 进程但必须保持原生会话 ID；模型覆盖属于会话且只在下一条消息生效；历史展示不等于模型上下文；未知恢复错误不得以新建会话掩盖；原生上下文被删除时须新建。

## 7. 技术可行性与约束

| 能力 | 分类 | 产品含义 |
| --- | --- | --- |
| 模型、工具、认证 | CLI 原生 | 不自行实现助手或密钥体系 |
| CCS 模型目录 | 本地只读外围 | 仅同步模型名与目录，不接管 Provider 切换或凭证 |
| Chat、列表、草稿、历史 | 外围应用 | 由 GPUI 界面与本地存储提供 |
| 流式内容、审批、恢复 | 各 CLI 单独适配 | 统一显示，不假设协议相同 |
| TUI、所有 slash command、任意提问工具 | 无法保证统一 | 首版不承诺原生 CLI 全功能等价 |
| 取消后的远端请求状态 | 无法保证 | 只能确认本地受管进程已停止 |
| 工作区权限隔离 | 依赖 CLI / OS | cwd 与互斥不是安全边界 |

Codex 使用 app-server；Claude 使用 stream-json / stdio 控制交互。PTY 不作为 Chat 解析来源，避免从 ANSI 屏幕猜测语义。适配器必须承受版本变化，固定“已验证版本”并做回归；没有未经确认的兼容承诺。

## 8. MVP 方案

首版只完成：添加工作区 → 选择引擎创建会话 → 发送 → 阅读流式回复和工具结果 → 审批或取消 → 再次发送续接 → 重启找回历史。

实施顺序：真实协议与原生恢复 → 进程生命周期 → Chat 渲染 → 本地记录 → 审批 → 异常与回归。当前核心链路已有实现，尚不能把 UI 与真实权限交互标为验收完成。

非目标：终端主界面、完整编辑器、多人协作、后台守护、自动 Git 提交、任意 CLI 兼容、自动代理编排及商业化。

验收：两引擎各完成真实回复和原生 ID 续接；两个工作区可区分任务；同工作区无双写；取消与关闭不留受管进程；重启保留记录且无任务重放；审批允许和拒绝均能对应准确请求；坏状态不被覆盖；中文输入、滚动和最小窗口可用。未通过项见验证记录。

## 9. 产品路线图

| 阶段 | 交付目标 | 暂不支持 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| Chat M0 | 双 CLI 协议、Chat、续接、存储、进程清理 | 完整兼容矩阵、成熟历史管理 | 真实回复与恢复通过，关键异常有证据 |
| MVP 日用试验 | 完成 UI / 权限验收、崩溃恢复、并行压力与安全提示 | 多代理、更多平台 | 本人连续两周真实使用，无错目录或上下文串线 |
| V1.0 | 历史整理、路径配置、只读 Git Diff（已提前实现）、版本诊断、打包 | 自动化协作 | 每日使用稳定，更新与数据迁移可靠 |
| V1.x | 根据反馈增加模型启动参数、搜索、更多交互类型 | 无需求的团队平台 | 每个新增功能有真实重复场景 |
| 长期 | 更多引擎与平台，显式的任务交接 | 无条件自动权限升级 | 每个平台独立回归，单引擎基础体验不退化 |

## 10. 风险清单与验证计划

| 假设 / 风险 | 验证 | 失败后的处理 |
| --- | --- | --- |
| Chat 比终端方便 | 记录两周真实任务，比较找回和阅读耗时 | 缩减功能或保留为个人工具 |
| 续接可靠 | 两轮跨进程测试、错误 ID 测试、删除记录测试 | 停止恢复，不静默重建 |
| 权限交互可映射 | 合成协议单测 + 临时目录的真实允许/拒绝 | 该类型暂不开放 |
| Windows 进程可清理 | 父子进程、取消、关窗与异常退出测试 | 不解除占用，优先修复 |
| 版本变化破坏协议 | 固定版本记录，升级后复跑握手与恢复 | 回退到已验证 CLI |
| 历史可能含敏感内容 | 检查存储内容和日志边界 | 明确本地明文，不默认上传 |
| GPUI UI 可靠性 | IME、缩放、最小窗口、长对话 | 先修核心输入与阅读，再加功能 |

核心指标：首任务成功率、CLI 轮次启动成功率、可恢复会话的确切 ID 续接成功率；每个都同时记录分子、分母、Provider 和版本。异常中断、取消耗时、找回耗时为辅助指标。消息数、token 和使用时长只作观察，不当成价值。

个人试用不需要先接遥测。建议手工记录不少于 20 次实际任务与 10 次续接，目标启动和续接各 ≥95%；任何错目录执行、串会话或错误授权都是暂停扩展的阻断项。样本门槛是试用判断标准，不代表统计学可靠性。

若连续两周多数真实任务仍主动回到终端，先识别缺失的高频交互；若这些交互无法可靠适配，就缩小范围或停止扩张，避免持续堆功能。
