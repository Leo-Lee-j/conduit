# 性能与指标

本文维护性能边界与测量方法。历史审查中的逐次数字属于当时的源码和环境，不能作为当前版本达标结论。

## 当前约束

| 路径 | 约束与观察点 |
| --- | --- |
| CLI 事件 | 有界队列、数量/字节背压、控制事件预留及 UI 公平处理预算；取消和终态不能被普通流式消息淹没 |
| 聊天渲染 | 按稳定身份与显式失效条件复用消息、工具摘要及聊天视图，输入变化不应重建无关历史 |
| 侧栏 | 虚拟列表和每工作区摘要缓存；排序/插入保留稳定 ID 滚动锚点，后台全文匹配不在 render 中重复扫描 |
| 持久化 | 后台保存回执、内容寻址正文页/块、未变化内容复用；不能以优化为由取消发送落盘门禁 |
| 正文 | 最多 2 个读取任务，驻留目标 8 个正文/估算 64 MiB；被保护内容和单会话加载峰值另测 |
| 导入 | SQLite 增量索引、分批读取与前缀校验；缓存大小不是总 RSS 或磁盘硬上限 |
| 文件与图表 | 后台防抖、过期结果隔离、有界文本/模型/图片与缓存；布局任务不可假称可强制抢占 |
| 终端 | 输入、屏幕历史和控制串有界；隐藏输出不应持续触发聊天重绘或主状态保存 |
| 插件 | VM、宿主原生工作、队列及实例分别限额；具体边界见[Shell 运行时](plugins/runtime.md) |

缓存失效至少考虑主题/字体、会话内容与选择、注册表身份、上下文版本、权限、动态状态、焦点、容器尺寸和显式刷新。只比较数字版本不能识别换了注册表但版本碰巧相同的情况。

正文分块解决重复写入，按需加载解决跨会话驻留；它们都不自动解决选中一个极长会话时的全量组装。持久化、导入、搜索、附件回收和运行态保留必须一起测量，见[会话与存储](sessions.md)。

## Token、上下文和速度语义

[Usage](../src/domain.rs)和协议适配器区分最近请求、当前任务和会话累计，不把不同口径复用为一个数。

- 输入指全部输入，缓存读取/写入是拆分信息；不能把已包含的缓存再次加到总量。
- 上下文使用最近报告的请求快照及模型窗口；累计调用消耗不等于当前上下文，缓存命中也不意味着不占窗口。
- 输出速度只用可靠的输出计数和对应时间，不能包含输入、缓存或导入历史，不能从字符数估算 token。
- 当前会话平均速度按有效输出及时间加权，是含任务等待的墙钟平均，不是模型瞬时生成速度；未知量保持未知，不伪造成零。
- 恢复历史、重复流式快照、计数重置和子代理用量分别处理，不能污染主代理上下文和本轮速度。

相关回归在 `domain.rs`、`protocol.rs` 和会话 UI 测试中。显示指标改变时先冻结语义，再调整窄窗布局与悬浮说明。

## 测量规则

1. 固定源码、工具链、构建 profile、依赖、夹具和数据目录；基线与候选使用一致条件。
2. 预热与正式样本分开，保留独立进程重复、所有失败和原始轨迹。A/B 顺序在每个场景内平衡，不能只做全局 before→after。
3. 完整输入/帧耗时与分项计时分别报告。p95 不能相加，p50 的 nearest-rank 值也不能直接称作偶数样本的算术中位数。
4. 校准计数器、分配追踪、CPU 采样和测试框架自动绘制的开销；测量探针本身可能改变结论。
5. CPU、GPU、布局、脚本执行和等待分开归因；模拟绘制没有原生 GPU 呈现，不能代表桌面完整帧。
6. RSS、private commit、分配器存活量、VM 弱引用和生命周期曲线不是同一指标。对象释放不证明全部原生内存无泄漏；短时增长也不直接证明泄漏。

## 未完成的验收

- 真实 Windows IME、GPU、滚动、多屏/DPI 与慢磁盘退出反馈仍须按场景验收。
- 极长单会话、并发读取/搜索/导入、连续启停和 native 分配归属需要完整曲线与对照。
- Shell 的编辑增量预算、历史普通路径 watchdog 故障、负载与采样开销上界未形成完整生产准入结论；后续报告不能仅凭局部缓存下降解除门槛。

原型性能入口、预算和剩余问题统一维护在[插件验证](plugins/validation.md)，可运行参数在[工具 README](../tools/shell-prototype/README.md)。
