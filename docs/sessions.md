# 会话与存储

## 调度与并发

不同会话可并行，同一会话只能运行一轮；同一引擎的相同原生会话 ID 也只能有一个活动运行。每轮独立持有事件通道、审批队列、取消标记和 Windows Job。切换会话保留其草稿、审批及阅读位置，取消只作用于目标运行。

Git 写操作与聊天按仓库协调，包含共享 `.git` / `commondir` 的 linked worktree。分支、提交和推送等待同仓库 CLI 任务结束；Git 写操作期间阻止该仓库启动新任务。其他仓库不应被连带阻塞。并行本身不提供文件隔离。

## 发送与退出确认

1. 先校验工作区、引擎和服务路由，再建立待发送会话状态，避免失败留下空会话。
2. 发送快照有独立保存回执，不与普通自动保存合并。落盘前保留草稿和附件，CLI 等待启动门闩。
3. 保存成功且请求仍有效后启动；保存失败、取消或关闭恢复发送前内容。迟到回执不得清除之后编辑的草稿、改变当前导航或重启已取消的任务。
4. 取消先尝试协议软取消，再清理进程树。强制清理超过 10 秒会发布可见故障，暂停队列并继续后台重试；仍持有进程和会话互斥，不能把超时当作已经退出。
5. 普通退出与更新重启保存聊天、工作区和 Git 草稿及附件引用。保存失败保留界面供恢复；启动不重放未完成任务。

运行清理完成后才发送 `Finished` 并释放适配器资源。后台发送及审批消息按来源绑定，不抢当前会话焦点。见[通知中心](notifications.md)。

## 数据布局与兼容

默认数据根目录为 `%LOCALAPPDATA%\Conduit`，可用 `CONDUIT_DATA_DIR` 隔离。同一数据目录限制单实例；只读或损坏状态不能通过默认配置覆盖原数据。

| 数据 | 说明 |
| --- | --- |
| `state.json` | v4 工作区、会话摘要、正文引用、偏好及队列等元数据 |
| Transcript 内容文件 | SHA-256 内容寻址的正文根、消息页及文本块；未变化部分可复用 |
| `state.v2.json` | 从 v1/v2 元数据迁移时保存的原始备份 |
| `history-index-v1.sqlite3` | 可重建的原生历史解析缓存 |
| `notifications.json` | 独立的有界通知历史 |
| 草稿恢复与附件文件 | 退出/更新恢复使用，由存活引用与保存回执决定回收 |

当前读取 v1–v4，保存写入 v4。v1/v2 启动迁移先备份原文件，发布正文后再替换元数据；v3 正文仍可读取，后续保存使用 v4。旧版本程序不应尝试清理不认识的正文格式。正文先刷盘并原子发布，再原子替换引用它的 `state.json`，失败不能产生指向未持久化内容的新引用。

正文分块减少重复写入，并不表示已实现逐屏分页读取：选中超长会话时仍可能组装完整正文。内容回收跟踪已提交根与正在读取/写入的租约；不能只按当前内存会话列表删除文件。

## 按需加载与搜索

启动先加载元数据。选中会话后后台读取正文并检查引用身份；快速切换、导入或删除后的旧结果不得覆盖新状态。缺失、损坏或校验失败显示错误与重试，不得当成空会话继续发送或保存。

默认同时最多 2 个正文读取任务，驻留目标为 8 个已加载正文、估算 64 MiB。当前选中、运行、命名、排队、重命名或未确认保存的会话不能被错误驱逐；被保护内容可能使总量超过目标，这不是进程内存硬上限。

全文搜索在后台读取冷正文，保留完整匹配会话 ID，预览最多 40 项；输入有防抖，过期查询不写回。搜索、导入与附件回收均不能把尚未加载的正文视为不存在。

## 原生历史导入

从 Claude Code 和 Codex JSONL 日志后台导入。OpenCode 暂无终端历史自动导入；在应用中建立的 OpenCode 会话可按原生 ID 续接。

### 索引与增量解析

索引位于应用数据目录的 `history-index-v1.sqlite3`，与 `state.json` 同目录，也遵循 `CONDUIT_DATA_DIR`。它是可重建的 SQLite 缓存，不修改原生日志；删除索引会使下一次导入重新解析日志。

每个文件保存路径、provider、文件大小、创建及修改时间、解析器版本、所属工作区、已处理字节位置、已处理前缀的 SHA-256 和可继续解析的状态。状态包括消息、事件去重依据和未结束回合的计时信息，因此追加后生成的消息键、模型和耗时与完整解析一致。

- 文件属性未变化：复用解析状态，不读取 JSONL 内容。
- 文件增长且上一条已提交记录以换行结束：流式校验已处理前缀，校验通过后仅解析后续记录。前缀中间被原地改写也会被检测到。
- 文件缩短、被替换、前缀校验失败、解析器版本变化或缓存状态损坏/被淘汰：重新流式解析。
- 最后一行是不完整的 JSON 或 UTF-8：保留之前的提交位置，等追加完成后重新读取该行；有效但没有结尾换行的 JSON 可以导入，下一次增长时完整重建。
- 多个扫描同时更新同一缓存时，解析状态必须与发现阶段的元数据匹配，避免把不同版本的状态和位置混用。

增量解析仍需在文件增长时读取旧前缀进行校验。`bytes_read` 统计解析及工作区探测读取量，`verified_bytes` 单独统计前缀校验量，`cache_hits` 统计直接复用次数；这些是内部批次统计，不表示进程内存占用。

### 工作区与后台调度

发现日志时先利用有效索引排除不属于目标工作区的未变化文件。已知属于目标工作区的文件优先，随后按修改时间从新到旧处理。未索引的 Codex 日志尝试从前 64 KiB 的 `session_meta` 识别工作区；识别不到时继续完整解析。Claude 日志可能在后续记录里出现其他工作区，因此不会仅凭文件开头排除。

每批最多完成 16 个文件，或在累计读取/校验约 16 MiB、运行约 100 ms 后交还后台调度。大文件的解析在记录之间暂停，前缀校验在 64 KiB 块之间暂停，下一批保留当前位置和解析状态继续。单条记录处理、缓存序列化及会话组装可能超出上述时间目标，它们不是硬性实时上限。

扫描成功完成一个稳定文件后才写入索引和交付该会话。扫描期间文件变化会丢弃尚未提交的结果，并重新排队，最多重试两次；持续变化时保留已有对话并提示下次导入重试。取消或退出不会提交部分文件，下一次导入从上次稳定索引恢复；首次扫描尚未完成的文件会重新解析。

界面逐批合并已完成会话，并显示扫描进度；进度是本轮候选文件的处理数量，所有工作区共享一次扫描的进度。首批返回后，启动加载阶段可以结束，剩余批次继续运行。整个扫描保留初始会话版本，用户在期间开始或完成回合、创建新会话时，迟到的历史不会覆盖其消息。读取异常保留已有会话并显示原因。

### 资源限制

| 资源 | 限制与行为 |
| --- | --- |
| 单条 JSONL 记录 | 8 MiB；超过时停止该文件并保留原有缓存与对话，显示明确错误 |
| 单文件/本轮历史总读取量 | 无累计拒绝阈值；流式、分批、可取消 |
| 单项缓存的序列化状态 | 32 MiB；过大时保留元数据，下次流式重建该会话 |
| 缓存状态有效载荷合计 | 256 MiB；淘汰最早写入的状态，保留工作区等元数据，后续仍可重建 |
| SQLite 页缓存 | 8 MiB，禁用 mmap |

缓存载荷预算不包含 SQLite 元数据、空闲页及 WAL，因此不是数据库文件大小的硬上限。索引打开失败时，导入退回直接流式读取，并报告索引不可用；缓存写入失败也不会阻止本次会话导入。

这些限制也不是整个应用的内存上限：当前解析器仍持有一个文件的消息状态，导入时仍需组装单个会话；持久化后正文交由按需加载机制管理。单个超长会话的加载峰值仍需测量，增加缓存预算不能替代读取粒度优化。
