# 插件后续方案

本页描述可执行插件的尚未实现设计约束。已提供的声明式[文件图标插件](icon-themes.zh-CN.md)不执行代码，使用独立的本地安装流程。先完成[Shell 准入](validation.md)并选择生产后端，再推进用户安装管理；不要把下面的协议或预算当作当前可用 API。

## 独立进程备选

当 Shell 的 UI 线程响应、资源隔离或公开 API 不能满足要求时，可以评估本地独立进程。它复用[贡献身份](contributions.md)和宿主命令语义，不要求首版同时实现两种运行时。

- 宿主以绝对路径启动受信任的包快照，每插件一个 Windows Job；stdio 使用有界、可取消、有版本的请求/响应协议。
- 数据消息携带运行 generation、实例 ID、contextVersion 和 revision；隐藏、注销或过期结果不得重建实例。
- UI 只能使用经过验证的原生模板，不接收任意 GPUI 句柄或可执行脚本作为模板数据。
- 环境显式白名单，临时目录与包路径由宿主管理；不自动继承模型凭据、代理认证或应用数据目录。普通进程仍不是完整 OS 沙箱。
- UI 不等待管道或进程退出；控制与普通数据分别有容量预留、数量/字节限额和公平预算，无法保存必要控制响应时停止故障实例。
- 停止先拒绝新工作、撤销订阅并限时礼貌关闭，再清理 Job；确认退出之前保留停止失败状态和交接屏障。

原方案的候选预算包括最多 8 个进程、每插件 32 个在途请求、1 MiB 单消息和每方向 128 条/4 MiB 普通队列；这些只是待验证起点。选择该路线后再冻结完整协议、错误码、模板和 SDK，不把未实现规范当作兼容承诺。

## 安装与信任

无论采用哪种后端，安装管理应共享一套宿主状态与事务：

1. 从用户明确选择的本地包建立快照，验证路径、类型、大小、摘要和静态清单，预览贡献及权限；检查不执行代码。
2. 信任绑定包摘要及授权集合，升级内容或权限变化需要重新确认。不能仅凭插件 ID 复用旧授权。
3. 安装状态区分期望启用、实际运行、故障和保留数据；只有事务确认后才注册或切换活动版本。
4. 升级先停止旧实例并等待数据写入，保存旧包和数据代次；候选失败恢复一致的旧版本，回退不能混用新旧数据。
5. 卸载先撤销入口和运行资格，再清理包；保留数据时留下不可加载的记录，重新安装仍需当前包授权。清理失败显示待重试，不恢复已撤销入口。

初版不规划在线市场、依赖自动安装、后台静默启用其他插件或 arbitrary native library 注入。删除路径必须解析到宿主管理根目录内，并拒绝重解析点和插件提供的任意目标。

## 持久化与布局

拟议存储按插件、global/workspace scope 和数据代次命名空间组织，只接收 key/value，路径由宿主管理。`storage/get`、`set`、`delete` 分别受 read/write 权限控制，写入使用 namespace revision 比较交换，并在真正持久化后回复。

已经受理的写入绑定当时的工作区和代次；之后切换上下文可以丢弃 UI 结果，但不能把写入改投新工作区。冲突需重读并由业务决定合并，不能自动覆盖。

布局偏好只保存顺序、隐藏、选择、宽度及有限轻量视图状态，兼容旧状态并验证 scope；不恢复命令、授权弹窗或运行实例，不因状态项每次更新而写盘。Shell localStorage 不另建一套权威数据源。

候选管理预算为最多 64 条插件记录、单包 128 MiB/2048 个文件、单 value 64 KiB、每 namespace 128 个键、每数据代次 10 MiB、每插件写队列 32 项，最多保留当前与上一代次。实施前须用真实包、磁盘和性能样本验证；日志和原始输出同样有界并脱敏。

## 交付门槛

安装、运行、故障恢复、升级、回退、卸载、磁盘不足、崩溃中断与清理失败都需独立回归。关闭窗口及更新安装必须等待插件停止和已受理写入确认，不等待长期 Active 插件自行 idle。

正式开放第三方安装前，更新[插件首页](README.md)的后端决策、状态与安全边界，完成 G1–G6 和实际 Windows 验收，发布可复验报告及用户恢复方法。
