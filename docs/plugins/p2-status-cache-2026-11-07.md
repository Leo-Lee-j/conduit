# P2-A G5 工具栏状态区缓存与完整帧对照（2026-11-07）

本轮独立缓存工具栏状态贡献区域。预热后的每个中文/emoji 输入字符仍读取一次原生状态值，但不再重建状态区元素。原始历史 stress 样本中，注册场景进入编辑参考预算，活动和混合场景仍超预算；完整帧对照存在明显长尾回退，G5 生产准入保持 `not_evaluated`，不进入 P2 冻结或 P3。

复核补记：后续检查发现本轮 A/B 执行顺序未充分平衡，长尾段将样本中位数误称为 p50。下文已校正口径，原始证据保持不变；新一轮 56 个顺序平衡进程仍有明显波动，不能确认性能稳定改善。完整发现、边界回归与限制见[复核报告](p2-status-cache-review-2026-11-07.md)。下文其余结果与构建信息仍指原始测量快照。

## 改动与失效条件

`StatusRow` 通过窗口 keyed state 保留，并使用独立的 GPUI 元素缓存；运行提示、性能监视器、终端与通知按钮仍按原路径更新。每次宿主渲染继续执行 `status_entries()`，比较文字、实际提示、元素标识、宽度和命令可用性，避免把任意原生 provider 的动态值错误地当成注册版本的常量。

缓存同时记录注册版本、完整上下文及其版本、可用宽度和外观，并逐一验证真实 `Registration` 句柄。整个注册表被替换但数字版本相同时也会刷新捕获的命令。声明在有效注册版本内不变；状态命令的参数固定为 Null，作用域来自已比较的上下文，点击时仍走现有命令校验。状态行自身使用 full width，缓存外层保留 flex 分配、最小宽度和固定高度，宽度测量后的下一帧通知逻辑继续有效。

新增两项回归覆盖草稿输入复用、动态文字和仅提示变化、主题、相同版本注册表替换、工作区切换和撤销。既有状态区回归继续覆盖窄窗/停靠布局、溢出菜单末项点击、只读和未绑定命令。新增的五个状态区计数仅编入桌面 UI 测试；历史探针和四项 Markdown schema 未改动。

## 测量口径

隔离工作树沿用 5,760 条消息、9,504,000 文本字节、16 个开发包、最多 3 个活动实例、1600×800 窗口和 14 个 Unicode 标量的中文/emoji 输入。正式进程各有 10 轮预热和 60 个样本，轮间节奏 16 ms；每条件 3 个独立进程，场景顺序轮换。复核确认，前后顺序受轮换位置影响：历史 stress 每个场景三轮均保持同一 A/B 顺序，完整帧 active 也连续三轮 before→after，计数校准 active 则连续三轮 on→off，因此不能将此设计视为已平衡顺序偏差。未启用 allocation-probe，编译、检查及各测量互斥，采样期间源码摘要稳定。

- 历史 stress A/B：4 场景 × 前后 × 3，共 24 个进程，计数关闭。保留其原有帧驱动，便于与前轮比较。
- 完整帧 A/B：3 场景 × 前后 × 3，共 18 个进程，计数关闭，使用 `simulate_next_frame` 与 `draw().clear(cx)`。
- 候选分项与计数开关校准：3 场景 × 开关 × 3，共 18 个进程。开启计数的 7,560 个正式单字符阶段均为一次根渲染、一次状态读取、零状态区构建、零 dock 标签栏构建、零聊天行/Markdown 重建。
- 另有前后各 3 个 pilot 进程，每进程 5 轮预热、20 个样本，仅用于定位，排除在 60 个正式进程之外。

所有进程校验输入、焦点、末条回复可见和实例状态；完整帧探针另在计时外强制绘制 Markdown，证明计数链路有效。表格均先取各进程 p95，再取三个进程的中位数，单位 ms；配对差值先逐对相减，再取中位数。嵌套分项 p95 不能相加。

## 历史 stress A/B

| 场景 | 编辑 before → after | 编辑配对差值 | notify+draw before → after | 通知配对差值 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 36.2719 → 36.6715 | +0.2481 | 6.4600 → 6.2768 | -0.2961 |
| registered | 43.1058 → 38.9353 | -4.1705 | 7.4342 → 6.7135 | -0.8894 |
| active | 45.7514 → 41.4604 | -4.2910 | 7.6107 → 6.7727 | -0.7698 |
| mixed | 44.8094 → 40.8574 | -3.9520 | 8.1044 → 7.2397 | -0.3320 |

注册和活动场景的编辑各有 2/3 对改善，混合场景 3/3 对改善。第二轮 registered 编辑配对回退 +10.7263 ms，active 回退 +3.0239 ms；baseline 编辑配对中位差 +0.2481 ms。这些样本全部保留，没有用重跑替换；不能宣称所有场景或每个进程都加速。插件场景 notify 的九对差值均下降，但这不代表完整帧路径也有相同结论。

参考预算仍为 `max(2 ms, baseline p95 × 10%)`。候选编辑预算 3.66715 ms，registered / active / mixed 相对 baseline 的增量为 2.2638 / 4.7889 / 4.1859 ms，只有 registered 通过。notify 预算 2 ms，三者增量为 0.4367 / 0.4959 / 0.9629 ms，均通过。

## 完整帧 A/B 与长尾

历史驱动已知存在下一帧回调投递差异，因此单列完整帧复核。这里的输入周期是同一轮 Ctrl+A、14 次单字符输入及 input-draw 的阶段耗时之和，不含 rows-sync、JSON 写入及阶段间隙；其计时口径与历史 stress 不同，不混算预算或合并样本。

| 场景 | 输入周期 before → after | 输入配对差值 | notify+draw before → after | 通知配对差值 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 38.1189 → 38.0480 | -0.3483 | 5.3491 → 4.9782 | -0.3709 |
| registered | 45.1514 → 40.4539 | -4.5848 | 5.6950 → 5.0828 | -0.4464 |
| active | 45.8425 → 43.3007 | -1.6883 | 6.0210 → 6.0896 | +0.0686 |

完整帧 registered 输入的三对差值为 -4.6975、+1.5794、-4.5848 ms；active 为 +15.1434、-1.6883、-4.5037 ms。active 的通知差值为 +1.4213、+0.0686、-0.1404 ms，其中两对回退。因此本轮只确认状态区重复工作减少，以及配对中位数改善，尚未建立稳定长尾改善的结论。

首轮 active-after 的输入样本中位数为 42.4031 ms，before 为 43.2217 ms（偶数样本取中间两项平均；按探针使用的 nearest-rank 定义，p50 分别为 42.3839 和 43.1029 ms）；但 after 的 p95 达 60.9859 ms，最长 67.9787 ms，较慢样本集中在后段。原始阶段记录及 `tail-analysis.json` 保留了分解，原因尚未归因，不直接归咎于缓存、系统噪声或某个宿主子模块。
