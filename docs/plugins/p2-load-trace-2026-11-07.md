# P2-A G5 连续 CPU 环境记录（2026-11-07）

本轮新增可复用的 Windows 探针 CPU 采样模块，补齐上一轮仅有三次手工负载快照的缺口。40 个进程完成并通过独立复算；32 个开启采样的进程平均系统 CPU 占用为 71.69%–85.95%。采样开关校准仍有明显波动，不能确认采样开销可忽略或缓存性能稳定改善。G5 生产准入保持 `not_evaluated`。

## 工具与口径

`tools/shell-prototype/windows_cpu_trace.py` 通过 Win32 `GetSystemTimes`、`GetProcessTimes` 记录系统、探针及 Python 观察进程的累计 CPU 时间，用 `perf_counter_ns` 记录快照时刻和读取跨度。默认采样间隔 100 ms，按实际间隔计算，不假设调度准时。

系统 kernel 时间包含 idle，计算 busy 时扣除 idle；进程 CPU 时间跨线程累加，同时输出逻辑核等效占用和整机容量百分比。聚合按累计时间加权，不平均不同长度区间的百分比。短尾间隔未更新的系统计数保留为未知并计算覆盖率，不当作空闲。多处理器组平台直接拒绝，避免混用统计范围。

原始快照、实际间隔、读取跨度和间隔超过请求值两倍的次数均保留。各计数并非原子读取。范围包含启动、夹具准备、预热、正式动作及退出，不能对应单个 UI 阶段，更不能代替 GPU 时间。观察进程记账 CPU 较少或为零，不证明采样对调度、缓存、系统调用没有影响。

模块供 runner 导入 `run`，传入命令参数列表、工作目录、环境及新的日志/trace 路径。`interval_s=None` 关闭采样以供校准。日志排他创建，拒绝覆盖旧证据；超时、启动失败、非零退出和采样错误均留存并标为无效。只清理本次直接子进程，需要后代进程清理的测试应继续使用 `verify.run`。本轮没有超时，没有终止其他应用或调整电源、优先级。完整使用示例为证据目录中的 `matrix.py`，复跑必须使用新目录。

## 固定计划与环境

运行前保存执行计划，检查未发现 Rust 编译进程。当前系统记录了 12 个逻辑核和既有高性能电源方案。使用前轮保留的两份二进制，SHA-256 与原构建清单一致；没有重新构建。

- 校准：同一 after 二进制，baseline / active × off / on × 4 轮，共 16 进程。
- 完整帧 A/B：baseline / registered / active × before / after × 4 轮，共 24 进程，两边均采样。
- 每场景恰好两次 AB、两次 BA，场景顺序轮换；每进程 10 次预热、60 正式样本，宿主分项计数关闭。
- 编译、源码修改与测量互斥。没有按负载等待、排除样本或自动重跑。off 模式不采集 CPU，不能事后证明校准两边负载相同。

工作负载沿用 5,760 条消息、9,504,000 文本字节、16 个开发包、最多 3 个活动实例、1600×800 窗口和 14 个 Unicode 标量输入。仍为 `gpui-test-no-gpu`；输入周期是 Ctrl+A、14 次输入及 input-draw 阶段之和，不含 rows-sync、JSON 写入或阶段间隙。

## 连续 CPU 结果

32 个进程共保留 3,170 次快照。

| 指标 | 各进程最小值 | 各进程中位值 | 各进程最大值 |
| --- | ---: | ---: | ---: |
| 平均整机 CPU 容量占用 | 71.69% | 77.29% | 85.95% |
| 平均探针逻辑核等效占用 | 0.6732 | 0.7376 | 0.7801 |
| 平均探针整机容量占用 | 5.61% | 6.15% | 6.50% |
| 观察进程累计 CPU 时间 | 0 ms | 15.625 ms | 62.5 ms |
| 单进程最大采样间隔 | 109.79 ms | 113.77 ms | 133.44 ms |

按有效区间实际时长加权，各进程有 97.00%–100% 的时间处于整机占用超过 50% 的区间。系统计数时间覆盖率最低 99.97%，没有间隔超过请求值两倍，单次读取跨度最大 8.96 ms。

从系统与探针占用量级推断，大部分 CPU 使用在探针之外；这不证明每个慢样本都是调度等待，也没有定位到某个外部应用。数据缺少逐阶段 CPU、上下文切换和 GPU 呈现时间，不能据此确认单帧长尾根因。
