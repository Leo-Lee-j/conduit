# 插件验证与准入

当前结论：原生贡献和 Shell 开发接入已有自动化回归，Shell 生产准入尚未完成；P2 后端决策与 P3 安装管理不能据此宣布完成。本文保留准入定义和可复验方法，不汇总不同源码快照的通过数。

## G1–G6

| 门槛 | 已有基础 | 继续验证的边界 |
| --- | --- | --- |
| G1 构建与公开 API | 固定上游、可审阅补丁、默认构建和 Fast 类型检查入口 | Fast 成品链接、运行与真实桌面；不能调用私有 API 冒充可用接入 |
| G2 授权与加载 | 显式 Policy、按 owner 授权、快照复核及双 owner 隔离测试 | 安装持久化信任及生产包事务尚未接入 |
| G3 多视图与命令 | 同 owner 多实例、定向命令、票据和代次失效 | 新宿主能力继续核对 scope、焦点无关路由和停止后的旧回调 |
| G4 根节点与输入 | 正确根结构、主题/弹窗、组合输入接口、窄窗与焦点回归 | 真实 Windows IME、候选窗、原生浮层及多屏/DPI |
| G5 资源与响应 | VM/原生描述限额、独立故障探针、CPU/完整帧/内存测量工具 | 编辑增量、长尾、watchdog 根因、真实 GPU/滚动及测量开销仍未完整通过 |
| G6 发现与关闭 | 静态清单不执行脚本、惰性激活、owner 浮层清理、关闭/更新停止 | 后续存储写入确认及安装交接仍需接入同一屏障 |

## 可重复执行入口

原型全部命令、构建准备和参数集中在[工具 README](../../tools/shell-prototype/README.md)，补丁更新见[补丁 README](../../tools/shell-prototype/patches/README.md)。不要复制旧 artifacts 中的绝对工作树路径作为开发入口。

- `verify.py`：格式/Clippy/类型检查、交互回归，以及显式 watchdog、resources、commands 和 development-fault 探针。
- `verify-desktop.py`：真实 ConduitApp 开发构建和桌面回归；另提供 performance、stress、breakdown、diagnostics、chat-profile 测量阶段。native-memory / host-profile 是独立 opt-in 测试探针，不是该 runner 的 phase。
- `smoke-windows.ps1`：启动本次原型窗口、激活与命令操作、截图及退出检查。
- Python 验证器：检查报告结构、源码身份、有效用例数、帧顺序与派生统计。

常规回归与 opt-in 性能/资源故障探针分开；空测试组、源码在测量期间改变、外部超时或未生成报告都应失败。外部 runner 超时是测试防挂死措施，不是产品运行时保护。

`fast-check` / `release-check` 仅证明对应配置检查完成；必须运行相应成品才能报告实际运行。未提供原生 GPU 的测试环境只报告 CPU/测试帧结论。

## 性能口径

基础矩阵含无插件、只注册、首次打开、可见/隐藏、多视图等状态；stress 覆盖长会话、较多静态包、3 个活动 VM、故障隔离及生命周期。3 个 VM 驻留不表示同时可见或并行执行。

每个进程分别统计预热后的 p50/p95/最大值，再汇总跨进程范围，不把所有进程样本混成一个分位数。参考增量预算为 `max(2 ms, baseline p95 × 10%)`，报告中的 `production_gate = not_evaluated` 必须保留，不能把参考比较通过当作生产准入。

完整帧需要确定动作、更新、draw 和下一帧回调的边界；聊天 Markdown 或布局分项不能相加替代完整 p95。A/B 顺序在各场景内平衡，保留首次失败和长尾，校准计数器、分配记录、测试自动绘制及 CPU 采样开销。

生命周期同时记录 ready / after_stop / settled、VM/实例数量、弱引用和进程内存。settled 只表示按探针约定执行等待/绘制，不意味着强制 GC 或 OS 已回收页面。idle 是背景对照，不能直接相减得到插件专属内存。

## 尚未解决的证据缺口

- 历史普通路径 watchdog 超时在后续部分重跑中未复现，根因仍未归属；预设死循环测试不能代替该故障解释。
- 聊天、插件视图、标签栏和状态区缓存减少了部分重复工作，但完整编辑增量和长尾尚未形成稳定达标结论。
- 状态区复核纠正了 A/B 顺序和中位数口径；负载不稳定，不能只挑下降样本，也不能把全部回退归因于系统噪声。
- 连续 CPU 采样已有工具，但环境控制与采样开销可靠上界仍需证明。
- 完整帧探针纠正了下一帧回调积压带来的内存误判；VM 释放不证明 native/GPU 无泄漏，仍需更长窗口和分配归属。
- 真实 IME、滚动、GPU、Fast 成品及未来存储屏障尚未完成。历史一次剪贴板回归失败后重跑通过，也不能记为已确认根因修复。

## 证据保存与更新

每次报告保留源码/二进制身份、工具链、命令/退出码、原始 JSON/JSONL、包夹具、样本和独立摘要，输出至新的 artifacts 目录，不能覆盖旧证据。若改变驱动或统计定义，应产生新口径，不回写旧报告使其看似通过。

更新本页时只修订当前结论、门槛或方法；逐次结果留在报告和 Git 历史。与正式应用共用的测量规则见[性能与指标](../performance.md)。
