# P2-A G5：宿主分项归因与右侧标签栏缓存

日期：2026-11-07（Asia/Shanghai）。承接 [native 内存归因](p2-native-memory-2026-11-07.md)。本轮独立测量宿主构建、布局请求、prepaint 和 paint，缓存右侧 dock 的标签栏。活动插件和混合场景的完整编辑 p95 在三轮配对中均下降，通知重绘的增量预算本轮通过；**完整编辑预算仍未通过，G5 生产准入保持 `not_evaluated`**。

## 实现与边界

`DockHeader` 是独立的 GPUI 缓存实体，只包含没有动态附加动作的标签栏；带原生动态动作的标题栏继续直接渲染。脚本内容保留原有独立缓存，避免刷新标签栏时强制重建 ScriptView。缓存键包含视图注册版本、完整上下文及版本、右侧选择、分支模式、关闭按钮身份与外观；同时验证注册句柄，防止同名插件重新安装后，旧点击请求在相同数字版本下被复用。尺寸和继承文本样式沿用 GPUI 缓存失效机制。

新增三项桌面回归：中文/emoji 输入及脚本命令不重建标签栏；跨工作区、只读状态、明暗主题、窄窗/宽窗和撤销正确更新；相同声明与版本的注册表整体替换后，标签点击使用新句柄。发送、提及与队列的输入通知逻辑没有变动。未更改上游补丁或 Cargo 缓存。

宿主分项只编入 UI 测试。`desktop_host_profile_probe` 使用独立 `host-profile` v1 schema，显式执行 `simulate_next_frame` 与 `draw().clear(cx)`；历史 stress/chat-profile/breakdown 路径及四项 Markdown schema 保留原样。本轮二进制不启用 `allocation-probe`。

## 测量口径

沿用 2×24×120 数据集（5,760 条消息、9,504,000 文本字节）、16 个开发包及最多 3 个活动实例，1600×800 测试窗口，中文/emoji 14 字符编辑，16 ms 轮间节奏。每进程 10 轮预热、60 个正式样本，每条件 3 个独立进程；所有测量与编译、检查和其他测量互斥，期间源码哈希稳定。

- 主要前后对照：历史 stress 驱动，4 场景×前后×3 进程，共 24 个进程。轮换场景顺序，前后顺序交错。两端分项计数均关闭，保留原始输入、命令状态和故障隔离验证。
- 宿主分项与探针校准：3 场景×计数开/关×3 进程，共 18 个进程。15,120 个正式单字符阶段；其中 7,560 个开启宿主计数，均无标签栏构建、聊天行重建或 Markdown 阶段调用，每字符仍有一次根渲染。每进程在计时外强制绘制 Markdown 证明探针有效，并验证焦点、输入值和末条回复可见。
- 分项含子节点，request-layout 不包含后续 Taffy 根求解；不能相加各项 p95 来替代总耗时。两个驱动不能混作同一前后样本。早期 pilot 仅用于定位，排除在 42 个正式测量进程之外。

## release 前后对照

数值为三个进程各自 p95 的中位数，单位 ms；配对列先逐进程相减再取中位数。

| 场景 | 完整编辑 before → after | 编辑配对差值 | notify+draw before → after |
| --- | ---: | ---: | ---: |
| baseline | 38.7644 → 40.3301 | +1.1686 | 5.8861 → 6.3821 |
| registered | 44.3804 → 45.6781 | +0.9061 | 7.0714 → 6.8469 |
| active | 57.9384 → 46.4223 | -11.0861 | 8.8434 → 7.3098 |
| mixed | 58.2799 → 46.1857 | -12.0942 | 9.0065 → 7.2580 |

active 的编辑配对差值为 -13.7235、-11.0861、-4.5454 ms；mixed 为 -12.0942、-18.5716、-10.7826 ms。active 的 notify 配对有一次 +0.2508 ms，不能声称每次重绘都改善。

baseline 和 registered 的编辑没有改善，配对中位差分别为 +1.1686、+0.9061 ms；registered 第一对增加 6.0106 ms。原因未进一步归因，本轮不宣称全场景无回退，所有样本保留。

预算仍为 `max(2 ms, baseline p95 × 10%)`。优化后完整编辑预算 4.03301 ms；registered / active / mixed 相对 baseline 的增量为 5.3480 / 6.0922 / 5.8556 ms，均未通过。notify 预算 2 ms，对应增量 0.4648 / 0.9277 / 0.8759 ms，本轮均通过。

## 剩余开销与校准

开启计数后的单字符分项 p95（每进程先算、再取三进程中位数）：

| 分项 | baseline | registered | active |
| --- | ---: | ---: | ---: |
| 插件上下文同步 | 0.0014 | 0.0039 | 0.0076 |
| 根构建 | 0.1480 | 0.2367 | 0.2561 |
| 工具栏布局请求 | 0.0758 | 0.1898 | 0.1723 |
| 根布局请求 | 0.5196 | 0.6287 | 0.6605 |
| 根 prepaint | 0.8807 | 0.9835 | 1.0264 |
| 根 paint | 0.7778 | 0.9117 | 0.9264 |

active 中标签栏布局请求 0.0014 ms，整个 dock 布局请求 0.0219 ms；早期 pilot 中整个 dock 为 0.3185 ms，但 pilot 样本规模不同，仅作为归因线索。宿主同步没有呈现毫秒级成本，后续优先细分工具栏状态贡献、其余宿主控件及根 prepaint/paint。

同一最终二进制、同一完整帧驱动，计数开/关的单字符 p95 中位数分别是：baseline 3.1730/3.1744，registered 3.7355/3.6616，active 3.9836/3.7209 ms。逐对“开减关”的中位数是 -0.0135、+0.2046、+0.3037 ms；registered 第三对达到 +1.0158 ms。探针开销与波动不可忽略，因此上面的主要性能结论来自关闭分项计数的独立 A/B。

## 验证与未完成项

release 插件/更新回归 60 项通过（6 个 opt-in 探针由独立 runner 管理）；dev 插件、聊天滚动/缓存、侧栏和更新回归 81 项通过；Python 28 项通过。格式检查、release all-target Clippy `-D warnings` 和主工作区 all-target/ui-tests 类型检查通过。

尝试在 release 扩大运行聊天区回归时，4 项依赖调试选择器的测试失败；保留的 before 二进制复现了同样四项、同样位置的失败。该组在 dev 下完整验证，失败日志不删除，也不计作 release 通过。新标签栏回归使用原生语义/公开元素标识，在 dev 和 release 均运行。

所有结果均为 `gpui-test-no-gpu`。历史普通路径 watchdog 根因、真实 GPU/滚动、Windows IME 与 Fast 成品验收仍未完成；本轮不改变 P2 冻结或 P3 状态，也不重新作 native 内存无泄漏断言。

集成时发现普通根工程没有启用桌面专用 profiling 模块，已为 12 处调用补齐 `conduit_shell_desktop` 条件。该改动只修复普通构建，桌面测量分支不变；`measured-source/` 保留测量时源码，`post-measurement-cfg.json` 和 `post-cfg-checks.json` 记录纯条件变更及复核。测量二进制未冒充最终源码的重新构建产物。
