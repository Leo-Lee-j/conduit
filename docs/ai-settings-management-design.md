# AI 设置专项完善

日期：2026-11-06。状态：设计与首轮实施完成；后续增强和验收限制见文末。

## 目标与现状

本专项覆盖 CLI 接入扩展、引擎管理、模型管理，以及 Skills / MCP 的展示和管理。沿用原生 GPUI 设置工作区、明暗主题与现有配置保存机制。

当前 Claude Code、Codex、OpenCode 已有协议、模型扫描和扩展扫描实现。问题是引擎元数据分散在 domain、cli 和设置页；路径按引擎分别增加字段；没有统一启停策略；CLI 模型列表不能维护；扩展列表缺少状态筛选，编辑入口需要展开详情。已有的路径优先级、后台检测、CCS 同步、凭据保护、配置备份和过期写入检查继续复用。

## 信息架构与交互

| 页面 | 主体 | 常用操作 | 状态说明 |
| --- | --- | --- | --- |
| AI 引擎 | 引擎选择、启用状态、能力、路径与诊断 | 启用/停用、选择路径、自动查找、检测版本、安装说明 | 启用状态与安装/版本检测分别呈现 |
| 模型与服务 | 引擎选择、服务列表、CLI 模型目录 | 添加/编辑本地模型、隐藏/恢复、设为新会话默认、刷新 | CLI 来源、自定义、新会话默认、隐藏分别标注 |
| Skills | 引擎与范围、搜索、状态筛选、技能列表 | 新建、导入、编辑、停用/恢复、定位来源 | 全局/项目/插件、同名定义、已停用；不推断运行时优先级 |
| MCP 服务 | 引擎与范围、搜索、状态筛选、服务列表 | 添加、编辑来源、原生启停、测试连接 | 配置状态与连接测试结果分开；插件托管显示原因 |

列表采用名称、说明、来源/状态、操作的顺序；常用编辑动作直接可见，路径和高级操作放在详情。长路径与名称可查看完整文本。筛选显示匹配数与总数，扫描错误始终可见；空目录、无匹配、读取中分别提示。沿用主题语义颜色，状态同时使用文字。窄窗口允许操作换行；列表继续使用虚拟滚动。设置导航与搜索保留既有索引，避免新增分组导致搜索定位错位。

自动保存用于引擎开关、模型显示偏好和默认选择；模型编辑器使用保存/取消。原生扩展变更说明文件位置和生效时机，保存失败不更新成功状态。只读模式可浏览与诊断，不能更改设置或来源文件。

## 引擎接入与管理

增加统一 `EngineDescriptor` 注册表，集中稳定 ID、名称、环境变量、可执行文件、常见安装路径、已验证版本、版本标识、官方帮助地址和设置能力。`Provider` 的既有序列化值保留，避免破坏历史会话。UI、路径解析和版本识别从注册表读取。

CLI 配置增加按引擎存储的配置映射；旧 `claude_path/codex_path/opencode_path` 继续可读，修改对应路径时迁移。默认全部启用，旧文件加载行为不变。注册表负责元数据与能力，协议消息处理仍由现有原生适配器实现；不能把任意可执行文件当成已适配引擎。

新引擎接入步骤：增加稳定 Provider 标识与注册项 → 实现协议启动/流式事件/取消/审批 → 实现模型与扩展读取 → 添加协议夹具和兼容测试。首轮不提供动态加载任意 CLI 的虚假通用入口；后续可在协议契约稳定后拆出独立适配器接口。

停用阻止后续聊天、排队消息、自动命名与 Git 提交说明任务启动，不终止在途任务，不删除历史。聊天引擎选择显示停用状态并阻止选择；设置中仍可诊断、修复和重新启用。没有可用引擎时明确提示，不能默默切换到另一个引擎。

## 模型管理

应用侧 `ModelPreferences` 按引擎保存自定义模型与隐藏 ID，原生目录仍由 CLI 读取。目录合并使用模型 ID 去重，自定义信息覆盖同 ID 的显示标签、备注和上下文窗口。原生来源不会因刷新覆盖应用偏好。

支持添加、编辑、移除本地定义，隐藏/恢复目录项，以及设为该引擎新会话默认。模型 ID 非空、无控制字符且有长度上限；OpenCode 使用 `provider/model` 格式；上下文窗口为正整数或留空。隐藏只影响候选列表，既有会话和默认模型仍可识别，不改写历史和 CLI 配置。已有默认值保持可见，避免下拉中找不到当前项。应用默认与 CLI 原生默认分别标注。

原生 CLI 通道使用上述偏好；CCS 和自定义服务继续按服务边界管理，不能把同名模型跨服务合并。自定义服务已有编辑入口，CCS 服务由 cc-switch 管理。后续增强可增加收藏、排序和服务内元数据编辑。

## Skills / MCP 管理

首轮增加全部、未禁用、已停用、插件托管、同名定义筛选，搜索覆盖名称、描述、来源路径与传输类型。“未禁用”不代表 CLI 已加载或认证通过。同名项全部保留并显示来源，不自动判断优先级。筛选采用搜索栏旁的下拉菜单，保留小窗口列表高度。

本地 Skill 使用可逆文件停用：`SKILL.md` 改名为 `SKILL.md.conduit-disabled`，恢复时反向操作，保留同目录脚本和资源。扫描识别两种文件。操作前校验普通文件、原内容和目标不存在；插件托管条目不可直接停用。共享目录中的 Skill 会影响所有读取该目录的 CLI，操作界面需说明这一点。冲突时拒绝覆盖。

Codex 与 OpenCode 的 MCP 使用原生 `enabled` 字段，保留 TOML / JSONC 注释和其他配置，通过已有编辑预览、备份和过期写入检查保存。Claude 的禁用存在项目本机覆盖与插件来源差异，首轮保留来源文件编辑和连接测试，明确显示该能力边界，不写入猜测的通用字段。插件来源只提供查看与定位。后续原生适配可补上 Claude 精确作用域启停、逐条删除与引用检查。

连接测试继续异步执行并可取消；切换引擎或范围丢弃旧结果。列表不展示参数、环境变量值或认证头。

## 实施顺序与验收

1. 注册表、配置兼容与启动门禁；验证旧配置、优先级、停用后的入口。
2. 模型偏好、管理表单与候选列表集成；验证去重、隐藏、默认值、重启持久化和只读。
3. 扩展筛选、来源与操作布局、可逆 Skill 停用、支持引擎的 MCP 启停；验证冲突、过期写入、注释保留和插件托管边界。
4. 定向单元测试和 GPUI 交互测试（850×500、1280×900、明暗主题），运行构建、格式检查、Clippy 和仓库回归；记录真实限制。
