# 多工作区与多会话并发

更新：2026-10-27

## 根因

底层已经具备并发基础：`runs: HashMap<u64, ActiveRun>` 按会话保存运行状态；每轮 `ChatRuntime` 有独立线程、事件/控制通道、取消标记和 Windows Job。此前 `send_text` 与发送按钮都通过 `workspace_busy` 判断可运行性，同目录任意会话运行都会禁止发送。该判断还把任意 `git_operation` 当作所有工作区繁忙，导致跨仓库聊天被连带阻塞。

## 本次调整

- 会话是调度单位：不同会话直接并行，工作区只承载目录与历史；同会话每次只能运行一轮。
- 原生上下文防重：同一 Provider 的相同 native ID 只能有一个活动轮次，避免重复本地记录同时 resume。
- 发送统一判定：键盘发送和按钮使用同一入口；切换引擎时按新会话判定，重试/重新生成仍按原会话判定。
- 生命周期隔离：消息索引、审批队列及审批详情状态保留在 ActiveRun，取消只操作对应 Job，进程树退出后才释放该会话。
- 历史导入隔离：异步扫描结果不覆盖仍在运行的会话。
- Git 写操作与聊天按仓库协调：通过 `.git` 与 `commondir` 识别共享引用的 linked worktree，分支操作、提交/推送会等待该仓库所有 CLI 任务结束；Git 写操作运行时同仓库禁止发起新任务。聊天任务之间仍按会话独立并发。Git 写操作自身沿用单操作调度。
- 数据兼容：不修改已有持久化格式，无需迁移历史。所有事件仍在 UI 线程合并并统一持久化。

## 验证

新增 UI 回归同时保留三个活动轮次：工作区 A 的 Claude/Codex 两会话，以及工作区 B 的 Claude 会话。覆盖重复发送不替换运行时、原生上下文防重、切换引擎/重新生成目标、同名审批 ticket 隔离、历史快照保护、取消后邻会话继续输出、完成只释放自身以及工作区移除保护。

新增 worktree 边界测试覆盖仓库子目录、`.git` 文件形式的 linked worktree 和无仓库目录。已有真实进程夹具覆盖同目录双运行时取消隔离与进程树退出屏障。上述回归不调用模型。真实 CLI 的多会话持续运行与资源压力仍需验收。

本轮结果：默认测试 99 通过、11 项集成测试忽略；三会话 UI 回归通过。完整 UI 测试集 107 通过、1 项既有文字拖选测试失败、11 项忽略（`drag_across_assistant_reply_tracks_the_pointer` 未找到可选中的用户文本行）。`cargo fmt --check` 与 `git diff --check` 通过。严格 Clippy 被既有 `render_collapsed_tool_group` 的 `too_many_arguments` 阻断；仅豁免该 lint 后检查通过。

默认 `target/debug/conduit.exe` 被运行中的应用占用，未强制关闭；通过 `cargo rustc --locked --bin conduit -- -o target/debug/conduit-concurrency.exe` 成功产出独立验证程序。隐藏窗口启动探测未在 15 秒内取得窗口句柄，不能据此宣称窗口冒烟通过；新版本实际界面仍待打开验收。

## 后续优化边界

并发启动不等于文件隔离：同目录任务修改同一文件时依然可能冲突。需要隔离的任务可使用不同 Git worktree，本次不自动复制目录或改写分支。

当前事件轮询每 33 ms 为每轮读取最多 1000 条事件，状态保存会序列化整个会话库。会话数明显增加后，应依据性能面板先测量 UI 帧耗时和保存耗时，再考虑每帧总事件预算、轮转公平性、增量保存或后台保存快照。若账户或机器资源需要限流，应增加独立的全局并发配置与显式排队状态，避免再次用工作区锁代替调度。
