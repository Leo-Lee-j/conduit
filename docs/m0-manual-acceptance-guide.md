# Chat M0 人工验收交接单

本单用于把 [验证记录](m0-validation.md#手工-ui-验收清单) 的 12 项人工验收一次性做完。自动预验已完成能自动观察的部分（见 [UI 自动预验记录](m0-ui-acceptance-run.md)），**本单只列仍需人眼、真实按键与输入法完成的项目**。不要用自动预验代替签署。

## 0. 准备

```powershell
cd D:\m\conduit
cargo build --locked
pwsh -NoProfile -File scripts/ui-acceptance.ps1 -Action seed   # 生成隔离数据 target/ui-acceptance/data
# Windows PowerShell 5.1 用：
# powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\ui-acceptance.ps1 -Action seed
```

脚本以 UTF-8 BOM 保存；自行编辑时请保留 BOM，否则 Windows PowerShell 5.1 会按 ANSI 解析中文并报“字符串缺少终止符”。

- 全程使用隔离 `CONDUIT_DATA_DIR`，不写 `%LOCALAPPDATA%\Conduit`。
- 记录：构建时间、Windows 缩放比例、每项实际结果；截图可存 `target/ui-acceptance/out/`。
- 涉及真实 CLI 的项只用临时工作区与合成提示，会消耗少量账户额度。

## 1. 输入与编辑（需人：约 10 分钟）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 1 | 聚焦输入框输入两行：第一行后按 Enter，再按 Ctrl+Enter / Shift+Enter | Enter 发送（输入框清空并保持焦点）；Ctrl+Enter 与 Shift+Enter 只换行、不发送 |
| 2 | 用微软拼音逐字输入、选候选、组合中退格后再发送 | 组合文本与候选窗正确；组合期间按 Enter 不误触发送（需先确认候选/组合）；发送后无乱码或重复 |
| 3 | 用 Win+. 输入 emoji；发送含标题、列表、行内代码、围栏代码块的回复；选择回复 Ctrl+C；点代码块复制 | Emoji 正常；选区与剪贴板一致；代码块复制内容精确、不含围栏 |
| 6 | 依次切换会话、发送消息、允许/拒绝审批、取消任务后直接打字 | 每次按键都进入输入框，无需再次点击 |

建议启动：`pwsh -NoProfile -File scripts/ui-acceptance.ps1 -Action capture -Name manual-chat -DataDir target/ui-acceptance/data-claude -KeepRunning`（复用种子数据），或直接 `cargo run -- --settings`。

## 2. 阅读与布局（需人：约 10 分钟）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 4 | 发送长回复，停留底部，再上滚阅读；结束后回到底部 | 底部时跟随新内容；上滚后不被拉回；回到底部继续跟随 |
| 7 | 窗口缩至 850×500；在 100%、125%、150%、200% 缩放下检查会话列表、输入框、审批覆盖层、设置页 | 无控件裁切、重叠或不可点击；文字与审批详情可读；滚动可用。设置弹窗窄窗裁切已在本轮修复，仍需人眼确认 |
| 8 | 两个工作区各启动会话并行；A 中上滚阅读，等 B 完成；再取消 A | B 完成不改变 A 的滚动位置；取消 A 不影响 B；侧栏状态与各自任务一致 |

850×500 可直接用脚本开窗：`pwsh -NoProfile -File scripts/ui-acceptance.ps1 -Action capture -Name manual-narrow -DataDir target/ui-acceptance/data -Width 850 -Height 500 -KeepRunning`。DPI 缩放需在系统显示设置中切换后重新启动应用。

## 3. 审批、关闭与设置（需人：约 20 分钟）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| 5 | 在临时工作区发起需要审批的无害操作，分别点击允许本次、拒绝；再触发长详情与多请求队列 | 按钮只提交一次；状态依次为“正在提交审批…/正在执行…”；拒绝后目标无变化；详情可滚动；队列序号正确；只可拒绝时显示提示。生产参数不产生审批时记录“不可复现”，不伪造通过 |
| 9 | 有运行中任务和待审批请求时关闭窗口；另测无任务正常关窗 | 应用退出；任务管理器无遗留 conduit / claude / codex 子进程；重启可加载数据，未完成运行标记为中断 |
| 9b | 运行中任务关闭后重开（同一隔离数据目录） | 历史加载、interrupted 提示出现且不重复落盘；不重放任务 |
| 10 | 打开设置页，选择或清除 CLI 路径，执行检测并中途取消一次 | 点击命中正确控件；取消后检测进程退出；来源与检测结果一致 |
| 12 | 打开“模型同步”，核对 Claude / Codex 的 CLI 当前模型与 CCS Provider 分组；在会话中打开模型选择器切换模型并发送一条合成消息；新建同引擎会话观察默认模型；刷新后再看列表 | 菜单可进入且滚动正常；只展示配置来源与模型清单，无密钥；CCS 当前 Provider 模型出现在选择器，其他 Provider 不出现；标签随选择更新；新会话继承 Provider 当前默认；选择只影响当前会话且下一条消息生效 |

审批项提示：Conduit 的 Codex 生产参数为 `approvalPolicy=on-request` + `sandbox=workspace-write`，在临时工作区内执行普通命令可能**不会**弹出审批。要复现审批，请在临时工作区请求一次越出沙箱的操作（如写入工作区外路径或访问网络），确认是 CLI 真实发出的请求再点击。没有请求时不得伪造。

## 3b. 历史整理（需人：约 5 分钟，使用隔离数据中的合成会话）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| H1 | 点击侧栏顶部搜索图标，在弹窗输入某会话标题片段，再输入只出现在消息正文中的片段 | 弹窗列出命中会话并在标题/摘要中高亮命中词；点击结果切换到该会话 |
| H2 | 会话行“⋯” → 重命名，修改后保存 | 标题更新并持久化（重启后仍在）；空标题被拒绝并提示 |
| H3 | 会话行“⋯” → 归档；点工作区右侧“已归档” | 默认隐藏；切换后可见并带“已归档”标记；重启后归档状态保持 |
| H4 | 会话行“⋯” → 删除 → 确认（只删除合成会话） | 会话与消息记录移除；当前选中切换到其他会话；重启后不再出现 |
| H5 | 点输入区左下角引擎下拉切到 Codex，再点侧栏顶部“＋”或用工作区行“＋”新建会话 | 下拉向上弹出；切换后右上角模型选择器切到 Codex 模型；新建会话为 Codex 引擎 |
| H6 | 工作区行“⋯” → 移除工作区 → 确认 | 菜单从行右侧弹出；工作区从侧栏消失；磁盘目录未被删除；重启后不再出现 |
| H7 | 设置 → 通用 → 界面：把“工作区会话数”调小到 2，回到侧栏 | 每个工作区只显示最近 2 条会话，超出显示“显示更多（还有 X 条）”；点开可展开、再点“收起”；重启后条数保持 |

## 3c. 第七轮界面细节（需人：约 5 分钟，使用隔离数据中的合成会话）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| H8 | 依次把鼠标移到侧栏“＋ / 搜索 / 工作区行＋ / ⋯ / 会话行⋯”、引擎与模型下拉、设置与审批按钮上（不点击） | 光标变为 pointer（手型）；禁用按钮保持普通光标 |
| H9 | 打开长会话，停在底部后向上滚动；再点击右下角的 Pin 图标 | 底部时 Pin 不显示；上滚后 Pin 自动出现在对话区右下角（输入区右上角上方）；点击后回到底部且 Pin 消失；切回底部后保持隐藏 |
| H10 | 分别打开工作区行“⋯”和会话行“⋯” | 两个菜单都从行右侧弹出，左缘在同一列；会话菜单在窄窗或列表底部不被窗口裁切 |
| H11 | 打开设置，检查左栏与“通用”“CLI”页 | 通用页只有本机数据与界面设置；CLI 相关的路径查找顺序、可执行文件与版本说明在“CLI”页，不与通用混排 |

## 3d. 只读 Git 变更面板（需人：约 10 分钟，准备一个真实 Git 工作区）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| H12 | 在含未提交修改的 Git 工作区选中会话，点底栏右侧 Git 图标 | 右侧打开“Git 变更”页：分支名、暂存/未暂存/未跟踪数量，文件按新增/修改/删除分成三个可折叠块；文件名颜色分别为蓝/绿/浅红，不显示 diff 内容；点“刷新”后分组与 `git status` 一致 |
| H13 | 面板打开时切换工作区；再对非 Git 目录打开“变更” | 切换后不显示上一个目录的快照；非 Git 目录显示“该工作区不是 Git 仓库”和“重新读取”，不是原始 `fatal:` 文本 |
| H14 | 在面板打开前后执行 `git status`，检查 `.git/index` 与 `index.lock`；用大量变更文件观察滚动 | 面板读取不改变仓库状态、不残留 `index.lock`；长文件列表可滚动且界面不明显卡顿；未跟踪文件只显示路径不显示内容 |
| H15 | 发一条会修改文件的 CLI 任务，任务结束后看已打开的 Git 面板 | 面板自动重读并显示新变更；关闭面板后不再发起 Git 读取 |

## 3e. 第九轮输入区与侧边栏（需人：约 10 分钟）

| # | 操作 | 通过标准 |
| --- | --- | --- |
| H16 | 使用全新/空数据目录打开应用，检查聊天左上角与输入区 | 左上角工作区选择器可打开，能选择已有工作区（如有）或添加目录；输入区与正常会话同宽高，无工作区时有明确禁用态 |
